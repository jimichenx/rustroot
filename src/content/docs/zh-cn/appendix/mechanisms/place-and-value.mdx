## 这个概念解决什么问题

你已经见过下面几种写法：

- `point.x = 10`；
- `values[0] = 10`；
- `*reference = 10`；
- `let value = expression`。

这些写法会先撞上一个直觉：表达式应该是“算出一个值”的东西，而 `point.x = 10` 这样的赋值看起来只是“做了一件事”，更像语句，怎么会是表达式？

因为在 Rust 里，“表达式”的范围比这个直觉宽。`if` 是表达式，花括号块是表达式，赋值也是表达式——它算出的值是 `()`。反过来，上面列表里的 `let` 是语句，不是表达式；`expression` 那个位置上的才是表达式。“是不是表达式”本身没有区分度；有区分度的是求值的结果：求值时，有的表达式指向一个可以被读取、修改或借用的位置，有的表达式算出一个值。

Rust 把前一类叫作**位置表达式（Place Expression）**，把后一类叫作**值表达式（Value Expression）**。这个区分能解释赋值、可变借用、解引用和字段移动为什么有不同的要求，也能解释为什么有的位置读得走值，有的读不走。

“表达式产生值”的直觉并没有全错。当一个位置表达式出现在需要值的地方，读取发生，它也就算出了一个值——直觉里的表达式，见到的都是这一层。

## 位置表达式：指明一个位置

位置表达式是写明“程序里哪个位置”的表达式。变量名最直接；其余的写法都是从别的位置“走到”目标位置。位置不是地址——它存不进变量、传不了参、比不了大小，你能做的是读取它、往它写入、从它借出引用。

Rust 里能成为位置的形式一共五种：变量名、字段、索引、解引用、静态变量。下面一个一个看，最后回到它们的共同点。

### 索引：运行时计算的一步

### 解引用：沿引用走到指向的位置

`*reference` 沿一个引用走到它指向的位置。上面字段那节的示例里，`*y = 20` 就是这个形式：`y` 是 `&mut i32`，`*y` 回到了 `point.y` 那个位置，所以写回的是 `point.y` 的值。

智能指针是否支持这种写法，取决于它是否提供了合适的 `DerefMut` 实现——和索引走的是同一条路：方法返回引用，解引用得到位置。

### 静态变量：全局的位置

静态变量像变量名一样，直接指一个位置，只是这个位置全局可见，程序运行期间一直存在。它能读、能借，但移不出值——原因在「得到位置，不等于能拿走值」一节展开。

五种形式的共同点是两层约束：

1. 表达式必须能指向一个位置；
2. 这个位置必须允许当前操作——赋值需要可变位置，可变借用还要满足读写排他。

## 值表达式：只产生一个值

值表达式负责计算结果，不代表一个可以继续写入的存储位置。常见例子包括：

- 字面量，如 `42`；
- 算术运算，如 `x + y`；
- 函数调用，如 `String::from("hello")`；
- 方法调用，如 `values.len()`；
- 结构体构造，如 `Point { x: 1, y: 2 }`。

例如，`String::from("hello")` 产生一个新的 `String` 值。`let text = ...` 再把这个值绑定到 `text`。`let` 不是把某个现成位置改成字符串；它建立了一个新的绑定。

这个区别也解释了为什么不能把任意表达式放在赋值左侧：`42 = 10` 没有可写入的位置，`x + 1 = 10` 也没有。

「值表达式不代表存储位置」只说了一半。计算结果总要有地方落：直接绑定给变量时，值落进变量的位置；当场使用时——比如对它取引用——值先落进一个**临时位置（temporary）**。把两半合起来，模型才是完整的：

> 每个值都落在某个位置里。位置表达式指向一个已经存在的位置；值表达式算出新值，落进为它准备的位置——变量绑定，或一个临时位置。

临时位置通常只活到所在语句结束。`extended` 那行是例外：

## 读取一个位置时发生什么

位置表达式自己不产生值。当它出现在需要值的地方——赋值右侧、函数参数、`println!` 里——读取才会发生：从位置里取出值，交给这个上下文。

```text
let target = source;
```

`source` 是位置表达式，`let` 需要一个值，于是读取发生。读出来的结果怎么处理，由类型决定：

- `i32` 实现了 `Copy`，按位复制一份，原位置照旧可用；
- `String` 没有实现 `Copy`，读取变成移动——值被取走，原位置作废，释放责任随之转移；
- 想留下原来的绑定，就显式调用 `.clone()` 再造一份。

所以位置/值和复制/移动不是两组要分开背的概念，而是同一个动作的前后两半：位置表达式回答「从哪里取值」，类型决定「取走之后，原来的位置怎么办」。

## 从字段位置移动

## 位置上下文

同一个表达式在不同上下文中，编译器会要求不同的能力：

- 赋值左侧需要可写的位置；
- `&mut` 后面需要可以独占借用的位置；
- 读取位置时，可能复制它的值，可能移动它的值，也可能被拒绝移出；
- `&` 借用位置时，不会接手位置中值的所有权；
- 解引用可以把一个引用或智能指针带回它指向的位置。

这些能力仍然受第一篇的规则限制。一个位置存在，不代表它总能被修改、移动或借用。

## 与 4.1 的关系

4.1 讲 `let`、`mut`、`Copy`、`Move` 和 `Clone` 时，先区分“绑定”和“绑定中的值”。位置表达式把这个模型再往前推进一步：

> 变量、字段、索引和解引用都可以成为值的来源，但它们是否能被写入，取决于可变性和借用关系。

这也是结构体方法、切片索引和 `DerefMut` 能够接回所有权模型的原因。

## 限制与实现细节

“位置”是语义上的存储位置，不是对机器布局的承诺。编译器可能把值放进寄存器、消除存储，或者合并访问；只要程序的可观察行为符合 Rust 规则即可。

链的“一环一环走”也是语义上的分解，不是运行期的执行顺序。编译器在编译期沿链算出最终位置，字段和常量索引通常折叠成一次地址计算——`people[0].name` 的写回，往往就是对 `people` 的地址加一个常量偏移。链上真正产生运行期动作的是指针环节：沿引用解引用要读一次指针，`Vec` 的索引要先过 `index_mut` 的越界检查。

位置表达式也不等于“永远有一个合法地址”。索引可能越界，解引用可能违反借用关系，位置中的值也可能已经被移动。表达式的类别只说明它参与了哪种语义，不替你证明操作一定成功。
