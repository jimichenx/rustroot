## 一、容器下标如何变成位置：`Index` 与 `IndexMut` 展开

对栈上定长数组 `[T; N]`，编译器直接知道连续内存起始处与元素步长；但对标准库结构体 `Vec<T>` 或 `HashMap<K, V>`，编译器内核并不直接认识它们的内部字段。为什么 `values[1] = 99;` 依然能作为位置表达式放在赋值号左侧？

原因是标准库容器的方括号下标是 **Trait 方法调用加内建 `*` 解引用**的语法糖（Syntactic Sugar）：

- 只读上下文中的 `values[0]`，展开为 **`*Index::index(&values, 0)`**（返回 `&T` 后由 `*` 定位）；
- 可变位置上下文中的 `values[1] = 99;`，展开为 **`*IndexMut::index_mut(&mut values, 1) = 99;`**（返回 `&mut T` 后由 `*` 定位并写回）。

<Code code={indexSugar} lang="rust" />

<small class="code-source">运行输出</small>
```text
first = 10, values = [10, 99, 30]
```

看清这一步展开，就能串联两处现象：

1. **为什么越界 `panic` 发生在运行时**：下标越界检查写在 `index` / `index_mut` 的函数体内部，编译期只检查索引类型是否为 `usize`（或切片范围），运行期越界才触发终止；
2. **为什么 `let first = names[0];` 会触发 `E0507`**：对 `Vec<String>` 写 `names[0]` 时，展开后的 `*Index::index(&names, 0)` 落在了只读引用 `&String` 的解引用位置上，既违背了连续缓冲区不可留空的约束，也无法从 `&self` 借用背后移出 `String` 所有权。

## 二、借用值表达式：临时位置延长与 `E0716` 排障

值表达式负责算出新结果，本身不指代现成变量。但当代码需要对计算结果当场取引用时，新值必须先落进当前栈帧开辟的一个匿名**临时位置（Temporary）**。

默认规则下，**临时位置的存活区间在所在语句末尾的分号 `;` 处即告结束**。唯独当 `&`（或包含它的外层结构体/元组构造）直接作为 `let` 绑定的初始值时，编译器会触发**临时生命周期延长（Temporary Lifetime Extension）**，将该临时槽位的释放推迟到外层代码块 `}` 结束：

<Code code={temporaryPlace} lang="rust" />

- `existing` 借用的是已声明的变量位置 `text`，存活至整个代码块结束；
- `extended` 用 `&` 直接借用 `String::from("temp")` 的返回值，命中延长规则，匿名临时槽位被拉长至代码块结束，正常编译运行。

一旦在值表达式后面链式调用方法（如第 6 行注释的 `String::from("temp").as_str()`），编译器看到的是普通函数调用 `String::as_str(&临时槽位)`，**不再触发延长规则**。取消第 6、8 行注释后，临时 `String` 在第 6 行分号处当场释放，留下的切片 `bad` 立即悬垂并触发高频报错 `error[E0716]`：

<small class="code-source">编译器输出摘要（取消 temporary-place.rs 第 6、8 行注释后）</small>
```text
error[E0716]: temporary value dropped while borrowed
 --> appendix/place-value-expressions/src/bin/temporary-place.rs:6:15
  |
6 |     let bad = String::from("temp").as_str();
  |               ^^^^^^^^^^^^^^^^^^^^         - temporary value is freed at the end of this statement
  |               |
  |               creates a temporary value which is freed while still in use
7 |     println!("{existing} {extended}");
8 |     println!("{bad}");
  |                --- borrow later used here
```

工程中遇到 `E0716` 时，不要试图给类型强加生命周期标注，直接按编译器提示将中间产出的所有者拆成一行具名 `let` 绑定（如先写 `let owned = String::from("temp");`，再写 `let s = owned.as_str();`），明确接管释放时机即可解决。

## 三、同为位置，三种移出结局：引用、`static` 与 `Box<T>`

除了主线梳理的局部变量、结构体字段、下标与普通引用外，全局静态项 `static` 与堆独占智能指针 `Box<T>` 在移出非 `Copy` 值时呈现出截然不同的规则：

### 2. 全局静态变量 `static`：禁止移出（`E0507`）

`static` 声明的全局变量在程序整个运行期间固定驻留于静态数据段，本身是一个全局可见的位置表达式，允许在任意函数中读取或取 `&` 引用，但**禁止移走其内部值**：

取消第 5 行 `// let s = TEXT;` 的注释会报 `error[E0507]: cannot move out of static item TEXT`。静态变量可被任意函数反复甚至并发访问，一旦允许某次调用移走其中的值，其余代码后续读取就会落入失效内存。

### 3. 编译器专属特例：`*boxed` 允许直接移出

普通自定义智能指针与 `Rc<T>`、`Vec<T>` 的 `*x` 展开后均经过 `Deref::deref(&x)` 只读借用，同样禁止移出；唯独标准库的 **`Box<T>`** 享有编译器内建的解引用移出支持：

## 四、语义分解与机器码偏移折叠

位置表达式链（如主线中的 `people[0].name`）的「逐段寻位」是编译期类型与借用检查的语义模型，并不代表运行时要分多步跳转：

- **内联字段与常量下标折叠为单次偏移**：结构体字段与定长数组元素连续内联存放，编译器在生成机器码时直接把 `people` 的栈基址加上常量字节偏移合成为一次内存读写，甚至直接将局部变量优化进 CPU 寄存器；
- **只有跨指针与动态索引才产生运行期动作**：当链条中包含引用解引用 `*r` 时，CPU 需读取一次指针地址；包含 `Vec` 下标 `v[i]` 时，则需执行一次堆地址读取与 `i < len` 边界比较。
