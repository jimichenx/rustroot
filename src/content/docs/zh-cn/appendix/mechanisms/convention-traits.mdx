与上一节介绍的「编译器钩子 Trait（Lang Items）」不同，标准库里还有另一大类极其重要的契约：**`From` / `Into`、`TryFrom` / `TryInto`、`Default`、`AsRef` / `AsMut`、`Display` / `FromStr`**。

在编译器内核眼里，它们没有任何特殊语法特权——没有哪个运算符会直接展开成 `Default::default()` 或 `AsRef::as_ref()`。

既然没有语法特权，为什么标准库非要定义它们？
因为它们是 **Rust 全生态（标准库、数十万个第三方 crate 与你的业务代码）共同遵守的公共通信协议**。只要你的自定义类型签下了这几份契约，全生态任何使用泛型编写的库函数都能直接与你的类型无缝协作。

本节逐一拆解这四组出镜率最高的生态约定契约。

## 一、 必定成功的类型转换：`From<T>` 与 `Into<T>`

当类型 `B` 可以**百分之百成功、无信息丢失**地从类型 `A` 构造出来时（例如从 `u16` 转为 `u32`、从 `&str` 转为 `String`、或从底层错误包装为顶层错误枚举），全生态约定使用 `std::convert::From`：

<small class="code-source">推演用伪代码：为自定义端口类型实现 <code>From&lt;u16&gt;</code></small>
```rust
struct Port(u16);

impl From<u16> for Port {
    fn from(raw: u16) -> Self {
        Port(raw)
    }
}
```

正如我们在[第 7 章 7.4 节](/abstraction/conversions-and-from/)所学，标准库内部已经包含了一条一揽子实现（Blanket Implementation）：

<small class="code-source">标准库源码结构示意</small>
```rust
impl<T, U> Into<U> for T
where
    U: From<T>,
{
    fn into(self) -> U {
        U::from(self)
    }
}
```

因此在工程实践中遵循两条准则：
1. **为你自己的类型实现转换时，永远只手写 `impl From<A> for B`**：写完后，调用方既可以显式写 `Port::from(80u16)`，也可以直接写 `let p: Port = 80u16.into();`；
2. **编写通用函数接收参数时，可以用 `<T: Into<Port>>` 放宽入口**：这样调用方既可以直接传 `Port`，也可以直接传 `80u16`，函数内部统一调一句 `let port = param.into();` 即可完成归一化。

## 二、 可能失败的受检转换：`TryFrom<T>` 与 `TryInto<T>`

并不是所有转换都百分之百成功。例如：
- 把一个范围更大的 `u32` 转换成 `u16`（超过 `65535` 会溢出）；
- 把一个整数转换为要求范围在 `1..=65535` 之间的非零端口号 `Port`。

**严禁在 `From::from` 的实现内部因为输入不合法而调用 `panic!` 或 `.unwrap()`！**
一旦转换过程可能因输入数据不合法而失败，全生态约定必须改用返回 `Result` 的 **`std::convert::TryFrom<T>`**（其 내부包含一个关联类型 `type Error;`，用于指定失败时的错误类型）：

<small class="code-source">推演用伪代码：用 <code>TryFrom&lt;u32&gt;</code> 校验端口号范围</small>
```rust
impl TryFrom<u32> for Port {
    type Error = &'static str;

    fn try_from(value: u32) -> Result<Self, Self::Error> {
        if value == 0 || value > 65535 {
            Err("port out of 1..=65535 range")
        } else {
            Ok(Port(value as u16))
        }
    }
}
```

与 `From` / `Into` 完全对称，标准库也提供了一揽子实现 `impl<T, U> TryInto<U> for T where U: TryFrom<T>`。因此你只需实现 `TryFrom`，调用方就自动获得了返回 `Result` 的 `.try_into()` 方法。

## 三、 零成本借用视图转换：`AsRef<T>`

回想我们在第 4 章学过的字符串与切片法则：如果一个只读函数需要读取字符串内容，参数写 `s: &str` 可以同时接收 `&str` 和 `&String`。

但在很多工程场景下（尤其是文件操作，如 `std::fs::File::open(path)`），调用方手里拿的可能是字符串字面量 `"config.toml"`（`&str`）、可能是堆字符串 `String`、也可能是专门的路径类型 `Path` 或 `PathBuf`。如果函数参数写死某一个引用类型，其他类型的调用方就得手动转换。

为此，标准库定义了轻量级借用转换契约 **`AsRef<T>`**：

<small class="code-source">标准库源码结构示意</small>
```rust
pub trait AsRef<T: ?Sized> {
    fn as_ref(&self) -> &T;
}
```

它的工程含义是：**「在不转移所有权、不发生高昂堆内存分配的前提下，从 `&self` 零成本借出一个 `&T` 视图」**。
因为标准库已经为 `str` 和 `String` 都实现了 `AsRef<str>`（以及 `AsRef<Path>`、`AsRef<[u8]>`），当你在函数签名上写下 `<S: AsRef<str>>` 时，调用方无论直接传 `"localhost"` 还是传 `String::from("127.0.0.1")`（甚至连 `&` 都不用加），都能零分配地直接传入：

<small class="code-source">推演用伪代码：使用 <code>AsRef&lt;str&gt;</code> 同时接纳 <code>&amp;str</code> 与 <code>String</code></small>
```rust
fn print_endpoint<S: AsRef<str>>(host: S, port: Port) {
    let host_str: &str = host.as_ref();
    println!("{}:{}", host_str, port.0);
}
```

## 四、 默认值构造契约：`Default`

在 Rust 中没有「未初始化变量的默认零值」，所有变量都必须显式初始化。为了让泛型容器或配置结构体能够统一生成「合理的初始默认值」，标准库定义了 **`std::default::Default`**：

<small class="code-source">标准库源码结构示意</small>
```rust
pub trait Default {
    fn default() -> Self;
}
```

- 数字类型的 `default()` 是 `0`，`bool` 是 `false`，`String` 是空字符串 `""`，`Vec<T>` 是空数组 `vec![]`，`Option<T>` 是 `None`；
- 对于自定义结构体，你可以直接加上 `#[derive(Default)]`（自动将每个字段初始化为其类型的 `default()`），也可以手写 `impl Default`（例如将网络超时结构体的默认毫秒数设为 `3000`）。
- **生态联动收益**：只要你的类型实现了 `Default`，你就可以直接在 `Option<YourType>` 上调用 `.unwrap_or_default()`，或者在结构体初始化时使用 `..Default::default()` 自动补齐其余默认字段！

## 五、 四大生态约定契约速查与实验

| 生态约定 Trait | 核心方法签名 | 所有权与成本特征 | 典型工程用途 |
| --- | --- | --- | --- |
| **`From<T>` / `Into<T>`** | `fn from(T) -> Self` | 按值接管 `T`，构造并返回新所有者 `Self` | 必定成功的类型转换、配合 `?` 自动归并错误 |
| **`TryFrom<T>` / `TryInto<T>`** | `fn try_from(T) -> Result<Self, Self::Error>` | 按值接管 `T`，返回 `Result` | 需要做边界或格式校验、可能失败的类型转换 |
| **`AsRef<T>`** | `fn as_ref(&self) -> &T` | 只读借用 `&self`，零堆内存分配 | 让函数参数同时兼容 `&str` / `String` / `PathBuf` 等多种输入 |
| **`Default`** | `fn default() -> Self` | 无参直接构造默认实例 | 提供默认配置、配合 `unwrap_or_default()` 使用 |
