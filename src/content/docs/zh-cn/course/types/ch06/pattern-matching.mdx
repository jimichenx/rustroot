上一节末尾留下了一个直接问题：既然 `Role::Member(500)` 与 `Role::Admin { ... }` 内部都装着数据，为什么不能直接点出字段，也没有类似面向对象的 `if r is Member` 加 `r as Member` 强转语法？

回到枚举的内存布局即可看清原因。

## 为什么不能点号访问或强转

在结构体中，所有字段同时存在、偏移固定，随时可以写 `user.name`。而在 `enum Role` 的 24 字节栈槽位中，后 16 字节是分时复用的共享载荷区——当标签为 `0`（`Guest`）时，后方字节处于闲置未初始化状态；若放行 `r.security_key`，就会直接读出无效内存。

至于为什么不提供「先用 `is` 判断标签、再用 `as` 向下转型」的两步写法，原因有两层：

1. **变体不是类型**：上一节已经验证 `Role::Member` 只是变体构造器而非类型（`E0573`），语法上不存在向非类型强转的操作；
2. **两步分离存在脱节风险**：若将检查标签与读取载荷拆成两个独立动作，程序员仍可能在 `if (r instanceof Guest)` 分支内误写 `((Member) r)`，留到运行时才触发转型异常。

因此，Rust 要求通过**模式（Pattern）按形状解构（Destructuring）**，<span class="rr-keypoint">将「核对开头的判别式标签」与「按对应布局绑定内部载荷」合并为同一个不可拆分的语法动作。</span>

## `let` 解构与可反驳模式

模式匹配并非 `match` 独有。从[声明与绑定](/memory/bindings/)起使用的 `let` 语句，完整语法原本就是 `let 模式 = 表达式;`——写 `let x = 5;` 时，`x` 是接住整个值的单变量模式；面对复合结构时，怎么用构造器拼起来，就能用同形状的模式拆开：

<small class="code-source">源文件：<code>examples/types/enum-option-match/src/bin/let-pattern-refutable.rs</code></small>
<Code code={letPatternRefutable} lang="rust" />

默认运行输出 `point = (10, 20), user = Ferris (7)`。第 15、16 行直接用单行 `let` 拆开了元组 `(x, y)` 与结构体 `User { name, age }`；但一旦取消第 20 行 `// let Role::Member(points) = _role;` 的注释，对枚举执行同样的单行解构，编译器会以 `error[E0005]` 拦截：

<small class="code-source">编译器输出摘要（取消 let-pattern-refutable.rs 第 20 行注释后）</small>
```text
error[E0005]: refutable pattern in local binding
  --> types/enum-option-match/src/bin/let-pattern-refutable.rs:20:9
   |
20 |     let Role::Member(points) = _role;
   |         ^^^^^^^^^^^^^^^^^^^^ patterns `Role::Guest` and `Role::Admin { .. }` not covered
   |
   = note: `let` bindings require an "irrefutable pattern", like a `struct` or an `enum` with only one variant
```

报错揭示了积类型与和类型在解构时的根本分界：

1. **不可反驳模式（Irrefutable Pattern，必然匹配成功）**：元组 `(i32, i32)` 与结构体 `User` 只有唯一一种数据形态，`(x, y)` 和 `User { name, age }` 必定匹配成功，可直接用于普通 `let` 绑定与函数形参；
2. **可反驳模式（Refutable Pattern，可能匹配失败）**：和类型 `Role` 有三种合法可能性，单写 `Role::Member(points)` 在运行期遇到 `Guest` 或 `Admin` 时无法绑定 `points`。

面对可能失配的可反驳模式，编译器强制要求交代**其余可能性的去向**。按兜底策略的不同，`let 模式 = 表达式` 衍生出三套语法工具：

| 未命中分支的处理方式 | 语法工具 | 结构关系 |
| --- | --- | --- |
| **逐一列出全部可能性分别处理** | **`match`** | 列出各变体 `模式 => 表达式`，接受穷尽检查 |
| **命中才执行，未命中静默跳过** | **`if let`** | 在 `let 模式 = 表达式` 前加 `if` |
| **命中则留在外层继续，未命中当场退场** | **`let else`** | 在 `let 模式 = 表达式` 后接 `else { return ...; }` |

## `match` 与穷尽性检查

需要对每种变体分别计算或分流时，使用 **`match`** 表达式：

<small class="code-source">源文件：<code>examples/types/enum-option-match/src/bin/match-role.rs</code></small>
<Code code={matchRole} lang="rust" />

默认运行输出 `quotas: 10, 600, 11999`。`match role` 读取开头的标签，自上而下比对每条分支（`模式 => 表达式`，若只需部分结构体字段可写 `Role::Admin { dept_id, .. }` 忽略其余字段），并遵守两条编译期规则：

1. **各分支产出同一类型**：与[元组、函数与表达式](/types/functions-and-expressions/)中的 `if / else` 一致，`match` 作为表达式要求所有分支返回相同类型（此处均为 `u64`），否则报 `E0308`；
2. **穷尽性检查（Exhaustiveness Check，`E0004`）**：若注释掉第 12 行的 `Role::Admin` 分支，编译立即失败：

<small class="code-source">编译器输出摘要（注释掉 match-role.rs 第 12 行后）</small>
```text
error[E0004]: non-exhaustive patterns: `&Role::Admin { .. }` not covered
 --> types/enum-option-match/src/bin/match-role.rs:9:11
  |
9 |     match role {
  |           ^^^^ pattern `&Role::Admin { .. }` not covered
```

在大型项目重构中，穷尽性检查能把遗漏分支从线上事故变成编译清单：日后向 `enum Role` 新增第四个变体 `Auditor` 时，执行 `cargo build` 就会精确列出全项目每一处尚未处理 `Auditor` 的 `match` 行号。

若某段逻辑只需特殊处理少数变体，其余情况可在末尾用通配符 `_ => 默认值` 兜底。

<Aside type="caution" title="慎在核心业务枚举上滥用通配符 _">
通配符 `_` 会关闭该 `match` 对未来新增变体的 `E0004` 提醒——新增的 `Auditor` 会静默落入 `_` 分支。审查权限或状态机核心代码时，优先显式写出各变体名（同类处理可合并写为 `Role::Guest | Role::Member(_) => ...`）。
</Aside>

## 单分支简写：`if let` 与 `let else`

只关心枚举的某一种变体时，用 `if let` 或 `let else` 替代只含一个有效分支的 `match`：

### `if let`：命中才执行

右侧 `&user` 命中 `Role::Member` 时，载荷绑定给块内变量 `points` 并执行 `{}`；未命中则跳过 `{}` 继续向下执行。（若连内部载荷都不需要绑定、只想返回 `bool`，可直接用标准库宏 `matches!(user, Role::Member(_))`。）

### `let else`：不命中则退场

当前置校验要求必须拿到某个变体的数据才能继续主干逻辑时，连续套用 `if let` 会导致代码层层向右缩进。此时改用 **`let else`**：

## 模式绑定中的移动与借用

无论 `let`、`match` 还是 `if let` / `let else`，解构绑定都是对内部载荷执行赋值或借用。当变体携带 `String` 等非 `Copy` 类型时，被匹配的目标是值 `task` 还是引用 `&task`，直接决定了载荷是**移动**还是**借用**：

<small class="code-source">源文件：<code>examples/types/pattern-ownership/src/bin/match-move-and-borrow.rs</code></small>
<Code code={matchMoveAndBorrow} lang="rust" />

<small class="code-source">运行输出与编译器诊断摘要（取消第 22 行注释后）</small>
```text
inspecting: backup-db
consuming: backup-db

error[E0382]: borrow of partially moved value: `task`
  --> types/pattern-ownership/src/bin/match-move-and-borrow.rs:22:28
   |
18 |         Task::Run(name) => println!("consuming: {name}"),
   |                   ---- value partially moved here
...
22 |     println!("after move: {task:?}");
   |                            ^^^^ value borrowed here after partial move
```

三种匹配目标与所有权三件套一一对位：

| 被匹配的目标表达式 | 模式变量 `name` 的类型 | 所有权行为 | 匹配后原枚举状态 |
| --- | --- | --- | --- |
| **`&task`**（只读引用） | **`&String`** | 共享只读借用 | 继续有效（日常只读检查首选） |
| **`&mut task`**（可变引用） | **`&mut String`** | 独占可变借用 | 继续有效，可在分支内原地修改载荷 |
| **`task`**（枚举值本身） | **`String`** | 按值移动（非 `Copy` 时） | **部分移动失效**（再用报 `E0382`；若隔着 `&self` 按值移出则报 `E0507`） |

因此，若 `if let Message::Text(content) = msg` 之后还需继续使用 `msg`，只需在右侧补上 `&` 改为匹配 `&msg` 即可转为只读借用。掌握了和类型的布局与穷尽解构后，下一节看标准库如何用一个两变体枚举 `Option<T>` 替代空指针。
