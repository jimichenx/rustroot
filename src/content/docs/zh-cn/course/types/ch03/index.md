上一篇顺着「唯一释放责任」推导出了所有权、移动与借用，并在变量声明、重新赋值和遮蔽的真实代码中核对了这套规则。

按许多传统教程的顺序，接下来就该逐一学习整数、数组、字符串和结构体的语法了。但如果在动手学具体容器之前不先把原有的「类型」观念扭转过来，后面遇到「同样占 8 字节，`&i32` 复制而 `&mut i32` 移动」，或是面对 `[i32; 4]`、`&[i32]`、`Vec<i32>`、`Option<&str>` 等一连串签名时，往往只能靠死记硬背应付编译器。

所以本章不是为了空谈理论，而是在进入具体数据类型之前，先用三节重塑你看待 Rust 类型的整体架构：

- **第一段：类型的两面与编译期类型表。** 看清在没有 `class` 与运行时对象头的 Rust 里，每个具体类型（含不同有效区间的引用）如何在编译器的「编译期类型表」中对应一个包含物理表示与安全约束的独立「类型实体」，并在生成机器码时整表擦除。
- **第二段：类型构造器与按需生成。** 明确 `T`、`&T`、`&mut T` 是三个独立的类型；看清写下 `struct User` 之后，`&User`、`&mut User`、`[User; 4]`、`Vec<User>` 这些新的类型实体如何在编译期由类型构造器按需填参生成，并由外层构造器重新制定约束。
- **第三段：正交零件组合与由外向内拆读。** 对比其他语言打包好的「预制件」与 Rust 拆分出的构造器零件，掌握由外向内逐层拆读嵌套类型签名的方法，并分清语言内置构造器与标准库构造器的边界。

阅读本章时请放轻松：为了展示真实现象，示例代码中会提前路过 `[i32; 4]`、`&[i32]`、`Vec<T>`、`Option<T>` 等几种复合类型。**现阶段不必追求把这些写法的创建语法或方法细节全部看懂**——那些实操内容会在本篇后续各章逐一拆透；本章你只需要抓准大体的架构画面，能从全局上回答下面三个问题就算过关：

1. **表示相同为何规则不同**：为什么栈上内存布局相同的 `&i32` 与 `&mut i32`、`String` 与 `Vec<u8>`，允许的赋值方式与数据内容却不同？这些约束信息在编译后去了哪里？
2. **新类型何时由谁生成**：当你在代码中只定义了 `struct User` 时，从未手写过的 `&User` 与 `&mut User` 是在什么时候由什么机制生成的？为什么表面同写 `&String` 的两处局部借用，在编译器内部却是两个不同的具体类型？
3. **多层签名从哪一层读起**：面对 `Option<&[i32]>` 或 `&mut Vec<String>` 这样的嵌套类型，如何由外向内判断它在栈上占多少字节、能否复制以及是否承担释放责任？
