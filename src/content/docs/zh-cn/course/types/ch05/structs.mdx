上一节的元组 `(i32, i32)` 可以临时打包多个值，但在业务建模中有两处局限：一是元素没有名字，靠 `.0`、`.1` 访问难以表达业务含义；二是任意两个 `(i32, i32)` 都是同一个类型，编译器无法区分「二维坐标」与「矩形宽高」。

要在工程中建立语义明确的数据模型，需要用 **`struct`（结构体）**定义全新的**独立类型**。

## 结构体的三种形态与初始化简写

每写下一个 `struct` 定义，就在编译期类型表中注册了一个独立的类型。结构体共有三种声明形态：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/struct-basics.rs</code>（节选）</small>
<Code code={structBasics} lang="rust" anchor="three_forms" />

1. **具名字段结构体（`User`）**：为每个字段命名并标注类型。实例化时写 `User { 字段名: 值, ... }`，字段顺序可调换，但必须初始化**每一个字段**——Rust 不存在未初始化的默认 `null` 字段。
2. **元组结构体（`Color`）**：只给结构体起类型名，字段不命名，用 `red.0`、`red.1` 取值。即便再定义一个同样装三个 `u8` 的 `struct Point(u8, u8, u8);`，`Color` 与 `Point` 也是两个互不兼容的独立类型，可防止传参时混淆。
3. **单元结构体（`AlwaysEqual`）**：不带任何字段，与上一节的单元类型 `()` 一样在运行时占 **0 个字节**，常用于在不占内存的前提下单独挂载行为契约。

构造具名字段结构体时，支持两项常用简写：

<Code code={structBasics} lang="rust" anchor="shorthand,update_syntax" />

- **同名字段简写**：当变量名与字段名相同时（如参数 `name` 与 `age`），直接写 `User { name, age, active: true }`，无需重复写 `name: name`。
- **结构体更新语法 `..u1`**：基于已有实例创建新实例时，末尾写 `..u1` 表示其余未列出的字段直接按 `=` 规则从 `u1` 赋值过来。注意其所有权后果：上例中从 `u1` 取用的 `age`（`u64`）与 `active`（`bool`）均实现了 `Copy`，因此 `u1` 仍保持有效；若 `..u1` 取走了未实现 `Copy` 的 `String` 字段，则 `u1` 对应字段会发生**移动**而失效。

运行完整程序，实测三种结构体在 64 位平台栈上占用的字节数：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/struct-basics.rs</code></small>
<Code code={structBasics} lang="rust" collapse={12} />

<small class="code-source">运行输出</small>
```text
u2: Bob (age 28, active true)
rgb = (255, 0, 0)
sizes: User = 40B, Color = 3B, AlwaysEqual = 0B
```

`User` 占 **`40B`**（`String` 的 24 字节控制头 + `u64` 的 8 字节 + `bool` 的 1 字节 + 7 字节内存对齐填充），`Color` 占 **`3B`**，`AlwaysEqual` 占 **`0B`**。

与 Java 或 Python 对象在堆上附带 12～16 字节对象头、内部字段再二次跳转不同，Rust 的 `struct` 采用**扁平内联（Flat Inline）**布局：所有字段紧挨着直接平铺在当前栈帧（或外层容器缓冲区）中，没有任何隐藏的运行时对象头。

<Aside type="note" title="字段可变性由外层绑定统一控制">
Rust 不支持在结构体定义中给单个字段标 `mut`（不能写 `struct User { mut age: u64 }`）。字段能否修改取决于实例绑定的声明方式：`let user = User { ... };` 下全部字段只读，`let mut user = User { ... };` 下全部字段均可修改（如 `user.age = 29;`）。
</Aside>

## 为什么自定义类型默认走移动语义

定义一个仅含两个 `i32` 字段（共 8 字节、无堆分配）的结构体 `Point`：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/point-move.rs</code></small>
<Code code={pointMove} lang="rust" />

一旦取消最后一行 `// println!("{}", a.x);` 的注释，编译器会报出 `error[E0382]: borrow of moved value: a`。同样装两个 `i32`，元组 `(i32, i32)` 与数组 `[i32; 2]` 自动实现了 `Copy`，自定义 `struct Point` 却默认走**移动**语义。

这是为了守住自定义类型的**演进兼容性**：如果编译器因 `Point` 当前只含整数就隐式替它开启 `Copy`，日后一旦向该结构体新增一个非 `Copy` 字段（如 `label: String`），下游所有依赖 `let b = a;` 按位复制的调用方都会编译断裂。

因此，自定义结构体**默认一律走移动语义**。仅当确认类型体积小、全部字段均满足 `Copy`，且愿意将其作为对外契约承诺时，才通过 `#[derive(...)]` 属性让编译器自动生成复制实现：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/point-copy.rs</code></small>
<Code code={pointCopy} lang="rust" />

`#[derive(Clone, Copy)]` 会让编译器为 `Point` 自动生成 `Clone`（显式 `.clone()` 复制契约）与 `Copy`（赋值时隐式按位复制契约；语言规定实现 `Copy` 必须同时实现前置契约 `Clone`）。若结构体内部含有 `String` 等未实现 `Copy` 的字段，强行标注 `Copy` 会被编译器以 `error[E0204]` 拒绝。

## 部分移动（Partial Move）：字段粒度的状态追踪

如果结构体同时包含 `String` 字段与 `u32` 字段，不移动整个实例，只把其中的 `String` 字段单独赋给新变量，会发生什么？

在[数组](/types/arrays/)与[动态数组 `Vec<T>`](/types/vectors/)中，编译器禁止写 `let s = names[0];` 移出单个元素，原因是下标 `i` 可以是运行期算出的变量，编译期无法静态追踪哪个槽位已空。而**结构体的字段名（如 `user.name`）在源码中是编译期静态确定的**。运行下面这段程序（顶部 `#[derive(Debug)]` 让结构体支持 `{:?}` 调试打印）：

<StructPartialMove />

这就是结构体（及元组）的**部分移动（Partial Move）**机制。<span class="rr-keypoint">执行 `let name = user.name;` 时，运行时栈帧上的槽位同样留在原地，编译期状态表则将有效性追踪细化到单个字段粒度：</span>

| 访问目标 | 编译期裁决 | 状态表与释放规则 |
| --- | --- | --- |
| **已移出的字段（`user.name`）** | **禁止（`E0382`）** | 堆缓冲区释放责任已转交 `name`，原字段记为已移出 |
| **结构体整体（`user`）** | **禁止（`E0382`）** | 内部字段已残缺，不能再作为完整的 `User` 整体传参或打印 |
| **其余未移动字段（`user.age`）** | **允许** | 状态仍为有效，可单独读写；`user` 离开作用域时，编译器仅对尚未移出的剩余有效字段执行释放 |

## 小结与动手核对

1. **三种形态与扁平内联**：`struct` 分为具名字段、元组和 0 字节单元结构体；字段直接内联平铺、零对象头，可变性由外层 `let mut` 统一控制；
2. **默认移动，显式 `Copy`**：自定义结构体默认走移动语义，仅在全部字段支持 `Copy` 且显式标注 `#[derive(Clone, Copy)]` 时按位复制；
3. **字段级部分移动**：移出单个非 `Copy` 字段后，该字段与结构体整体均失效（`E0382`），未移出的其余字段仍可独立访问与释放。
