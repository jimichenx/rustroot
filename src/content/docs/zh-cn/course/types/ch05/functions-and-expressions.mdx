前两章拆解的[数组](/types/arrays/) `[T; N]` 与 `Vec<T>` 都要求所有元素属于同一种类型。在进入自定义结构体（`struct`）之前，本节依次立稳组织日常代码的四块基础构件：打包不同类型数据的**元组**、取代 `void` 的 0 字节**单元类型 `()`**、**函数签名与分号返回规则**，以及能直接求值的**代码块与控制流表达式**。

## 元组：打包不同类型的值

当需要把几个不同类型的值临时组合在一起（如状态码与布尔标记、二维坐标对）时，使用的是圆括号写成的**元组（Tuple）**：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/tuple-and-unit.rs</code>（节选）</small>
<Code code={tuplesAndUnit} lang="rust" anchor="tuple_basics" />

<small class="code-source">运行输出</small>
```text
status = 200, ok = true, first = 200
```

对照这三行代码，使用元组需掌握三点规则：

- **类型与长度编译期固定**：类型标注把各位置的类型按顺序写在圆括号内（如 `(i32, bool)`，局部变量也可省略标注交由编译器推断）；一旦声明，元素个数与各位置的类型均不可更改；
- **两种取值方式**：可用 `let (status, ok) = record;` 按位置一次性**解构（Destructure）**绑定到多个变量，也可用点号加从 `0` 开始的下标（如 `record.0`、`record.1`）单独读取；
- **复制与移动规则**：与数组一致，当内部所有元素都实现 `Copy`（如 `i32` 与 `bool`）时，元组自动实现 `Copy`，解构后原变量 `record` 仍可继续访问；只要包含未实现 `Copy` 的元素（如 `(String, i32)`），整体赋值或移出该元素就会发生移动。

## 单元类型 `()`：占 0 字节的空元组

往元组里放两个元素是 `(i32, bool)`；如果**一个元素都不放**，写出来就是一对空括号 **`()`**。Rust 称之为**单元类型（Unit Type）**，它唯一的值也写作 `()`：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/tuple-and-unit.rs</code>（节选）</small>
<Code code={tuplesAndUnit} lang="rust" anchor="unit_basics" />

<small class="code-source">运行输出</small>
```text
unit = (), size of () = 0B
```

输出 `size of () = 0B` 表明：`()` 是一个**零大小类型（Zero-Sized Type，简称 ZST）**。在编译期，它是合法的具体类型（可通过 `{:?}` 调试格式打印出 `()`）；到了运行时，它占 **0 个字节**，CPU 不会为它生成任何搬运数据的指令。

C 或 Java 将不返回业务数据的位置标为 `void`（表示「无类型」的语法特例）；Rust 取消了 `void`，统一用占 0 字节的具体类型 `()` 表示「没有业务值需要传递」。

```text
[init] ready

```

### 显式标注的函数签名

Rust 用 `fn` 定义函数，函数名与参数名采用蛇形命名法（`snake_case`）。参数列表写为 `参数名: 类型`，返回类型跟在箭头 `->` 之后。上面三个函数覆盖了日常全部三种返回形式：

1. **返回单个值**：`add` 声明 `-> i32`，向调用方交出一个整数；
2. **返回多个值**：`swap` 声明 `-> (bool, i32)`，用元组一次打包交出多个值；
3. **不返回业务数据**：`log_ready` 省略了 `->` 部分——**省略返回类型的函数一律等价于显式写出 `-> ()`**，因此 `main` 中可以把 `log_ready("init")` 的返回值直接绑定到 `unit_val: ()`。

在函数体内部，局部变量可以省略类型标注交由编译器推断；但在**函数签名**上，所有参数和返回值的类型**必须显式写出**。函数签名是跨函数的编译期检查边界：调用方只需读取一行签名，就能核对参数类型、借用权限与所有权转移，无需翻看函数体实现；函数体内部的修改只要不改动签名，也不会波及外部调用方。

### 表达式与语句：决定返回值的分号

再看 `add` 与 `swap` 的函数体：最后一行只写了 `a + b` 和 `(b, a)`，既没有写 `return`，末尾也没有加分号 `;`。若将 `fn-and-unit.rs` 中 `add` 里的 `a + b` 注释掉、取消 `a + b;` 的注释，编译器会立刻报出类型不匹配：

<small class="code-source">编译器输出摘要（取消 fn-and-unit.rs 中 a + b; 注释后）</small>
```text
error[E0308]: mismatched types
 --> types/structs/src/bin/fn-and-unit.rs:2:27
  |
2 | fn add(a: i32, b: i32) -> i32 {
  |    ---                    ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
3 |     // a + b
4 |     a + b;
  |          - help: remove this semicolon to return this value
```

多加一个分号 `;` 就让产出类型从 `i32` 变成 `()`，原因在于 Rust 对**表达式（Expression）**与**语句（Statement）**的区分：

| 语法构件 | 作用 | 末尾分号 `;` | 求值产出的类型 |
| --- | --- | --- | --- |
| **表达式（Expression）** | 求值并交出一个值（如字面量 `42`、变量 `a`、运算 `a + b`、调用 `add(3, 4)`） | **不带分号** | 求值结果的具体类型 `T`（如 `i32`） |
| **语句（Statement）** | 执行动作而不向外传递计算值（如 `let x = 1;` 声明，或在表达式末尾加 `;`） | **带分号 `;`** | 丢弃内部算出的值，对外固定交出 **`()`** |

在函数体 `{ ... }` 的末尾：<span class="rr-keypoint">不加分号的尾部表达式直接成为整个函数的返回值；加上分号则把刚算出的值当场丢弃并交出 `()`，与签名 `-> i32` 冲突而触发 `E0308`。</span>（`return` 关键字仅用于从函数中途提前返回，正常结尾直接写尾部表达式。）

## 代码块与控制流表达式

函数体靠尾部无分号表达式交出结果，并非 `fn` 独有的规则。在传统命令式语言中，`{ ... }`、`if / else` 与循环只负责划分作用域或跳转，不能放在等号右侧；而在 Rust 中，**代码块 `{ ... }`、`if / else` 与 `loop` 本身全都是表达式**，可以直接求值并赋给变量，也可以直接作为函数的尾部返回值。

### 代码块 `{ ... }` 求值

一对普通花括号 `{ ... }` 既划定了独立的局部作用域（内部变量 `base` 在 `}` 处离开作用域并释放），整块本身又能向外产出计算结果：

<Code code={exprBlocks} lang="rust" anchor="block_expr" />

块内前面可以按顺序执行多条带分号的语句，最后一行不带分号的 `base + 5` 成为整个代码块交出的值（`15`）；右花括号后面的 `;` 则用于结束外层的 `let bonus = ...;` 声明语句。

### `if / else` 分支与类型一致

条件分支同样是表达式，既可以直接作为函数体返回元组，也可以直接写在 `let` 等号右侧（替代其他语言的三元运算符 `cond ? a : b`）：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/expr-blocks.rs</code>（节选）</small>
<Code code={exprBlocks} lang="rust" anchor="min_max_fn,if_expr" />

编写 `if / else` 表达式须满足三条类型规则：

1. **条件必须是 `bool` 类型**：条件外不套圆括号，也不会把整数 `0` 或空字符串隐式当作 `false`；
2. **各分支靠尾部无分号表达式交出值**：若在某支末尾多加了分号（如写成 `{ "A"; }`），该分支就会丢弃字符串并交出 `()`；
3. **所有分支必须产出同一个类型**：变量或函数返回值在编译期只能有唯一确定的类型。取消上面 `let bad` 的注释让两个分支分别返回 `&str` 与整数，编译器会直接拦截；同理，省略 `else` 分支的 `if` 在条件为 `false` 时只能交出 `()`，因此无 `else` 的 `if` 求值类型固定为 `()`。

<small class="code-source">编译器输出摘要（取消 expr-blocks.rs 中 let bad 注释后）</small>
```text
error[E0308]: `if` and `else` have incompatible types
  --> types/structs/src/bin/expr-blocks.rs:26:48
   |
26 |     let bad = if score >= 60 { "pass" } else { 0 };
   |                                ------          ^ expected `&str`, found integer
```

### 循环求值：`loop`、`while` 与 `for`

基础循环按能否向外交出计算结果分为两类：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/expr-blocks.rs</code>（节选）</small>
<Code code={exprBlocks} lang="rust" anchor="loop_expr" />

- **`loop`（无限循环）可交出计算值**：循环持续运行直至遇到 `break`；写成 `break 表达式;`（如 `break count * 100;`）可在退出循环的同时，将该值作为整个 `loop { ... }` 表达式的结果赋给 `code`；
- **`while`（条件循环）固定产出 `()`**：若初始条件即为 `false`，循环体一次也不会执行，编译器无法保证拿到结果值，因此 `while` 表达式的类型固定为 `()`；
- 遍历集合的 `for` 循环求值类型同样固定为 `()`，其背后的迭代器协议将在[`for` 循环与迭代器](/abstraction/for-and-iterators/)中拆解。
