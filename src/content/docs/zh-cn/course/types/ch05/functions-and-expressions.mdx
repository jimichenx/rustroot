## 函数签名、元组与单元类型 `()`

日常函数按返回形式主要分为三类：返回单个值、用元组返回多个值，以及不返回业务数据。

### 1. 函数签名：跨函数的类型与所有权契约

Rust 用 `fn` 定义函数，函数名与参数名采用蛇形命名法（`snake_case`）：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/fn-and-unit.rs</code>（节选）</small>
<Code code={fnAndUnit} lang="rust" anchor="add_fn" />

参数列表写成 `参数名: 类型`，返回值类型跟在箭头 `->` 之后。在函数体内部，局部变量可以省略类型标注交由编译器推断；但在**函数签名**上，所有参数和返回值的类型**必须显式写出**。

这项规定的目的是隔离跨函数的编译期检查：调用方只需读取一行函数签名，就能核对参数类型、借用权限与所有权交接，无需翻看函数体实现；函数体内部的修改只要不改动签名，也不会波及外部调用方。

<Aside type="note" title="为什么参数类型后置（a: i32），返回值用箭头（-> i32）">
将标识符放在冒号左侧（`let x: i32 = 10;`、`fn add(a: i32)`），一方面使变量名与参数名在左缘整齐对齐，另一方面与类型推断保持同一套语法骨架——省略标注时直接抽掉中间的 `: i32` 即变为 `let x = 10;`。返回类型采用 `->` 而非冒号，则是为了在参数列表、后续泛型约束与函数体花括号 `{` 之间划出无歧义的语法分界。
</Aside>

### 3. 单元类型 `()`：为什么 Rust 没有 `void`

如果元组里一个元素都不放，写出来就是一对空括号 **`()`**，称为**单元类型（Unit Type）**，其唯一的值也写作 `()`：

C 或 Java 将不返回业务数据的函数标为 `void`（表示「无类型」的语法特例）；Rust 取消了 `void`，**省略 `-> ReturnType` 的函数一律等价于显式返回单元类型 `-> ()`**。运行完整程序核对三类函数的输出及 `()` 占用的字节数：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/fn-and-unit.rs</code></small>
<Code code={fnAndUnit} lang="rust" collapse={12} />

<small class="code-source">运行输出</small>
```text
[init] ready
sum = 7, min = 2, max = 9 (or 9), unit = (), size of () = 0B
```

输出 `size of () = 0B` 表明：`()` 是一个**零大小类型（Zero-Sized Type，简称 ZST）**。它在编译期是合法的具体类型，到了运行时占 **0 个字节**，CPU 不会为它生成任何搬运数据的机器指令。

<Aside type="note" title="0 字节类型的复用价值：标准库如何基于 HashMap<T, ()> 实现 HashSet<T>">
把「无返回值」设计成占 0 字节的具体类型 `()` 而非 C / Java 的 `void` 关键字，带来了一项直接收益：`()` 可以作为合法的类型参数填入任意类型构造器。

回看[键值容器 `HashMap<K, V>`](/types/hashmaps/)：在 Java 中，`void` 不能填入泛型，`HashSet<E>` 内部虽然复用了 `HashMap<E, Object>`，但每个哈希节点仍要额外存储一个指向全局假对象 `PRESENT` 的引用字段（4～8 字节）。而在 Rust 中，把值类型 `V` 填成 `()` 得到 `HashMap<T, ()>` 后，`()` 占 0 字节且不增加内存对齐填充，哈希槽位里只紧凑存放键 `T`，编译器也不会生成任何读写值的指令——无需重写哈希探测与扩容代码，就在物理层消除了值的全部开销。

不过，直接拿裸 `HashMap<T, ()>` 当集合用仍有接口瑕疵：每次插入都得传空值 `insert(k, ())`，返回值也是语义别扭的 `Option<()>` 而非 `bool`。为此，标准库在它外面包了一层下一节将介绍的单字段 `struct` 外壳（`pub struct HashSet<T> { map: HashMap<T, ()> }`）：内存布局保持不变，对外契约则重塑为 `insert(k) -> bool`、`contains` 与交并差等集合运算，再次印证了[类型的两面](/types/representation-and-constraints/)中「物理表示」与「行为约束」的正交分工。
</Aside>

## 表达式与语句：决定返回值的分号 `;`

再看 `fn-and-unit.rs` 里的 `add` 函数：函数体最后一行只写了 `a + b`，既没写 `return`，末尾也没加分号 `;`。若注释掉 `a + b`、取消第 6 行 `a + b;` 的注释，编译器会报出类型不匹配：

<small class="code-source">编译器输出摘要（取消 fn-and-unit.rs 中 a + b; 注释后）</small>
```text
error[E0308]: mismatched types
 --> types/structs/src/bin/fn-and-unit.rs:4:27
  |
4 | fn add(a: i32, b: i32) -> i32 {
  |    ---                    ^^^ expected `i32`, found `()`
5 |     // a + b
6 |     a + b;
  |          - help: remove this semicolon to return this value
```

多加一个分号 `;` 就让产出类型从 `i32` 变成 `()`，根源在于**表达式（Expression）**与**语句（Statement）**的区分：

| 语法构件 | 作用 | 末尾分号 `;` | 求值产出的类型 |
| --- | --- | --- | --- |
| **表达式（Expression）** | 计算并向外产出一个值（如 `a + b`、`add(3, 4)`） | **不带分号** | 计算结果的具体类型 `T`（如 `i32`） |
| **语句（Statement）** | 执行动作而不向外传递计算值（如 `let x = 1;` 或表达式加 `;`） | **带分号 `;`** | 丢弃内部算出的值，对外固定产出 **`()`** |

在任意花括号代码块 `{ ... }` 的末尾：<span class="rr-keypoint">不加分号的尾部表达式直接成为整个代码块（或函数）的返回值；加上分号则把刚算出的值当场丢弃并交出 `()`，与签名 `-> i32` 冲突而触发 `E0308`。</span>（`return` 关键字仅用于从函数中途提前返回，正常结尾直接写尾部表达式。）

## 控制流与代码块表达式

在传统命令式语言中，`if / else`、循环与 `{ ... }` 只负责控制跳转，不能直接放在 `let x = ...` 右侧；而在 Rust 中，**代码块 `{ ... }`、`if / else` 与 `loop` 本身都是表达式**，可以直接求值并赋给变量。

### 1. `if / else` 条件表达式

条件分支可直接写在 `let` 等号右侧（替代其他语言的三元运算符 `cond ? a : b`）：

<small class="code-source">源文件：<code>examples/types/structs/src/bin/expr-blocks.rs</code>（节选）</small>
<Code code={exprBlocks} lang="rust" anchor="if_expr" />

编写 `if` 表达式须满足三条类型规则：

1. **条件必须是 `bool` 类型**：不用圆括号包裹，且不会把整数 `0` 或空串隐式当作 `false`；
2. **分支尾部不加分号**：各分支最后一行不加分号以交出结果值（最外层末尾的 `;` 用于结束整条 `let` 声明语句）；
3. **所有分支必须产出同一个类型**：变量 `grade` 在编译期只能拥有唯一确定的类型。若取消上面 `let bad` 的注释，让两个分支分别返回 `&str` 与整数，编译器会报错拦截；同理，省略了 `else` 分支的 `if` 在条件不成立时只能产出 `()`，因此整个 `if` 的类型也固定为 `()`。

### 2. 代码块 `{ ... }` 与循环（`while` / `loop`）

一对普通花括号 `{ ... }` 既划定了独立的局部变量作用域（内部 `base` 的栈槽位随 `}` 结束收回），又能通过尾部表达式向外产出计算结果；除后续在[`for` 循环与迭代器](/abstraction/for-and-iterators/)展开的 `for` 遍历外，基础循环分为条件循环 `while`（求值类型固定为 `()`）与无限循环 `loop`（支持用 `break 表达式;` 退出并交出计算值）：

## 小结与动手核对

1. **函数签名与 `()`**：函数参数与返回类型必须显式写出；多返回值用元组 `(T1, T2)`，省略返回类型的函数默认返回占 **0 字节**的单元类型 **`()`**；
2. **分号决定产出**：代码块末尾不带分号的尾部表达式向外返回类型 `T` 的值，加上分号 `;` 则丢弃该值并返回 `()`；
3. **控制流即表达式**：`if` 条件须为 `bool`；将 `{ ... }`、`if / else` 或 `loop { break val; }` 用作表达式赋值时，所有出口分支必须产出**同一个类型**。

### 动手核对

判断下面这个函数能否通过编译，并指出原因：

```rust
fn check_positive(n: i32) -> bool {
    if n > 0 {
        true;
    } else {
        false
    }
}
```

核对结果：**不能通过编译（报 `error[E0308]: mismatched types`）**。`true;` 末尾多加了分号 `;`，使 `if` 分支丢弃 `true` 并产出 `()`，与 `else` 分支的 `bool` 及函数返回类型 `-> bool` 冲突；去掉 `true` 后的分号即可通过。下一节进入结构体（`struct`），看如何把多个字段组合成独立的所有权单元。
