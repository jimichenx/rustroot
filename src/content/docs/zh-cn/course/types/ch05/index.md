前两章拆解了语言内置与标准库提供的核心类型构造器（引用、数组、切片、`Vec<T>`、字符串与哈希表）。本章进入自定义数据建模与行为组织——定义函数契约、拼装复合数据结构，并把访问权限写进方法签名。

从面向对象语言转向 Rust 时，函数与结构体上最先遇到的通常是三处差异：没有 `void` 关键字，函数末尾多打一个分号 `;` 就会触发类型报错；`struct` 只声明平铺内联的数据字段，无隐藏对象头，移走其中一个字段后其余字段仍可单独访问；方法没有隐式的 `this` 指针，必须在首个参数位置显式写出 **`&self`**、**`&mut self`** 或 **`self`**。

本章分四步推进：

- **元组、单元类型 `()`、函数签名与表达式控制流**：先立稳异质定长的元组与取代 `void` 的 0 字节单元类型 `()`；再明确函数签名作为跨函数类型与所有权校验边界的作用，看清分号 `;` 如何把产出值的表达式变成返回 `()` 的语句，以及 `{}`、`if / else` 和 `loop` 如何直接求值。
- **结构体（`struct`）与字段级部分移动**：拆解具名字段、元组与单元三种结构体的扁平内联布局，说明自定义结构体为何默认走移动语义（需显式标注 `#[derive(Clone, Copy)]`），并追踪移出单个字段后编译期状态表在字段粒度上的有效性规则。
- **方法接收者三件套与点号自动适配**：通过 `impl` 块分离数据与行为，区分关联函数（`::`）与方法（`.`）；将 `&self`、`&mut self`、`self` 对位到借用与移动规则上，厘清点号 `.` 自动补齐 `&`、`&mut` 与 `*` 的安全边界。
- **位置表达式与值表达式**：区分指明内存槽位的位置表达式（变量 `x`、解引用 `*r`、下标 `v[i]`、字段 `p.f`）与算出新结果的值表达式，统一解释赋值左侧要求以及四种位置在移出非 `Copy` 值时的编译期裁决。

读完本章，你应当能独立回答以下问题：

1. 函数体或 `if / else` 分支末尾加不加分号 `;`，对求值产出的类型有什么影响？
2. 当结构体中的某个非 `Copy` 字段被移走后，原结构体整体、被移走的字段以及其余未移动的字段分别处于什么可用状态？
3. 设计或审查结构体方法时，何时用 `&self`、何时用 `&mut self`、何时用按值消费的 `self`？为什么不可变绑定调不了 `push`？
4. 同样指明一块已有内存槽位，为什么结构体字段允许移出 `String`，而数组下标与引用解引用却禁止移出？
