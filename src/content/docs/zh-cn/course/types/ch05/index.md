前两章拆解了语言内置与标准库提供的核心类型构造器（引用、数组、切片、`Vec<T>`、字符串与哈希表）。本章进入自定义数据建模与行为组织——看如何定义函数契约、拼装复合数据结构，并把操作权限写进方法签名。

从面向对象语言转向 Rust 时，函数与结构体上最先遇到的通常是三处差异：没有 `void` 关键字，函数末尾多打一个分号 `;` 就会触发类型报错；`struct` 只声明紧挨平铺的数据字段，无隐藏对象头，移走其中一个字段后其余字段仍可单独访问；方法没有隐式的 `this` 指针，必须在第一个参数位置显式写出 **`&self`**、**`&mut self`** 或 **`self`**。

本章分三段把这三处机制串成闭环：

- **第一段：函数签名、单元类型 `()` 与表达式控制流。** 明确函数签名作为跨函数类型与所有权校验边界的作用；看清空元组 `()`（占 0 字节的单元类型）如何取代 `void`，分号 `;` 如何把产出值的表达式变成返回 `()` 的语句，以及 `{}`、`if / else` 和 `loop` 如何作为表达式直接产出值。
- **第二段：结构体（`struct`）与部分移动（Partial Move）。** 拆解具名字段、元组与单元三种结构体的扁平内联内存布局，说明自定义结构体为何默认走移动语义（需显式标注 `#[derive(Clone, Copy)]`），并追踪移出单个字段后编译期状态表在字段粒度上的有效性规则。
- **第三段：方法接收者三件套与点号自动适配。** 通过 `impl` 块分离数据与行为，区分关联函数（`::`）与方法（`.`）；将 `&self`、`&mut self`、`self` 对位到借用与移动规则上，厘清编译器在 `.` 调用点自动补齐 `&`、`&mut` 与 `*` 的方向及安全边界。

读完本章，你应当能独立回答以下三个问题：

1. **表达式与语句的分界**：函数体或 `if / else` 分支末尾加不加分号 `;`，对求值产出的类型有什么影响？
2. **字段级的所有权状态**：当结构体中的某个非 `Copy` 字段被移走后，原结构体整体、被移走的字段以及其余未移动的字段分别处于什么可用状态？
3. **方法接收者如何选型**：设计或审查结构体方法时，何时用 `&self`、何时用 `&mut self`、何时用按值消费的 `self`？为什么不可变绑定调不了 `push`？
