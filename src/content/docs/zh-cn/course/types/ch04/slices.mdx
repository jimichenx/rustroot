上一节的 `sum4(arr: &[i32; 4])` 被长度 `; 4` 绑住，既无法接收长度为 `3` 的数组，也无法只计算数组中间某一段元素。在日常编码中，要**不复制原数据，借用整段序列或切出其中一段连续区间**（类似 Python 的 `a[1:3]`），使用的是**切片引用 `&[T]`**（日常交流中也常简称为**切片**）。

## 切片的基本用法

将求和函数的参数类型从 `&[i32; 4]` 改为抹去长度的 **`&[i32]`**，同一个函数就能同时接纳不同长度的数组及子区间（代码中 `for r in arr` 依次借出切片内每个元素的只读引用 `r: &i32`，再用 `*r` 解引用累加）：

<Code code={dstSum} lang="rust" anchor="slice_sum" />

<small class="code-source">运行输出</small>
```text
sum of a4:       100
sum of a3:       60
sum of a4[1..3]: 50
```

截取数组（以及后续的 `Vec<T>` 或字符串）子区间时，方括号内的**范围表达式（Range）**默认采用「左闭右开」规则。以四元素数组 `a = [10, 20, 30, 40]` 为例：

| 写法 | 含义 | 覆盖下标 | 切出的元素与长度 |
| --- | --- | --- | --- |
| **`&a[1..3]`** | **左闭右开**：从下标 `1` 开始，到 `3` 之前结束（不含 `3`） | `a[1], a[2]` | `[20, 30]`（长 `2`） |
| **`&a[..3]`** | 省略起点：从下标 `0` 开始（等价于 `&a[0..3]`） | `a[0]..a[2]` | `[10, 20, 30]`（长 `3`） |
| **`&a[1..]`** | 省略终点：从下标 `1` 切到末尾（等价于 `&a[1..4]`） | `a[1]..a[3]` | `[20, 30, 40]`（长 `3`） |
| **`&a[..]`** | 首尾全省：借用全部元素（等价于 `&a[0..4]`） | `a[0]..a[3]` | `[10, 20, 30, 40]`（长 `4`） |
| **`&a[1..=3]`** | **全闭区间**：包含末尾下标 `3` | `a[1]..a[3]` | `[20, 30, 40]`（长 `3`） |

默认采用左闭右开 `start..end` 有两个工程好处：区间元素个数直接等于 `end - start`，且相邻两段 `&a[0..2]` 与 `&a[2..4]` 的分界数字自然衔接，无需手写易错的 `+ 1` 或 `- 1`。

会用 `&[i32]` 之后，顺着类型构造器的规则往下追问，马上会浮现两个底层问题：**第一，为什么参数必须带 `&` 写成 `&[i32]`，去掉 `&` 直接写 `arr: [i32]` 行不行？第二，`&[i32]` 抹掉了编译期长度 `; N`，运行时的 `sum` 函数怎么知道读几个元素就停下？**

## 为什么不能去掉 `&`：切片类型 `[T]` 与动态大小类型

试着把 `&[i32]` 外层的 `&` 拿掉，将不带长度的 `[i32]` 直接用作函数参数类型：

取消 `bad_sum` 的注释后，编译器没有报语法错误——说明 Rust 里确实存在 `[i32]` 这个类型——而是以 `error[E0277]` 拒绝编译：

<small class="code-source">编译器输出摘要（取消 dst-sum.rs 中 bad_sum 注释后）</small>
```text
error[E0277]: the size for values of type `[i32]` cannot be known at compilation time
 --> types/slices/src/bin/dst-sum.rs:3:17
  |
3 | fn bad_sum(arr: [i32]) -> i32 {
  |                 ^^^^^ doesn't have a size known at compile-time
  |
  = help: the trait `Sized` is not implemented for `[i32]`
```

这条报错区分了两个紧密相连的概念：

1. **切片类型 `[T]`（Slice Type）**：在 Rust 类型系统中，真正名为切片类型的是不带 `&` 的 **`[T]`** 本体（`[-]` 是类型构造器，填入 `i32` 生成具体类型 `[i32]`）。它描述内存中任意一段紧密相邻的同类型元素序列，记录了元素类型与对齐，唯独将「共有多少个元素」留白；
2. **动态大小类型（Dynamically Sized Type，DST）**：如[栈与堆](/memory/stack-and-heap/)所述，栈帧中每个参数和局部变量的字节大小必须在编译期算定。抹去 `; N` 后，`[i32]` 可能是 12 字节也可能是 4000 字节，编译器无法为 `arr` 留出固定大小的栈槽位。这类编译期大小未知的类型统称为 **DST**（报错提示未实现 `Sized`），不能直接按值放入栈变量或函数参数，必须套上外层指针构造器（如 `&` 或 `&mut`）组成两层嵌套的 **`&[i32]`** 或 **`&mut [i32]`**。

## 切片胖指针：地址与长度存在哪里

接着回答第二个问题：参数 `&[i32]` 擦掉了编译期长度 `; N`，而栈上的数组 `a4`、`a3` 在运行时也没有对象头记录长度——顺着[类型的两面](/types/representation-and-constraints/)中的信息守恒原则，**编译期类型信息里省掉的元素长度，必须补回运行时的切片引用中。**

运行下面这段程序，在 64 位平台上实测指向同一个数组的 `&[i32; 4]` 与 `&[i32]` 各自占用的字节数：

<small class="code-source">源文件：<code>examples/types/slices/src/bin/fat-pointer-size.rs</code></small>
<Code code={fatPointerSize} lang="rust" />

<small class="code-source">运行输出（64 位平台）</small>
```text
r1 (&[i32; 4]): 8 bytes, first = 10
r2 (&[i32]):    16 bytes, len   = 2
```

两组字节数揭示了两种引用形态（以 64 位平台、1 个机器字占 8 字节为例）：

- **指向编译期定长类型的引用 `&[i32; 4]`（8 字节瘦指针 Thin Pointer）**：长度 `4` 已保存在编译期类型中，运行时变量 `r1` 只存 **1 个机器字（起始地址 `ptr`）**；
- **指向切片的引用 `&[i32]`（16 字节胖指针 Fat Pointer）**：`[i32]` 抹去了编译期长度，运行时变量 `r2` 扩充为 **2 个机器字（16 字节）**，逻辑上同时保存**起始地址 `ptr`**（指向 `a[1]`）与**元素个数 `len`**（值为 `2`）。

<FatPointerCompare />

注意区分示意模型与语言保证：图中的 `(ptr, len)` 展示的是切片胖指针携带的两项信息，8 / 16 字节对应 64 位目标平台（32 位平台为 4 / 8 字节），且 Rust 不将胖指针内部字段的排列顺序作为 ABI 语言保证；此外，不同种类的动态大小类型引用会携带各自所需的运行时元数据，并非都存放元素长度（例如后续[`dyn Trait` 与 `vtable`](/abstraction/dyn-trait-and-vtable/)中指向动态契约的胖指针，第 2 个机器字存放的是虚表指针）。

<span class="rr-keypoint">对切片 `[T]` 而言，引用构造器 `&` 将编译期抹去的长度补进了运行时的胖指针里。</span>调用 `sum(&a4[1..3])` 时，程序只需将起始地址偏移到 `a[1]`、将长度记为 `2`，即可零复制切出局部片段。

## 连续内存的通用视图与 `[T]` 文档导读

`&[T]` 只关心起始地址与元素个数，不关心目标序列存放在栈帧、堆内存还是静态数据段。因此，`[T]` 的适用范围超出了栈数组：

<small class="code-source">源文件：<code>examples/types/slices/src/bin/slice-universal.rs</code></small>
<Code code={sliceUniversal} lang="rust" />

<small class="code-source">运行输出</small>
```text

from array[1..]:50
from Vec:       600
from Vec[..2]:  300
```

同一个 `sum(slice: &[i32])` 既能接收栈上定长数组 `&stack_arr`，也能接收堆上动态数组 `&heap_vec` 及其子区间。在工程签名设计中，**只要函数只需读取或原地修改一段连续序列，参数就应写成 `&[T]`（或 `&mut [T]`），而不写 `&[T; N]` 或 `&Vec<T>`。**

<Aside type="note" title="为什么 &[i32; 4] 和 &Vec<i32> 能直接传给 &[i32]？">
`&stack_arr`（`&[i32; 4]`）与 `&heap_vec`（`&Vec<i32>`）能直接传给 `&[i32]` 参数，源于两项编译期自动转换：定长数组引用 `&[T; N]` 通过编译器内置的**去定长转换（Unsize Coercion）**补齐长度转为 `&[T]`；动态数组引用 `&Vec<T>` 则通过标准库 `Deref` Trait 触发 **`Deref Coercion`**（国内常译为解引用强制转换或解引用强制多态）提取堆缓冲区地址与长度转为 `&[T]`，完整规则将在[Deref Coercion、方法解析链与接口设计边界](/pointers/deref-coercion/)中拆解。
</Aside>

查阅标准库的 [Primitive Type `slice`（`[T]`）文档](https://doc.rust-lang.org/std/primitive.slice.html) 时，把握两条规律即可读懂连续容器的绝大多数 API：

1. **通用方法统一挂载在 `impl<T> [T]` 下**：无论手头持有 `[T; N]`、`Vec<T>` 还是 `&[T]` / `&mut [T]`，通过点号 `.` 调用方法时编译器都会自动解引用到 `[T]` 上查找，二分查找 `binary_search`、滑动窗口 `windows`、分块 `chunks` 等方法均集中于此；
2. **从首参数区分访问权限，不把 `&mut self` 等同于零分配**：首参数为 `&self` 的方法（如 `len`、`is_empty`、`contains`）只需只读切片 `&[T]`；首参数为 `&mut self` 的方法（如 `reverse`、`sort_unstable`、`sort`）需要可变切片 `&mut [T]`，表示直接改写调用方的切片槽位而非返回新容器——但 **`&mut self` 只说明需要可变访问权限，不保证内部一定不分配辅助内存**（例如 `reverse` 与非稳定排序 `sort_unstable` 不分配堆内存，而保持相等元素顺序的稳定排序 `sort` 在运行时可能分配临时辅助缓冲区）。

<Aside type="note" title="没有类继承，为什么不同容器能共享同一套方法？">
面向对象语言常依赖父类继承复用集合方法（Java 中原始数组 `int[]` 未纳入集合继承树，排序便分裂为 `Arrays.sort` 与 `Collections.sort`）。Rust 则将「存储管理」（`[T; N]`、`Vec<T>`）与「连续内存操作」（`[T]`）解耦：只要外层容器物理上持有一段连续排布的 `[T]`，把通用算法在 `[T]` 上实现一次，所有连续载体及局部子切片 `&mut nums[1..4]` 即可零虚表开销共享整套方法（普通业务类型之间的行为抽象则使用 Trait 契约，跨语言对照见附录「[没有 `class` 的对象感](/appendix/comparisons/oop/)」）。
</Aside>

## 小结与动手核对

1. **切片引用 `&[T]` 支持跨长度与子区间借用**：范围语法默认采用左闭右开 `start..end`；
2. **切片本体 `[T]` 是动态大小类型（DST）**：编译期大小未知，不能直接按值放入栈槽位（报 `E0277`），套上 `&` 后在 64 位平台下构成携带地址与长度的 **16 字节胖指针**；
3. **统领连续内存视图**：栈数组 `[T; N]` 与堆动态数组 `Vec<T>` 均可借用为 `&[T]`，共享 `[T]` 上的标准库方法。

### 动手核对

在 `slice-methods.rs` 中，执行 `let m: &mut [i32] = &mut nums[1..4]; m.reverse();` 后，为什么只有后三个元素 `[10, 30, 20]` 反转为 `[20, 30, 10]`，而 `nums[0]` 的 `40` 保持原样？

核对结果：`&mut nums[1..4]` 构造的切片胖指针 `m` 中，起始地址指向 `nums[1]`，元素长度为 `3`。`m.reverse()` 只在从 `nums[1]` 起的 3 个连续槽位内部原地交换元素，`nums[0]` 不在该切片覆盖的范围内。

切片 `&[T]` 解决了通用借用问题，但它自身不拥有数据。当工程中需要一个在运行时动态增删元素、且独自承担释放责任的连续序列时，下一节拆解动态数组 `Vec<T>`。
