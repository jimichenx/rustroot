
这条报错同时引出了两个核心概念：

1. **切片类型 `[T]`（Slice Type）**：日常交流常把带 `&` 的 `&[T]` 简称为切片，但在 Rust 类型系统中，真正名为切片类型的是不带 `&` 的 **`[T]`** 本体（`[-]` 是类型构造器，填入 `i32` 生成具体类型 `[i32]`）。它描述内存中任意一段紧密相邻、无空隙的同类型元素序列——无论位于栈帧、堆缓冲区还是静态只读段——记录了元素类型与对齐，唯独将「共有多少个元素」留白。
2. **动态大小类型（Dynamically Sized Type，DST）**：如[栈与堆](/memory/stack-and-heap/)所述，栈帧中每个参数和局部变量的字节大小必须在编译期算定。抹去 `; 4` 后，传入的 `[i32]` 可能是 12 字节也可能是 4000 字节，编译器无法为 `arr` 分配固定大小的栈槽位。这类因抹去编译期尺寸信息而无法算出字节大小的类型统称为 **DST**（报错提示未实现 `Sized`），不能直接按值放入栈变量或函数参数。

### `&` 与 `[T]` 嵌套组合

目标序列 `[i32]` 本身大小不定，但指向它的引用大小在编译期是固定的。用引用构造器 `&`（或 `&mut`）包裹 `[i32]`，即可合成出具体类型 **`&[i32]`**（**切片引用**，日常亦简称为**切片**）。

注意这里的合成层级：Rust 没有单独定义名为 `&[T]` 的构造器，它是外层引用构造器 `&` 与内层切片构造器 `[T]` 的两层组合。将参数改为 `arr: &[i32]` 后，求和函数即可同时接纳不同长度的数组及子区间（代码中 `for r in arr` 依次取出切片内每个元素的引用 `r: &i32`，再用 `*r` 解引用累加）：

## 16 字节胖指针与范围语法

顺着[类型的两面](/types/representation-and-constraints/)中的信息守恒原则，参数类型 `&[i32]` 擦掉了编译期长度 `; N`，而栈上的数组 `a4`、`a3` 在运行时也没有对象头记录长度——**编译期类型信息里省掉的长度，必须补回运行时的引用变量中。**

<small class="code-source">源文件：<code>examples/types/slices/src/bin/fat-pointer-size.rs</code></small>
<Code code={fatPointerSize} lang="rust" />

运行输出：

<small class="code-source">运行输出</small>
```text
r1 (&[i32; 4]): 8 bytes, first = 10
r2 (&[i32]):    16 bytes, len   = 2
```

两组字节数揭示了两种指针形态：

- **指向定长类型的引用 `&[i32; 4]`（8 字节瘦指针 Thin Pointer）**：长度 `4` 已保存在编译期类型中，运行时变量 `r1` 只存 **1 个机器字（8 字节起始地址 `ptr`）**；
- **指向动态大小类型的引用 `&[i32]`（16 字节胖指针 Fat Pointer）**：`[i32]` 抹去了编译期长度，运行时变量 `r2` 扩充为 **2 个机器字（16 字节）**——第 1 个 8 字节 `ptr` 保存起始地址（指向 `a[1]`），第 2 个 8 字节 `len` 保存元素个数（值为 `2`）。

<FatPointerCompare />

<span class="rr-keypoint">同一个引用构造器 `&`，根据填入参数 `T` 是编译期定长还是动态大小，合成出的具体类型在运行时分别表现为 8 字节瘦指针或 16 字节胖指针。</span>传入 `sum(&a4[1..3])` 时，编译器只需将地址偏移到 `a[1]`、将长度填为 `2`，即可在不复制数组元素的前提下切出局部片段。

截取数组、`Vec<T>` 或字符串子切片时，方括号内的**范围表达式（Range）**默认采用「左闭右开」规则（以长度为 `4` 的数组 `a` 为例）：

| 写法 | 含义 | 覆盖下标 | 胖指针 `(ptr, len)` |
| --- | --- | --- | --- |
| **`&a[1..3]`** | **左闭右开**：从下标 `1` 开始，到 `3` 之前结束（不含 `3`） | `a[1], a[2]` | `(&a[1], 2)` |
| **`&a[..3]`** | 省略起点：从下标 `0` 开始（等价于 `&a[0..3]`） | `a[0]..a[2]` | `(&a[0], 3)` |
| **`&a[1..]`** | 省略终点：从下标 `1` 切到末尾（等价于 `&a[1..4]`） | `a[1]..a[3]` | `(&a[1], 3)` |
| **`&a[..]`** | 首尾全省：切取全部元素（等价于 `&a[0..4]`） | `a[0]..a[3]` | `(&a[0], 4)` |
| **`&a[1..=3]`** | **全闭区间**：包含末尾下标 `3` | `a[1]..a[3]` | `(&a[1], 3)` |

默认采用左闭右开 `start..end` 有两个工程好处：切片长度直接等于 `end - start`，且相邻两段 `&a[0..2]` 与 `&a[2..4]` 的分界数字自然衔接，无需手写易错的 `+ 1` 或 `- 1`。

`&[T]` 胖指针内部只记录起始地址 `ptr` 与元素个数 `len`，并不关心目标序列存放在栈帧、堆内存还是静态数据段。因此，`[T]` 的适用范围超出了栈数组：


同一个 `sum(slice: &[i32])` 既能接收栈上定长数组 `&stack_arr`，也能接收堆上动态数组 `&heap_vec` 及其子区间。在工程签名设计中，**只要函数只需读取或原地修改一段连续序列，参数就应写成 `&[T]`（或 `&mut [T]`），而不写 `&[T; N]` 或 `&Vec<T>`。**

<Aside type="note" title="为什么 &[i32; 4] 和 &Vec<i32> 能直接传给 &[i32]？">
`&stack_arr` 的类型是 `&[i32; 4]`，`&heap_vec` 的类型是 `&Vec<i32>`，之所以能直接传给 `&[i32]` 参数而不报类型不匹配，源于两项编译期自动转换：定长数组引用 `&[T; N]` 通过编译器内置的**去定长转换（Unsize Coercion）**补齐长度转为 `&[T]`；动态数组引用 `&Vec<T>` 则通过标准库 `Deref` Trait 触发 **`Deref Coercion`**（国内常译为解引用强制转换或解引用强制多态）提取出堆缓冲区地址与长度转为 `&[T]`。完整触发规则将在[Deref Coercion、方法解析链与接口设计边界](/pointers/deref-coercion/)中拆解。
</Aside>

查阅标准库的 [Primitive Type `slice`（`[T]`）文档](https://doc.rust-lang.org/std/primitive.slice.html) 时，把握两条规律即可读懂绝大多数连续容器 API：

1. **通用方法统一挂载在 `impl<T> [T]` 下**：无论手头持有 `[T; N]`、`Vec<T>` 还是 `&[T]` / `&mut [T]`，通过点号 `.` 调用方法时编译器都会自动解引用到 `[T]` 上查找，二分查找 `binary_search`、滑动窗口 `windows`、分块 `chunks` 等方法均集中于此；
2. **从首个参数区分只读与原地修改**：签名首参数为 `&self` 的方法（如 `len`、`is_empty`、`contains`）只需只读切片 `&[T]`，其中 `len()` 直接读取胖指针的第 2 个机器字；首参数为 `&mut self` 的方法（如 `reverse`、`sort`）需要可变切片 `&mut [T]`，直接在原内存槽位交换元素，不产生额外堆分配。

<Aside type="note" title="没有类继承，为什么不同容器能共享同一套方法？">
习惯了面向对象（OOP）语言的开发者，常默认「跨类型复用方法必须靠 `extends` 父类继承」。但在 Java 中，即便 `ArrayList` 继承了 `AbstractList`，原始数组 `int[]` 仍游离在类继承树之外，导致排序等基础操作分裂为 `Arrays.sort` 与 `Collections.sort` 两套接口，且继承树常伴随堆对象头与虚表分派成本。

Rust 给出了另一种解耦思路：`sort`、`reverse`、`binary_search` 等算法真正依赖的物理前提，仅仅是**「一段连续排布的内存 `(ptr, len)`」**，与这块内存位于栈还是堆、归谁释放、能否扩容无关。标准库将「怎么管理存储」（`[T; N]`、`Vec<T>`）与「怎么操作连续序列」（`[T]`）拆开——把通用算法集中在底层物理形态 `[T]` 上实现一次，所有连续内存载体乃至局部子切片 `&mut nums[1..4]` 即可零虚表开销地共享整套能力。

注意这种复用建立在「外层容器物理上持有一段连续 `[T]`」的前提之上；在普通业务结构体之间共享抽象行为时，Rust 不使用自动解引用模拟继承，而是通过结构体组合与 Trait 契约完成（跨语言对照可参阅附录「[没有 `class` 的对象感](/appendix/comparisons/oop/)」）。
</Aside>

## 小结与动手核对

1. **抹去 `; N` 得到动态大小类型 `[T]`**：编译期大小未知，不能直接按值放入栈槽位（报 `E0277`）；
2. **嵌套 `&` 产出 16 字节胖指针 `(ptr, len)`**：编译期省掉的长度移入运行时指针中；
3. **统领连续内存借用视图**：栈数组 `[T; N]` 与堆动态数组 `Vec<T>` 均可借用为 `&[T]`，共享 `[T]` 上的标准库方法。

### 动手核对

在 `slice-methods.rs` 中，执行 `let m: &mut [i32] = &mut nums[1..4]; m.reverse();` 后，为什么只有后三个元素 `[10, 30, 20]` 反转为 `[20, 30, 10]`，而 `nums[0]` 的 `40` 保持原样？

核对结果：`&mut nums[1..4]` 构造的 16 字节胖指针 `m` 中，起始地址 `ptr` 指向 `nums[1]`，长度 `len` 为 `3`。`m.reverse()` 只在从 `ptr` 起的 3 个连续槽位内部原地交换元素，`nums[0]` 不在该胖指针覆盖的区间内。

切片 `&[T]` 解决了通用借用问题，但它自身不拥有数据。当工程中需要一个在运行时动态增删元素、且独自承担释放责任的连续序列时，下一节拆解动态数组 `Vec<T>`。
