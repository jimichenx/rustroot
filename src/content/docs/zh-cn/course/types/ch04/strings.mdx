从 Java、Python 或 Go 转向 Rust 时，围绕字符串最先遇到的通常是三个疑问：为什么其他语言只有一个 `String`，Rust 里却同时出现 **`String`**、**`&String`**、**`str`** 与 **`&str`** 四种写法？为什么双引号字面量 `"hello"` 的类型是 `&str` 而不是 `String`？为什么连按下标取首字符 `s[0]` 都会被编译器拒绝？

把前两节建立的连续内存三成员——动态大小类型 `[T]`、16 字节胖指针 `&[T]` 与 24 字节动态数组 `Vec<T>`——直接映射过来，这三个疑问就能一次解开。

## 加了 UTF-8 约束的字节序列

在底层表示上，`String` 内部直接封装了一个字节动态数组 `Vec<u8>`，区别在于**多了一条类型级安全约束：内部的字节序列在任何时刻都必须是合法的 UTF-8 编码。**

给 `[u8]`、`&[u8]`、`Vec<u8]` 与 `&Vec<u8>` 统一加上这条合法 UTF-8 约束，字符串的四种写法便一一对位：

| 通用字节序列 | 叠加合法 UTF-8 约束后的类型 | 栈上物理表示（64 位） | 职责定位 |
| --- | --- | --- | --- |
| **`[u8]`** | **`str`** | 编译期大小未知（**DST**，不可直接上栈） | **字符串切片本体**：内存中任意一段连续的合法 UTF-8 字节 |
| **`&[u8]`** | **`&str`** | **16 字节胖指针** `(ptr, len)` | **字符串切片引用**（日常简称字符串切片）：不复制字节的只读视图 |
| **`Vec<u8>`** | **`String`** | **24 字节控制头** `(ptr, len, cap)` | **拥有所有权的堆字符串**：负责释放堆缓冲区，支持动态追加与扩容 |
| **`&Vec<u8>`** | **`&String`** | **8 字节瘦指针** `ptr` | 指向栈上 `String` 控制头的普通只读引用 |

不带 `&` 的 **`str`** 对应 `[u8]`，属于动态大小类型，不能直接声明 `let s: str`；日常高频使用的 **`&str`** 则是用 `&` 包裹 `str` 合成出的 **16 字节胖指针 `(ptr, len)`**。

### 为什么字面量 `"hello"` 的类型是 `&str`

写下 `let literal = "hello rust";` 时，这 10 个 ASCII 字节在编译期已直接写入可执行文件的**只读数据段（Read-Only Data Segment）**。程序运行时无需去堆上分配内存，只需在栈上放一个 16 字节胖指针 `&str`（`ptr` 指向只读数据段起始地址，`len` 为 `10`）。由于只读数据段从程序启动一直存续到退出，字符串字面量的完整类型记作 **`&'static str`**（`'static` 是编译器内置的全局有效区间名，详见[编译器的幕后逻辑：范围包含关系与 `'static`](/pointers/lifetime-variance-and-static/)）。

## UTF-8 变长编码：为什么禁止 `s[0]`

运行下面这段包含中英文混合文本的程序：

<small class="code-source">源文件：<code>examples/types/slices/src/bin/utf8-indexing.rs</code></small>
<Code code={utf8Indexing} lang="rust" />

运行输出：

<small class="code-source">运行输出</small>
```text
byte length (.len()): 10
char count (.chars()): 6
slices: Rust | 语言
chars: [R] [u] [s] [t] [语] [言] 
```

取消 `// let first = s[0];` 的注释后，编译器以 `error[E0277]` 拒绝整数下标访问：

<small class="code-source">编译器输出摘要（取消 utf8-indexing.rs 中 let first = s[0]; 的注释后）</small>
```text
error[E0277]: the type `str` cannot be indexed by `{integer}`
 --> src/bin/utf8-indexing.rs:7:19
  |
7 |     let first = s[0];
  |                   ^ string indices are ranges of `usize`
  |
  = help: the trait `SliceIndex<str>` is not implemented for `{integer}`
```

结合输出中的 `byte length: 10` 与 `char count: 6`，就能看清封禁 `s[i]` 的物理原因：

1. **`.len()` 返回字节数而非字符数**：UTF-8 是变长编码——英文 ASCII 字符占 **1 字节**（4 个字母共 4 字节），常用汉字占 **3 字节**（2 个汉字共 6 字节），Emoji（如 `'🦀'`）占 **4 字节**。胖指针与控制头里的 `len` 记录的是底层总字节数 `10`。
2. **消除语义歧义与隐藏的 `O(N)` 扫描成本**：若允许写 `s[4]`，既不清楚要取的是第 4 个原始字节（仅是汉字 `'语'` 的首字节残片）还是第 4 个字符，又违背了下标运算应当在常数时间 `O(1)` 完成的性能预期——在变长编码中定位第 `i` 个字符，CPU 必须从首字节起按 `O(N)` 逐个解码扫描。因此 Rust 要求显式表明意图：按 Unicode 标量值（`char`）遍历调 **`s.chars()`**，按原始字节（`u8`）访问调 **`s.as_bytes()`**。

<small class="code-source">运行输出（取消 utf8-boundary.rs 末行注释后）</small>

如果放行 `&s[0..1]`，就会造出包含残缺字节的非法 `&str`，直接击穿 `str` 的合法 UTF-8 约束。<span class="rr-keypoint">审查线上业务或 AI 生成的代码时，凡是对外部输入字符串硬写 `&input[0..10]` 的切片操作都应拦截——只要第 10 个字节落在中文字符或 Emoji 内部就会当场崩溃，应改用 `input.get(0..10)` 安全返回 `Option<&str>`。</span>

## 工程选型：何时用 `&str`，何时用 `String`

| 工程场景 | 选型判据 | 底层依据 |
| --- | --- | --- |
| **1. 函数参数（只读）** | **写 `fn process(s: &str)`**（不写 `&String`） | `&str` 既能直接接收字面量与子串切片，也能经 `Deref Coercion` 零分配接收 `&String` |
| **2. 函数参数（需接手所有权）** | **写 `fn take(s: String)`** | 函数内部需将文本存入结构体或跨线程移交时按值接收，把是否需要复制分配的决定权留给调用方 |
| **3. 函数返回值** | **新拼装的文本返回 `String`；截取自输入参数的子串返回 `&str`** | 函数内新生成的堆缓冲区须移交释放责任给调用方；从输入 `&str` 切出的子串直接返回胖指针即可 |
| **4. 结构体字段** | **常规业务实体默认用 `String`** | 让结构体独自持有堆文本所有权，可自由移动与长期存续，避免给整个结构体附加外部借用区间约束 |

## 小结与代码审查核对

1. **物理同构**：`str`、**`&str`（16 字节）**、**`String`（24 字节）**分别对应叠加了合法 UTF-8 约束的 `[u8]`、`&[u8]` 与 `Vec<u8>`；字面量存放在只读数据段，类型为 `&'static str`；
2. **UTF-8 边界**：`.len()` 返回字节数；禁止整数下标 `s[i]`（报 `E0277`），不确定字符边界或长度时使用 `s.get(a..b)` 替代 `&s[a..b]`；
3. **签名裁决**：只读参数用 `&str`，需独立持有所有权的字段与返回值用 `String`。

### 动手核对：审查并重构日志提取函数

需求：从一组日志中找出所有以 `"[ERROR] "`（8 个 ASCII 字节）开头的行，去掉前缀后返回剩余错误消息，且调用方在调用后仍需继续使用原日志列表。请审查下面这段问题代码：

```rust
fn extract_errors(logs: &Vec<String>) -> Vec<String> {
    let mut result: Vec<String> = Vec::new();
    for i in 0..logs.len() {
        let line: String = logs[i];        // 问题 A
        if &line[0..8] == "[ERROR] " {     // 问题 B
            result.push(line[8..].to_string());
        }
    }
    result
}
```

1. **问题 A** 会报什么编译错误？即便将问题 A 改为借用 `&logs[i]`，**问题 B** 遇到哪两类输入会触发运行时 `panic`？
2. 若要求**不复制任何字符串内容**（仅返回指向原日志子串的胖指针），函数签名与实现应如何重写？

<details>
<summary>点击核对参考答案与重构实现</summary>

1. **错误与崩溃原因**：
   - **问题 A**：触发 `error[E0507]: cannot move out of index of Vec<String>`，不能通过下标从 `&Vec<String>` 中移走未实现 `Copy` 的 `String`。
   - **问题 B**：① 某行日志不足 8 个字节（如空行 `""`）时触发越界 `panic`；② 某行包含多字节字符且第 8 个字节恰好落在汉字或 Emoji 中间（如 `"警告：连接超时"`，前两个汉字加全角冒号共 9 字节，索引 8 落在 `'：'` 内部）时触发非字符边界 `panic`。
2. **不复制文本字节的重构实现**（参数拓宽为 `&[String]`，返回 `Vec<&str>`，用 `get` 或 `strip_prefix` 安全切分）：
   ```rust
   fn extract_errors(logs: &[String]) -> Vec<&str> {
       let mut result: Vec<&str> = Vec::new();
       for line in logs {
           if line.get(0..8) == Some("[ERROR] ") {
               if let Some(msg) = line.get(8..) {
                   result.push(msg);
               }
           }
           // 工程中也可直接写：if let Some(msg) = line.strip_prefix("[ERROR] ") { result.push(msg); }
       }
       result
   }
   ```

</details>
