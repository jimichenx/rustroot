前两节拆解了连续内存的两类载体：定长数组 `[T; N]` 内联在栈帧、独自承担释放责任，但长度 `N` 在编译期固定；切片引用 `&[T]` 用 16 字节胖指针 `(ptr, len)` 借用任意长度的连续序列，但自身不持有数据。

当工程中既需要**独自持有所有权**，又需要**在运行时动态决定长度、随时增删元素**（对应 Java 的 `ArrayList<T>`、Python 的 `list`、C++ 的 `std::vector<T>`）时，就轮到标准库类型构造器——**动态数组 `Vec<T>`** 登场了。

## 创建 `Vec<T>` 的三种常见写法

刚从 Python 或 JavaScript 转向 Rust 时，常会把方括号 `[10, 20, 30]` 误认为动态列表。在进入内存布局前，先把 `Vec<T>` 的三种创建写法与定长数组区分清楚：

1. **用 `vec!` 宏初始化**：
   - 逐个列出元素：`let v = vec![10, 20, 30];`
   - 重复初始化：`let zeros = vec![0; 4];`（在堆上连续排开 4 个 `0`）
   - 注意区分：不带 `vec!` 的 `[10, 20, 30]` 是栈上定长数组 `[i32; 3]`；带上 `vec!` 的 `vec![10, 20, 30]` 才是管理堆缓冲区的 `Vec<i32>`。
2. **用 `Vec::new()` 创建空动态数组**：
   - 写法：`let mut v: Vec<i32> = Vec::new();`。若后续紧接着写了 `v.push(10)`，编译器可顺着 `10` 推断出 `Vec<i32>`；若尚未推入元素，则必须显式写出类型标注 `: Vec<i32>` 填满类型参数 `T`。
3. **用 `Vec::with_capacity(n)` 预留堆容量**：
   - 写法：`let mut v = Vec::with_capacity(10);`（预先在堆上留出至少容纳 10 个元素的空间，此时有效长度 `len` 仍为 `0`）。

## 24 字节控制头与扩容过程

由于元素个数在编译期未知且需支持动态增长，`Vec<T>` 将元素存放在按需扩展的堆缓冲区中。以 64 位平台上的局部变量 `Vec<i32>` 为例，栈上保存 **24 字节控制头**（下表按职责说明三项信息，不锁定标准库内部字段排列顺序；空 `Vec` 或零大小元素的 `Vec` 未必实际分配堆内存）：

| 控制头信息 | 大小（64 位） | 物理职责 |
| --- | --- | --- |
| **`ptr`** | 8 字节 | 指向堆上连续元素缓冲区的起始地址 |
| **`len`** | 8 字节（`usize`） | **当前有效长度**：缓冲区内已初始化、正在使用的元素个数 |
| **`cap`** | 8 字节（`usize`） | **缓冲区总容量（Capacity）**：当前堆块在不重新分配的前提下最多容纳的元素个数 |

为什么除了 `len` 还要单独记录 `cap`？如果每次 `push` 都刚好按新长度重新申请堆内存，连续追加元素就会频繁触发分配与搬迁。预留容量将追加操作分成了两种情况：

- 当 **`len < cap`** 时：`push` 直接把新元素写入第 `len` 号槽位并将 `len` 加 `1`，零堆分配；
- 当 **`len == cap`** 时：缓冲区已满，继续 `push` 触发扩容——分配器可能原地扩大当前堆块，也可能另开一块更大的新堆缓冲区，将已有元素按位复制过去并**释放旧堆块**。

## `Vec<T>` 的两条编译期安全防线

看清堆缓冲区的扩容搬迁与连续初始化要求后，日常操作 `Vec<T>` 时最常遇到的两条编译拦截便可以直接推出。

<Code code={vecSafetyRules} lang="rust" anchor="push_while_borrowed" />

取消 `// scores.push(40);` 的注释后，编译器报出与[引用与可变引用](/types/reference-constructors/)同源的读写借用冲突：

<small class="code-source">编译器输出摘要（取消 vec-safety-rules.rs 中 scores.push(40); 的注释后）</small>
```text
error[E0502]: cannot borrow `scores` as mutable because it is also borrowed as immutable
 --> src/bin/vec-safety-rules.rs:7:5
  |
6 |     let first_ref = &scores[0];
  |                      ------ immutable borrow occurs here
7 |     scores.push(40);
  |     ^^^^^^^^^^^^^^^ mutable borrow occurs here
8 |     println!("first score: {first_ref}");
  |                            ----------- immutable borrow later used here
```

把扩容过程代入即可核对：`first_ref` 保存着 `scores` 当前堆缓冲区第 0 号槽位的地址；紧接着调用的 `scores.push(40)` 需要可变借用 `&mut scores`，一旦触发扩容搬迁并释放旧堆块，后续读取 `first_ref` 就会落入已释放内存。编译器不赌运行期某次 `push` 是否真的触发搬迁，只要签名上读写有效区间重叠，一律在编译期拦截。

### 2. 禁止按下标移出非 `Copy` 元素（`E0507`）

再看尝试按下标直接取走 `Vec<String>` 中某个元素的场景：

<Code code={vecSafetyRules} lang="rust" anchor="move_out_of_index" />

取消 `// let stolen = names[0];` 的注释后，编译器报出 `error[E0507]`：

<small class="code-source">编译器输出摘要（取消 vec-safety-rules.rs 中 let stolen = names[0]; 的注释后）</small>
```text
error[E0507]: cannot move out of index of `Vec<String>`
  --> src/bin/vec-safety-rules.rs:14:18
   |
14 |     let stolen = names[0];
   |                  ^^^^^^^^ move occurs because value has type `String`, which does not implement the `Copy` trait
   |
help: consider borrowing here: `&names[0]`
```

原因与[数组](/types/arrays/)中的 `E0508` 一致：`Vec<T>` 保证堆缓冲区 `0..len` 范围内的每个槽位都处于有效初始化状态，以便离开作用域时逐一释放；若允许 `names[0]` 直接移走单个 `String`，就会在连续有效区间内留下未初始化的失效空位。

在工程中访问或移出 `Vec<T>` 元素应按意图选用对应方法：

1. **只读借用（不接手所有权）**：`&names[i]` 直接按下标借用，但 `i >= len` 时会当场触发运行时 `panic`；处理外部输入索引时优先用 **`names.get(i)`**，安全返回 `Option<&T>`（越界返回 `None`）。
2. **移出所有权（同步缩减 `len` 填平空位）**：
   - **`names.pop()`**：移出并返回末尾元素 `Option<T>`，`len` 减 `1`（时间复杂度 `O(1)`）；
   - **`names.remove(i)`**：移出第 `i` 个元素 `T`，将后方所有元素向前平移一格填补空位（`O(N)`）；
   - **`names.swap_remove(i)`**：不要求保持剩余元素顺序时，用末尾元素换入第 `i` 格填补空位（`O(1)`）。

## 连续内存三类载体的选型判据

至此，Rust 处理通用连续内存的三个核心类型——`[T; N]`、`Vec<T>` 与 `&[T]`——已经全部到齐。栈上的 `[T; N]`（经去定长转换）与堆上的 `Vec<T>`（经 `Deref Coercion`）在借用时均可零分配转为通用切片 `&[T]` / `&mut [T]`，并通过自动解引用直接调用上一节 `[T]` 文档中的全部方法。

定义数据结构、设计函数签名或审查 AI 生成的代码时，可按以下判据裁决：

| 对比维度 | 定长数组 `[T; N]` | 动态数组 `Vec<T>` | 切片引用 `&[T]` / `&mut [T]` |
| --- | --- | --- | --- |
| **元素存储位置** | 直接内联在数组值中 | 按需存放在堆缓冲区，`Vec` 持有控制头 | 不持有数据，借用栈、堆或静态区连续内存 |
| **栈上大小（64 位）** | `N × size_of::<T>()` | **24 字节** `(ptr, len, cap)` | **16 字节** `(ptr, len)` |
| **长度确定时机** | **编译期**固定在类型中 | **运行时**动态增删、按需扩容 | **运行时**切取决定，视图自身不可扩容 |
| **工程选型场景** | 元素个数在编译期固定且体积较小（如 RGB 颜色 `[u8; 3]`、固定尺寸矩阵） | 运行时才知个数、需动态增删，或放在结构体字段中长期持有所有权 | **只读或原地修改连续元素的函数参数**（写 `fn f(data: &[T])`，不写 `&Vec<T>`） |

## 小结与动手核对

1. **24 字节控制头与扩容**：`Vec<T>` 记录 `(ptr, len, cap)` 管理堆缓冲区，`len == cap` 时继续 `push` 触发扩容；已知规模可用 `Vec::with_capacity(n)` 预留空间；
2. **两条编译期安全防线**：持有元素引用 `&v[i]` 期间禁止 `v.push()`（`E0502`，防扩容悬垂）；禁止用 `let x = v[i];` 直接移出非 `Copy` 元素（`E0507`，改用借用或 `pop` / `remove` / `swap_remove`）；
3. **三类载体分工**：固定小数据内联用 `[T; N]`，动态持有上堆用 `Vec<T>`，函数借用传参用 `&[T]`。

### 动手核对

审查一段外部输入统计代码时，看到函数签名写为 `fn average(nums: &Vec<f64>) -> f64`，且函数首行直接写了 `let first = nums[0];`。请指出这两处写法的问题并给出修改方案。

核对结果：① 参数写成 `&Vec<f64>` 既多了一次从栈引用到堆缓冲区的间接寻址，又将栈数组 `[f64; N]` 与子切片挡在门外，应拓宽为 **`nums: &[f64]`**；② 外部传入的切片可能为空（`len == 0`），直接写 `nums[0]` 会在运行时触发越界 `panic`，应先判空或改用 **`nums.first()` / `nums.get(0)`** 安全处理。
