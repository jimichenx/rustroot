上一章建立了本篇的分析主轴：每个具体类型都由**类型构造器**填入编译期参数后生成，同时承载运行时的物理表示与编译期的行为及安全约束。

本章直接用这套构造器模型，按从基础引用到核心数据容器的顺序，拆解日常编码出镜率最高的一组复合类型：

- **第一段：共享引用与可变引用（`&T` 与 `&mut T`）。** 补齐[引用](/memory/references/)留下的「如何通过引用修改数据」缺口，看清 `&` 与 `&mut` 两个构造器如何在相同的 8 字节地址表示上，定出相反的 `Copy` 能力与**读写排他规则**。
- **第二段：连续内存序列的三类载体（`[T; N]`、`&[T]` 与 `Vec<T>`）。** 先看把编译期长度 `N` 编码进类型的定长数组 `[T; N]`；再顺着抹去 `; N` 的思路推导出动态大小类型 `[T]` 与 **16 字节胖指针 `&[T]`**；最后引入栈上 **24 字节控制头 `(ptr, len, cap)`** 管理堆缓冲区的动态数组 `Vec<T>`，从扩容搬迁推导出禁止借用悬垂与禁止下标移出的编译期防线。
- **第三段：UTF-8 字符串与双参数键值容器（`str` / `String` 与 `HashMap<K, V>`）。** 在字节序列 `[u8]`、`&[u8]`、`Vec<u8>` 之上叠加「合法 UTF-8 编码」约束，厘清字符串家族的内存归属与切片边界；随后从单参数序列走向双类型参数构造器 `HashMap<K, V>`，拆解键值插入的所有权交接与一次查找原地更新的 `Entry` 模式。

读完这一章，无论是编写业务代码还是审查 AI 生成的代码，你都应当能独立回答以下三个问题：

1. **物理形态与内存归属**：手里的变量在栈上是 8 字节瘦指针、16 字节胖指针 `(ptr, len)`、24 字节控制头 `(ptr, len, cap)`，还是内联平铺的连续元素？目标数据存放在栈帧、堆缓冲区，还是只读数据段？
2. **编译拦截与运行边界**：为什么持有容器内部元素引用（如 `&v[0]` 或 `map.get(k)`）期间不能调用 `push` 或 `insert`？为什么不能用 `v[0]` 移走单个 `String`？为什么字符串切片切在多字节字符中间会触发 `panic`？
3. **签名与容器选型**：设计函数参数、返回值与结构体字段时，如何在 `[T; N]`、`Vec<T>`、`&[T]` 以及 `String`、`&str` 之间选型？更新 `HashMap<K, V>` 时为什么优先使用 `entry(k).or_insert(...)`？
