上一章建立了本篇的分析主轴：每个具体类型都由**类型构造器**填入编译期参数后生成，同时承载运行时的物理表示与编译期的行为及安全约束。

本章从日常基础用法起步，用这套构造器模型依次拆解编码出镜率最高的一组引用与数据容器（本章示例中的内存尺寸均以 64 位平台为准，1 个机器字占 8 字节）：

- **第一段：共享引用与可变引用（`&T` 与 `&mut T`）。** 补齐[引用](/memory/references/)留下的「如何通过引用修改数据」缺口，从日常读写用法出发，看清 `&` 与 `&mut` 两个构造器如何生成两个独立的类型，在相同的 8 字节地址表示上定出相反的 `Copy` 能力与**读写排他规则**。
- **第二段：连续内存序列的三类载体（`[T; N]`、`&[T]` 与 `Vec<T>`）。** 先认识把编译期长度 `N` 编码进类型的定长数组 `[T; N]`；再通过截取与通用传参掌握切片引用 `&[T]`，从动态大小类型 `[T]` 推导出携带地址与长度的 **16 字节胖指针**；最后进入用 **24 字节控制头**管理堆缓冲区的动态数组 `Vec<T>`，从扩容机制看清禁止借用悬垂与禁止下标移出的编译期防线。
- **第三段：UTF-8 字符串与双参数键值容器（`str` / `String` 与 `HashMap<K, V>`）。** 在字节序列 `[u8]`、`&[u8]`、`Vec<u8>` 之上叠加「合法 UTF-8 编码」约束，厘清字符串家族的内存归属、文本三层粒度与切片边界；随后走向双类型参数构造器 `HashMap<K, V>`，拆解键值所有权交接、查询借用边界与原地更新的 `Entry` 模式。

读完这一章，无论是编写业务代码还是审查 AI 生成的代码，你都应当能独立回答以下三个问题：

1. **物理形态与内存归属**：在 64 位平台上，手里的变量在栈上是 8 字节瘦指针、16 字节切片胖指针、24 字节容器控制头，还是内联平铺的连续元素？目标数据存放在栈帧、堆缓冲区，还是只读数据段？
2. **编译拦截与运行边界**：为什么持有共享借用（如 `&s`、`&v[0]` 或 `map.get(k)`）期间不能调用需要排他访问的修改方法（如 `push` 或 `insert`）？为什么不能用 `v[0]` 移走单个 `String`？为什么字符串范围切片切在多字节字符内部会触发 `panic`？
3. **签名与容器选型**：设计函数参数、返回值与结构体字段时，如何在 `[T; N]`、`Vec<T>`、`&[T]` 以及 `String`、`&str` 之间选型？更新 `HashMap<K, V>` 时为什么优先使用 `entry(k).or_insert(...)`？
