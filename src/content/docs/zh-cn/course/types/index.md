title: 类型
description: 从值的物理表示与安全约束两面重塑类型认知，看清 Rust 如何通过类型构造器组装数据容器、结构体与枚举。
---

上一篇用真实代码验证了所有权、移动与借用。继续往后写 Rust，两个直接的困惑就会浮上来：同样写 `let t = s;`，为什么整数和只读引用 `&i32` 会复制，`String` 和可变引用 `&mut i32` 却会移动？在其他语言里用一个 `List` 或 `String` 就能表达的数据，到了 Rust 里为什么会分出 `[i32; 4]`、`&[i32]`、`Vec<i32>`、`&str`、`Option<&str>` 等多种写法？

习惯了面向对象语言的开发者，提到「类型」常会先想到 `int`、`float`、`boolean` 语法表，再往后就是 `class`。如果顺着这套旧习惯直接去学 Rust 的容器与结构体，往往会把各种类型签名当成孤立的语法碎片死记硬背。

因此这一篇不急着罗列整数和浮点数的语法表（基础标量语法已收拢在附录「[标量、元组与单元类型](/appendix/basics/scalars-and-tuples/)」供随时速查），而是分四步帮你把类型的底层坐标系重新立起来：

- **[一切皆类型](/types/constructors/)**：先退后一步搭起全景骨架——看清 Rust 如何把「物理表示 + 安全约束」装进编译期类型表，又如何用「类型构造器」按需组装出新类型；
- **[引用与数据容器](/types/references-and-slices/)**：顺着构造器视角，逐一拆开日常最高频的 `&T` / `&mut T`、数组、切片、`Vec<T>`、字符串与 `HashMap<K, V>`；
- **[函数与结构体](/types/custom-types/)**：掌握函数签名边界，亲手用 `struct` 定义自己的类型与方法接收者（`self` / `&self` / `&mut self`）；
- **[枚举、模式匹配与错误建模](/types/enums-and-matching/)**：用代数数据类型 `enum` 与穷尽匹配表达业务分支，看清 Rust 如何用普通库类型 `Option<T>` 与 `Result<T, E>` 替代空指针与异常。

本篇聚焦确定类型下的数据组织与安全边界；跨类型的泛型抽象与 Trait 契约、多所有者共享、并发及 `unsafe` 留到后续篇章展开。

读完这一篇，面对项目或 AI 生成代码里的复杂类型签名与数据结构，你不再需要靠试错或死记规则，而是能从内存布局、读写权限与释放责任上直接做出选型。
