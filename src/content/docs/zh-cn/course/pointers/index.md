走完前三篇，我们已经掌握了具体类型的内存布局、代数数据类型（`struct` 与 `enum`）、Trait 契约、动态分发胖指针以及迭代器与闭包。但在这段旅程中，我们有意留下了两处悬念：

1. 在物理内存里，引用 `&T`、`Box<T>`、`String`、`Vec<T>` 栈上存的明明都是内存地址，为什么有的叫「引用」、有的叫「智能指针」？为什么智能指针既能像普通引用一样直接用 `*` 解引用、在函数传参时自动转成 `&str` 与 `&[T]`，又能在离开作用域的那一刻自动释放堆内存？
2. 当一个引用不再局限于单个函数内部，而是作为函数的返回值跨出函数边界、或者被装进结构体字段长期持有时，借用检查器在不偷看函数体的前提下，靠什么证明它绝不悬垂？

这一篇分两章结清单一所有权体系下的全部智能指针与借用边界：

- **第 10 章（智能指针、`Box<T>`、解引用 `Deref` 与清理 `Drop`）**：先从广义物理指针概念出发，看清 Rust 如何将同一个 8 字节内存地址按编译期约束拆分为**引用、智能指针与裸指针**三大家族，并建立标准库智能指针的全局地图；随后立起最纯粹的堆独占智能指针 `Box<T>`，揭开控制解引用的两层体系（内建 `*` 锚点 vs `Deref` Trait 与跨类型强制转换 Deref Coercion），以及控制确定性清理的 `Drop` Trait。
- **第 11 章（借用边界与生命周期参数 `'a`）**：先潜入借用检查器的真实刻度（非词法生命周期 NLL 与 `&mut` 重借用），再还原引用构造器的双参数完整形态 `&'a T`，打通跨函数签名约束、生命周期省略规则、结构体 `<'a>` 参数穿透、字段借用拆分与 `'static` 的两份契约。

本篇依然坚守「单一所有者 + 编译期静态借用检查」的零运行时成本主干。多所有者共享计数（`Rc` / `Arc`）与运行时借用检查（`RefCell` / `Mutex`）留待第五篇展开。
