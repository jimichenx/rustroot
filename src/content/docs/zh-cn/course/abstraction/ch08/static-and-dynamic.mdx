上一章建立的泛型 `<T: Summary>` 在编译期按每个调用点传入的具体类型生成独立机器码：编译结束时，所有类型的栈尺寸与函数跳转地址均已确定，这类机制称为**静态分发（Static Dispatch）**。

当具体类型的选择无法在编译期定死、必须等到程序运行期根据外部输入或混合列表决定时，静态单态化就会遇到两道明确的物理边界。

## `impl Trait` 与两道静态边界

沿用已实现 `Summary` 契约的两个不同结构体 `Article` 与 `Metric`。日常编写单次使用的泛型参数或对外隐藏返回具体类型名时，Rust 支持用 **`impl Trait`** 省略 `<T>` 声明：

<Code code={staticBoundaries} lang="rust" anchor="impl_trait_and_branch" />

- **参数位置 `&impl Summary`**：`fn notify(item: &impl Summary)` 是 `fn notify<T: Summary>(item: &T)` 的语法简写（注意若写两个 `&impl Summary` 形参，各自对应独立的类型参数，允许传入不同具体类型；而 `fn pair<T: Summary>(a: &T, b: &T)` 要求两者为同一类型）；
- **返回位置 `-> impl Summary`**：如 `make_default_metric` 所示，表示返回某个实现了 `Summary` 的单一具体类型，向调用方隐藏 `Metric` 这个名字。

<span class="rr-keypoint">无论写在参数还是返回值位置，`impl Trait` 底层依然是编译期静态单态化。</span>正因如此，一旦尝试以下两种动态场景，编译器均会以 `error[E0308]` 拦截：

### 边界一：运行期分支返回不同具体类型

取消上面第 35～41 行 `choose_item(is_article: bool) -> impl Summary` 的注释，试图在 `if` 分支返回 `Article`、在 `else` 分支返回 `Metric`：

<small class="code-source">编译器输出摘要（取消 static-boundaries.rs 第 35～41 行注释后）</small>
```text
error[E0308]: `if` and `else` have incompatible types
  --> types/traits/src/bin/static-boundaries.rs:39:9
   |
36 | /     if is_article {
37 | |         Article { title: String::from("News") }
   | |         --------------------------------------- expected because of this
38 | |     } else {
39 | |         Metric { name: "cpu", value: 10 }
   | |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ expected `Article`, found `Metric`
```

布尔参数 `is_article` 的值到运行期才揭晓，而静态单态化要求在编译期为 `-> impl Summary` 锁定**唯一一个**具体类型，以便在调用方栈帧预留固定大小的返回槽位并写死后续 `.summarize()` 的跳转地址。两个分支返回不同结构体时，这一静态前提无法成立。

### 边界二：同一集合混装不同具体类型（异构集合）

再看 `main` 末尾被注释掉的 `vec![Article { ... }, Metric { ... }]`（第 49～52 行）：

  --> types/traits/src/bin/static-boundaries.rs:51:9

## 编译期静态与运行时动态的显式开关

把这两处 `E0308` 放到全站视角下对照，就能看清 Rust 贯穿各篇的设计主线：

在 Java、Python 或 Go 中，语言默认把大多数机制做成了运行时动态的（对象默认上堆带对象头、方法默认动态查表、回收默认靠 GC），即便业务中九成场景在编译期已知，仍要普遍承担运行时开销。Rust 则相反：**以编译期静态确定为默认起点；仅当信息确需推迟到运行期决定时，才通过成对的动态类型构造器显式开启运行时机制，并将编译期擦除的元信息补入运行时内存中：**

| 决策维度 | 编译期静态版（默认起点，零额外运行时元数据） | 运行时动态版（按需开启，缺失信息补入运行时） | 机制落点 |
| --- | --- | --- | --- |
| **连续序列长度** | **定长数组引用 `&[T; N]`**：长度 `N` 留在编译期类型中，栈上占 **8 字节瘦指针** | **切片引用 `&[T]` / `&str`**：擦除长度 `N`，补入第 2 个机器字，占 **16 字节胖指针 `(ptr, len)`** | [切片与胖指针](/types/slices/) |
| **跨类型多态分发** | **泛型 `<T: Trait>` / `impl Trait`**：具体类型在编译期单态化定死，`&T` 占 **8 字节瘦指针** | **动态 `&dyn Trait`**：擦除具体类型，补入虚表指针，占 **16 字节胖指针 `(ptr, vtable)`** | 下一节展开 |
| **值大小与存放位置** | **栈内联值 `T`**：编译期定长（`Sized`），随栈帧自动收回 | **堆指针 `Box<T>` / `Vec<T>`**：栈存固定指针，堆承载动态或递归数据 | [单一所有权的堆智能指针：`Box<T>`](/pointers/box-smart-pointer/) |
| **所有者与借用检查** | **唯一所有者 `T` 与静态借用 `&T` / `&mut T`**：编译期追踪移动与读写排他 | **引用计数 `Rc` / `Arc` 与内部可变 `RefCell` / `Mutex`**：计数或锁移入运行时内存维护 | [`Rc<T>` 与 `Weak<T>`](/concurrency/rc-and-weak/) |

对比表中前两行：擦除数组长度 `; N` 把 `&[i32; 4]` 变成了 16 字节的 `&[i32]`；同理，擦除具体类型 `Article` 也会把 8 字节的 `&Article` 变成 16 字节的 **`&dyn Summary`**。下一节拆解这多出来的 8 字节虚表指针如何化解上述两道边界。
