## 从 `Summary` 契约到动态大小类型 `dyn Summary`

在[Trait 契约与泛型约束](/abstraction/traits-and-bounds/)中确认过，裸 `Summary` 只是编译期契约而非类型（报 `E0782`）。要把所有实现了 `Summary` 的实例归入同一种类型，先用关键字 **`dyn`**（Dynamic 缩写）充当类型构造器，合成出擦除具体类型身份的新类型——**`dyn Summary`**。

一旦擦除了底层具体类型，`dyn Summary` 在编译期占多少字节便无从确定：底层可能是 24 字节的 `Article`、24 字节但布局不同的 `Metric`，也可能是其他模块定义的 1 字节 `TinyBadge(u8)`。因此，与擦除了长度的裸切片 `[i32]` 一样，**`dyn Summary` 是编译期大小未知的动态大小类型（DST，未实现 `Sized`）**，不能直接作为局部变量或参数按值放在栈上。

## 套上指针构造器：16 字节胖指针 `&dyn Summary`

要使用 DST，必须在外层再套一层引用或堆指针构造器，合成出 **`&dyn Summary`**（语法优先级等价于 **`&(dyn Summary)`**，堆独占版本则是 **`Box<dyn Summary>`**）。

再按信息守恒核对指针大小：普通引用 `&Article` 在 64 位栈上只占 **8 字节**（仅存数据起始地址 `data_ptr`）。但 `Article` 实例在内存中是不含对象头的裸字节；若擦除具体类型后的 `&dyn Summary` 依然只存 `data_ptr`，运行期调用 `item.summarize()` 时 CPU 面对裸字节将无处查找 `<Article as Summary>::summarize` 的函数地址。

为了不把契约中所有方法的函数指针都塞进栈变量里造成膨胀，编译器在可执行文件的**只读静态数据段（Read-Only Data Segment）**中为每份具体实现（如 `impl Summary for Article`）生成唯一一张只读的**虚表（Virtual Method Table，简称 `vtable`）**，而在栈上的 `&dyn Summary` 变量中固定并列存放**两个 8 字节地址（共 16 字节）**：

<DynTraitVtable />

对照布局图，16 字节胖指针与只读虚表的分工如下：

1. **第 1 个机器字 `data_ptr`（8 字节）**：指向栈上或堆上的真实实例裸数据（如 `post: Article`）；
2. **第 2 个机器字 `vtable_ptr`（8 字节）**：指向只读静态段中的 `<Article as Summary> vtable`（程序中即使有上千个 `Article` 转成的 `&dyn Summary`，它们的 `vtable_ptr` 也共享指向这同一张静态表）；
3. **只读虚表 `vtable` 的固定槽位**：依次记录释放函数指针 **`drop_in_place`**（供 `Box<dyn Summary>` 释放底层堆资源时调用）、具体类型的字节大小 **`size`** 与对齐 **`align`**，以及各契约方法的机器码入口地址（如 `summarize -> Article::summarize`）。

## 化解两道静态边界

由于任意实现了 `Summary` 的类型一旦包成 `&dyn Summary` 或 `Box<dyn Summary>`，在栈/容器槽位中都统一为固定 **16 字节**的同一个具体类型，上一节的两处 `E0308` 随即迎刃而解：

<Aside type="note" title="与其他语言 interface 变量的对应关系">
其他语言中的接口类型变量，在 Rust 中对应的并非裸 `Trait`，而是显式拼装出的胖指针：Go 语言的 `interface` 底层（`iface`）同样是 16 字节双指针（`tab` 表指针 + `data` 数据指针）；Java 的接口引用则通过堆对象头查找方法表。在 Rust 中，函数参数临时只读传参写 **`&dyn Trait`**，作为返回值、结构体字段或装入 `Vec` 长期持有所有权则写 **`Box<dyn Trait>`**。
</Aside>
