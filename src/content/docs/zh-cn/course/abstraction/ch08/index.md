前序章节建立了一整套**编译期静态确定**的模型：变量栈尺寸在编译期固定、释放指令在作用域末尾静态插入、泛型 `<T: Trait>` 在编译期经单态化展开为多份专属机器码（静态分发）。

当业务场景要求函数的返回值具体类型由运行期输入决定，或者要求同一个 `Vec` 混装十几种实现了同一契约的不同结构体时，编译期单态化便会触及边界。本章跨越从编译期静态到运行时动态的分水岭，按四步推进：

- **编译期单态化的运行时边界**：掌握 `impl Trait` 在参数与返回值位置的简写语法，核对静态单态化在异构集合与运行期跨分支返回上的两处 `E0308` 报错，拉通全站「编译期静态 ↔ 运行时动态」的构造器切换脉络。
- **`dyn Trait` 与 16 字节虚表胖指针**：与切片 `&[T]` 的胖指针结构对照，说明为什么擦除具体类型后的 `&dyn Trait` 在栈上占 16 字节（`data_ptr + vtable_ptr`），以及只读静态段虚表（`vtable`）的槽位构成。
- **静态分发、动态分发与 `dyn` 兼容性**：对比 `<T: Trait>` 与 `&dyn Trait` 的寻址过程、内联优化与二进制体积取舍，并从虚表与调用栈的物理限制直接推导出 `dyn` 兼容性（`E0038`）的三条前提。
- **无 `class` 的代码组织与多态选型**：拆开传统 `class` 的三合一耦合结构，用结构体组合与 `Trait` 替代继承树，确立「闭合集合用 `enum`、开放集合用泛型或 `dyn Trait`」的架构审查准则。

读完本章，你应当能独立回答以下问题：

1. 为什么 `fn choose_item(flag: bool) -> impl Summary` 在 `if` 和 `else` 分支返回两个都实现了 `Summary` 的不同结构体时会编译失败？
2. 为什么 `&Article` 在 64 位平台上占 8 字节，转成 `&dyn Summary` 后变成 16 字节？多出的 8 字节指向哪里、内部记录了哪些信息？
3. 为什么包含 `fn clone_self(&self) -> Self` 或泛型方法 `fn tag<U>(&self, x: U)` 的 `Trait` 被禁止写成 `&dyn Trait`？
4. 面对多种业务形态共享行为的需求，依据什么标准在 `enum`、泛型 `<T: Trait>` 与 `Box<dyn Trait>` 之间做选型？
