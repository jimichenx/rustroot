集齐 `struct` / `enum`、固有 `impl`、泛型 `<T: Trait>` 与胖指针 `dyn Trait` 后，从 Java、C++ 或 Python 转向 Rust 的工程师在真实项目设计中通常会面临两个架构问题：没有 `class` 与 `extends` 时如何复用字段与逻辑？`enum`、`<T: Trait>` 与 `dyn Trait` 都能表达多态分支，在设计与代码审查时依据什么标准选型？

## 拆开传统 `class` 的三合一结构

传统面向对象语言中的 `class` 将三件职责耦合在同一个语法单元内：① 定义数据的物理内存布局；② 挂载该类型的固有方法；③ 绑定类继承树与多态契约（`extends Base implements Drawable`）。有时业务只想复用父类的两个字段，却不得不通过 `extends` 连带引入整条继承链、对象头与虚表耦合。

Rust 将这三项职责拆分为彼此正交的独立机制，按需取用（跨语言细节对照见附录「[没有 `class` 的对象感](/appendix/comparisons/oop/)」）：

<ClassUnbundling />

- **定义物理内存布局 → `struct` 或 `enum`**：只决定栈/堆字节如何排列，不附带隐藏对象头或虚表；
- **复用字段与内部逻辑 → 结构体组合（Composition）**：若 `AdminUser` 与 `NormalUser` 都需要基础账号字段，直接定义 `struct AccountCore { id: u64, email: String }` 并作为普通字段内嵌进 `AdminUser { core: AccountCore, role_level: u8 }`，内存连续平铺；
- **承诺跨类型多态契约 → 按需实现 `Trait`**：不需要多态的类型不承担任何虚表成本；需要时再通过 `<T: Trait>` 或 `dyn Trait` 接入。

## 多态选型判据：闭合集合与开放集合

当业务出现「多种形态执行同一项操作」的需求时，不少刚转向 Rust 的开发者（及缺乏约束提示的 AI 代码）会顺着 OOP 接口惯性，把固定业务状态也定义成 `trait State` 加 `Box<dyn State>`——在 Rust 中，这通常属于引入无谓堆分配与虚表跳转的反模式。

<span class="rr-keypoint">在 `enum` 与 `Trait` 之间做架构选型的首要判据，是看这组类型的集合对外部扩展是闭合的（Closed）还是开放的（Open）：</span>

### 变体集合已知且闭合 → 选 `enum`

以商城支付方式 `PaymentMethod`（现金、银行卡、电子钱包）或协议状态、JSON 节点（6 种固定形态）为例，所有合法变体在当前模块内已知且固定，无需允许第三方库随意注入未知变体。这类**闭合集合**直接选用 **`enum`**：

选用 `enum` 同时兼顾三项收益：① **栈上连续内联**（`PaymentMethod` 固定占 24 字节，装入 `Vec<PaymentMethod>` 无独立堆分配与 `vtable` 跳转）；② **编译期穷尽保护**（日后新增第 4 种变体时，全项目漏改的 `match` 自动报 `E0004`）；③ **新增操作轻量**（补充 `refund(&self)` 方法只需新增一个 `match` 函数，不改动各变体结构）。

### 允许外部自由扩展新类型 → 选 `Trait`

反过来，若你在编写基础告警框架 `Notifier`，除内置邮件与 Webhook 外，**要求外部业务团队能在不修改框架源码的前提下自行定义 `SlackNotifier` 接入**，这类**开放集合**无法用闭合的 `enum` 表达，应选用 **`Trait`**：

在开放集合内部，再按是否需要混装或运行期擦除二选一：同质单类型调用（如通用矩阵运算）优先选静态泛型 **`<T: Notifier>`** 以保留编译期内联；确需把不同实现混装进同一列表（如 `&[&dyn Notifier]` 或 GUI 插件容器 `Vec<Box<dyn Widget>>`）时，再选动态分发 **`dyn Notifier`**。

| 选型方案 | 适用前提 | 新增操作 | 新增数据类型/变体 | 内存与运行期成本 |
| --- | --- | --- | --- | --- |
| **闭合和类型 `enum`** | **变体种类已知且固定**（订单状态、AST/JSON 节点） | 仅新增一个 `match` 函数 | 修改 `enum` 定义，编译器提示所有 `match` 补齐分支 | **栈内联**，零额外堆分配，零 `vtable`，可内联 |
| **静态泛型 `<T: Trait>`** | **开放集合 + 同质调用**（编译期确定当次具体类型） | 在 `Trait` 新增无默认方法需各实现者补写 | 外部模块写 `impl Trait for NewType` 即可接入 | **8B 瘦指针**，直接跳转可内联；二进制体积随类型数增长 |
| **动态分发 `dyn Trait`** | **开放集合 + 异构集合或运行期分支**（插件列表） | 同上，且须遵守 `dyn` 兼容性三条限制 | 外部新类型实现后可直接混装进同一容器 | **16B 胖指针**，查 `vtable` 间接跳转，无法内联 |
