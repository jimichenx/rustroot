## 静态分发与动态分发的执行对比

多态代码中存在多个实现了 `summarize` 的具体类型，确定「当次调用究竟跳转到哪一段函数机器码」的过程称为**分发（Dispatch）**：

<Code code={dispatchAndCompatibility} lang="rust" anchor="dispatch_pair" />

1. **静态分发（`<T: Summary>` 或 `&impl Summary`）**：
   - **编译期写死地址**：单态化阶段为 `&Article` 与 `&Metric` 分别生成两份独立函数，内部直接写死目标函数地址，栈上只传 8 字节瘦指针；
   - **支持编译期内联（Inlining）**：由于目标代码在编译期确定，优化器可将 `Article::summarize` 的几行指令直接展开进调用方函数体，省去函数调用跳转与栈帧切换，在密集循环中还能进一步触发寄存器与向量化优化。
2. **动态分发（`&dyn Summary` 或 `Box<dyn Summary>`）**：
   - **运行期两步间接寻址**：全二进制中只保留**唯一一份** `notify_dynamic` 机器码。运行期收到 16 字节 `(data_ptr, vtable_ptr)` 后，CPU 先顺着 `vtable_ptr` 读取只读虚表取出 `summarize` 槽位中的函数地址，再将 `data_ptr` 作为首个参数执行间接跳转；
   - **无法内联**：编译 `notify_dynamic` 时无法预知运行期传入的 `vtable_ptr` 指向哪个具体类型，优化器无法将目标方法体内联展开。

| 对比维度 | 静态分发：`<T: Trait>` / `impl Trait` | 动态分发：`&dyn Trait` / `Box<dyn Trait>` |
| --- | --- | --- |
| **指针大小** | **8 字节瘦指针**（仅 `data_ptr`） | **16 字节胖指针**（`data_ptr + vtable_ptr`） |
| **寻址时机** | **编译期**单态化写死目标地址 | **运行期**查 `vtable` 间接跳转 |
| **内联优化** | **支持内联**，可消除调用开销 | **无法内联** |
| **机器码份数** | 按传入的 `N` 种具体类型生成 `N` 份机器码 | 无论多少种实现类型，**只生成 1 份机器码** |
| **异构集合** | 不支持（`Vec<T>` 仅装单一类型） | **支持**（`Vec<&dyn Trait>` / `Vec<Box<dyn Trait>>`） |

## 从 `vtable` 物理限制推导 `dyn` 兼容性

尝试将标准库的 `Clone` 或含泛型方法的 `Trait` 写成 `&dyn Clone` 时，编译器会报出 **`error[E0038]: the trait ... is not dyn compatible`**（旧版文献称对象安全 Object Safety）。

无需背诵语法条文，直接核对动态分发的物理前提：要让单份通用机器码仅凭 `(data_ptr, vtable_ptr)` 完成调用，必须同时满足**有胖指针查表入口**、**调用方栈帧大小可知**与**静态 `vtable` 槽位数固定**。打破其中任意一条，虚表调用在物理上便无法成立：

```text
error[E0038]: the trait `NotDynCompatible` is not dyn compatible
  --> types/traits/src/bin/dispatch-and-compatibility.rs:49:20
   |
49 |     let _bad: &dyn NotDynCompatible;
   |                    ^^^^^^^^^^^^^^^^ `NotDynCompatible` is not dyn compatible
   |
note: for a trait to be dyn compatible it needs to allow building a vtable
  --> types/traits/src/bin/dispatch-and-compatibility.rs:37:8
   |
36 | trait NotDynCompatible {
   |       ---------------- this trait is not dyn compatible...
37 |     fn make_default() -> u32;
   |        ^^^^^^^^^^^^ ...because associated function `make_default` has no `self` parameter
38 |     fn clone_self(&self) -> Self;
   |                             ^^^^ ...because method `clone_self` references the `Self` type in its return type
39 |     fn tag<U>(&self, extra: U) -> u32;
   |        ^^^ ...because method `tag` has generic type parameters
```

<span class="rr-keypoint">报错中的三条 `because` 与虚表调度的物理约束一一对应：</span>

| 违反 `dyn` 兼容性的写法 | 物理受阻原因 | 标准库典型案例 |
| --- | --- | --- |
| **无 `self` 接收者的关联函数**（`fn make_default() -> u32`） | 调用时手里没有任何胖指针实例，缺失 `vtable_ptr` 查表入口 | `Default::default`、`From::from` |
| **按值返回或接收 `Self`**（`fn clone_self(&self) -> Self`） | 具体类型已擦除，调用方编译期不知 `Self` 占多少字节，无法在栈帧预留槽位（改为返回固定 16 字节的 `Box<dyn Trait>` 即可恢复兼容） | `Clone`、`PartialEq`（默认比较 `Self`） |
| **方法自身带泛型 `<U>`**（`fn tag<U>(&self, x: U)`） | 泛型方法会随任意未知 `U` 单态化出不限数量的函数地址，无法装入编译期固定槽位数的静态 `vtable` | `serde::Serializer` |
