上一篇主要在**使用**标准库预先定义好的类型构造器：往 `Vec<T>` 填入 `i32` 合成 `Vec<i32>`，往 `Option<T>` 填入 `String` 合成 `Option<String>`，并用固有 `impl` 块为单个具体类型挂载方法。

本章将视角从单个具体类型推向跨类型的通用抽象：亲手定义带 `<T>` 的泛型结构与泛型函数时，编译器在底层生成了什么代码？当不同的具体类型需要对外承诺同一组能力时，Rust 如何在没有类继承的前提下通过 **Trait** 完成静态检查、跨载体参数兼容与全局一致性保护？

本章分八步推进：

- **泛型与单态化（Monomorphization）**：从泛型参数 `<T>` 的四个位置出发，结合运行时栈上裸数据不含对象信息头的事实，推导通用代码为何按具体类型在编译期拆分为多份独立机器码。
- **Trait 契约与泛型约束**：说明为什么不能把 Trait 直接当作变量类型、为什么裸 `<T>` 内部连加法都无法调用，建立 `<T: Trait>` 双向静态检查与事后挂载能力。
- **关联类型与泛型 Trait**：对比 `trait From<T>` 与 `trait Iterator { type Item; }`，区分同一个类型对多种输入实现多次（一对多）与唯一锁定输出类型（一对一）的边界。
- **转换契约与 `?` 错误归并**：拆解一揽子实现（Blanket Implementation）如何让实现 `From` 的类型自动获得 `Into`，用 `<T: Into<Target>>` 接纳多种构造输入，并补齐 `?` 跨错误类型转换的机制。
- **借用视图与只读接口设计**：用 `AsRef` 零堆分配兼容单参与切片多载体输入，规避按值传参的静默移动，掌握「泛型薄壳 + 非泛型内层」去膨胀惯用法，并辨析 `Borrow` 的哈希等价要求。
- **受检转换、切片升级与成本命名**：补齐从动态大小切片升级为堆所有者的 `ToOwned`、返回 `Result` 的 `TryFrom` 与显式初始值 `Default`，收束为 `as_` / `to_` / `into_` 方法前缀审查准则。
- **孤儿规则与全局一致性**：推导跨包一致性为何以 `crate` 为边界，拆解外部容器包裹限制（`E0117`）与一揽子重叠冲突（`E0119`），掌握本地元组结构体包装（Newtype）与扩展契约模式。
- **内核机制、语言项与库策略**：从机制与策略分离出发，看清编译器如何借助 `#[lang]` 字符串钩子与生态约定 Trait 将语言内核压缩到极小，支撑 `#![no_std]` 与三层标准库拆分。

读完本章，你应当能独立回答以下问题：

1. 运行时栈上只存不含对象头的裸字节，`fn swap<T>(a: T, b: T)` 靠什么机制同时支持 1 字节的 `u8` 和 24 字节的 `String`？
2. 为什么不能像写 Java 接口那样直接写 `fn notify(item: Summary)`？`<T: Summary>` 在函数体内部和调用点分别检查什么？
3. 同样用于提升函数参数的多载体兼容能力，`<T: Into<Endpoint>>` 与 `<P: AsRef<Path>>` 在所有权流向与堆分配成本上有何不同？为什么 `HashMap<String, V>::get("key")` 依赖 `Borrow<str>` 而非 `AsRef<str>`？
4. 为什么为顶层错误实现 `From<ParseIntError>` 后就能直接对 `ParseIntError` 使用 `?`？转换可能因输入越界失败时，为什么必须改用 `TryFrom`？
5. 同样带有本地类型 `LocalId`，为什么 `impl From<LocalId> for Vec<u8>` 合法，而 `impl Display for Vec<LocalId>` 违反孤儿规则？标准库里的 Trait 按与编译器的关系分为哪两类？
