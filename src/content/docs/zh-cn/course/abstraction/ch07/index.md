在上一篇中，我们一直在**使用**标准库预先定义好的类型构造器：往 `Vec<T>` 里填入 `i32` 合成 `Vec<i32>`，往 `Option<T>` 里填入 `String` 合成 `Option<String>`，并用固有 `impl` 块为单个具体类型挂载方法。

本章将视野从「单个具体类型」推向「跨类型的通用抽象」：当我们自己定义带 `<T>` 的泛型类型与泛型函数时，编译器在底层生成了什么代码？当不同的类型需要对外承诺同一组行为时，Rust 如何通过 **Trait（契约）** 在不引入类继承的前提下完成静态检查、灵活参数兼容与跨包一致性保护？

本章按八步推进：

1. **泛型与编译期单态化（Monomorphization）**：从泛型参数 `<T>` 的四个位置出发，结合「运行时栈上裸数据不含对象信息头」的物理事实，推导为什么通用代码必须按具体类型在编译期拆分为多份独立机器码。
2. **Trait 契约与泛型约束**：解答为什么不能把 Trait 直接当作变量类型、为什么裸 `<T>` 内部连加法都无法调用，建立 `<T: Trait>` 双向静态检查，并认识数据定义与行为挂载分离带来的事后扩展能力。
3. **关联类型 vs 泛型 Trait**：对比 `trait From<T>` 与 `trait Iterator { type Item; }`，厘清什么时候一个类型需要对多种输入实现同一契约（一对多），什么时候必须唯一锁定输出类型（一对一）。
4. **转换契约与一揽子实现（`From` / `Into` 与 `?` 错误归并）**：拆解一揽子实现（Blanket Implementation）如何让你只实现 `From` 即自动获得 `Into`，看清如何用 `Into` 接纳多种构造输入，并揭开 `?` 运算符跨错误类型自动转换的底层机制。
5. **借用视图与只读 API 设计（`AsRef`、`AsMut` 与 `Borrow`）**：针对只读场景消除无谓堆分配，掌握用 `AsRef` 兼容单参与切片多载体输入、规避按值传参的静默移动陷阱、用「泛型薄壳 + 非泛型内层」消除单态化膨胀，并辨析 `Borrow` 如何保障 `HashMap` 零分配查询的语义等价。
6. **受检转换、切片升级与默认契约（`TryFrom`、`ToOwned`、`Default` 与成本命名）**：补齐从借用切片反向升级为所有者的 `ToOwned`、返回 `Result` 的受检转换 `TryFrom` 与显式初始值 `Default`（含防止派生默认值破坏业务不变量），建立 `as_` / `to_` / `into_` 方法前缀的审查判据。
7. **孤儿规则与全局一致性**：在见识完全套标准库契约与一揽子实现后，推导为什么跨包一致性边界画在 `crate` 上，拆解泛型包裹限制（`E0117`）与一揽子实现重叠（`E0119`），掌握本地包装（Newtype）与扩展契约（Extension Trait）模式。
8. **章末视野：Rust 语言到底有多小？**：从「机制与策略分离」出发，看清 Rust 如何通过 `#[lang]` 字符串协议钩子与全生态公共约定 Trait 把语言内核压缩到极小，将其他语言的内置特性交由库来实现。

## 读完本章，检验自己的五个问题

- 既然 Rust 的值在运行时内存里只存裸字节、不带对象信息头，一段写成 `fn swap<T>(a: T, b: T)` 的泛型函数靠什么机制同时支持 1 字节的 `u8` 和 24 字节的 `String`？
- 为什么不能像写 Java 接口那样直接写 `fn notify(item: Summary)`？`<T: Summary>` 泛型约束在函数体内部和函数调用点分别检查什么？
- 同样用来提升函数参数的多类型兼容能力，`<T: Into<Endpoint>>` 与 `<P: AsRef<Path>>` 在所有权流向与堆分配成本上有什么区别？为什么 `HashMap<String, V>::get("key")` 依赖的是 `Borrow<str>` 而不是 `AsRef<str>`？
- 为什么只为自定义错误实现了 `From<ParseIntError>`，就能直接对 `ParseIntError` 使用 `?` 运算符？当转换可能因输入越界而失败时，为什么严禁实现 `From` 而必须改用 `TryFrom`？
- 同样带上了本地类型 `LocalId`，为什么 `impl From<LocalId> for Vec<u8>` 能通过编译，而 `impl Display for Vec<LocalId>` 会违反孤儿规则？标准库里的 Trait 按与编译器的关系分为哪两大阵营？
