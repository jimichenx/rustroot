盘点前七节接触的核心能力，可以看到一个鲜明的结构特征——在 C++、Java、Python 或 Go 中由编译器硬编码处理的内置特性，在 Rust 中大多是写在标准库甚至第三方库里的普通类型与 `Trait`：

| 传统语言的编译器内置特性 | Rust 中的库级身份 |
| --- | --- |
| 空指针 `null` / `nil` | 标准库泛型枚举 `Option<T>` |
| 异常捕获 `try / catch / throw` | 标准库泛型枚举 `Result<T, E>` |
| 堆内存分配关键字 `new` | 标准库 `Box<T>`、`Vec<T>`、`String` |
| 同名不同参函数重载 | 泛型函数 `<T>` + `From` / `Into` / `AsRef` 契约 |
| 值复制与深复制规则 | 标准库 `Copy`、`Clone`、`ToOwned` |
| 运算符重载与格式化 | 标准库 `Add`、`PartialEq`、`Display`、`Debug` |
| 异步协程调度器（如 Go 运行时） | 内核仅生成状态机，调度器由第三方库（如 `tokio`）实现 |

本章最后一节从系统设计的**机制与策略分离**原则出发，理清语言内核与标准库的协作边界。

## 机制留在内核，策略交给库

操作系统设计有一条经典分工：把不可变的基础**机制（Mechanism）**留在极小的内核里，把因运行环境而异的**策略（Policy）**放到用户态库中。若语言将追踪式 GC 或固定线程调度器直接写死在编译器内核里，常规业务开发固然省事，但一旦进入裸机固件、实时音频引擎或定制高吞吐异步 I/O 场景，开发者便无法替换内核预设的决定。

Rust 将两层拆开：

1. **语言内核只保留无法由库自举的基础机制**：内置原生类型（标量、引用、数组、切片、元组）、所有权与借用检查器、`struct` / `enum` 与穷尽模式匹配、泛型单态化、`Trait` 检查器及孤儿规则；
2. **标准库与生态库提供具体策略**：堆容器如何扩容（`Vec<T>`）、字符串采用何种编码（`String`）、多载体如何转换（`From` / `AsRef` / `Borrow`）、异步任务如何调度（`tokio`），均作为普通库代码独立演进。

## 标准库 `Trait` 的两大阵营

既然运算符和堆容器都不写死在编译器里，极小内核如何与库协同工作？按**与编译器的关系**，本章学过的标准库 `Trait` 分为两大阵营：

### 系统钩子契约（语言项 `#[lang]`）

写下 `a + b`、`a == b`、`b = a`（按位复制）或 `for x in v` 时，编译器在语法降级（Desugar）阶段会将它们翻译为特定 `Trait` 方法调用（如 `a + b` 降级为 `Add::add(a, b)`）。

为了不让编译器反向硬编码依赖 `std::ops::Add` 路径（裸机环境下甚至不存在 `std`），Rust 采用**字符串协议绑定（语言项 Lang Items）**：

```rust
#[lang = "add"]
pub trait Add<Rhs = Self> {
    type Output;
    fn add(self, rhs: Rhs) -> Self::Output;
}

#[lang = "copy"]
pub trait Copy: Clone {}
```

编译器内部只认 `"add"`、`"copy"`、`"deref"`、`"into_iter"` 等字符串标识，官方 `core` 库在对应 `Trait` 上标注 `#[lang = "..."]` 认领标识。用户自定义类型只需加上 `#[derive(Debug, Clone, Copy, PartialEq, Eq)]` 或手写 `impl Add`，即可接入语言级运算符（完整清单见附录「[编译器钩子 Trait 速查](/appendix/mechanisms/lang-item-traits/)」）。

### 生态公共约定契约

另一批高频契约——**`From` / `Into`、`AsRef`、`Borrow`、`ToOwned`、`TryFrom`、`Default`、`Display`**——并无对应的运算符语法，也不在编译器的 `#[lang]` 清单中。

<span class="rr-keypoint">标准库统一定义这批编译器不感知的契约，是为了给全生态提供统一的公共握手协议。</span>若无官方统一的 `AsRef`、`Borrow` 与 `From`，第三方库各自发明互不兼容的转换接口，生态便会陷入胶水代码碎片化；有了标准库契约加孤儿规则保障唯一性，所有库围绕同一套约束定义签名，业务类型实现一次即可接入全生态。

| 阵营 | 与编译器关系 | 代表 `Trait` | 架构作用 |
| --- | --- | --- | --- |
| **系统钩子契约** | 经 `#[lang = "..."]` 与运算符及控制流语法绑定 | `Copy`、`Add`、`PartialEq`、`Index`、`Drop`、`Iterator` | 解耦编译器与标准库路径，向自定义类型开放原生语法 |
| **生态约定契约** | 编译器不感知，纯库级定义 | `From` / `Into`、`AsRef`、`Borrow`、`ToOwned`、`TryFrom`、`Default` | 充当核心库、第三方包与业务代码的公共通信协议 |

## 直接证据：`#![no_std]` 与标准库三层拆分

内核与库解耦的直接体现，是官方标准库按环境依赖拆分为三个递进的独立 `crate`：

1. **`core`（零操作系统、零堆分配）**：不依赖操作系统 API 与堆分配器。`Option<T>`、`Result<T, E>`、切片操作以及 `Copy`、`Add`、`From`、`TryFrom`、`AsRef`、`Borrow`、`Iterator` 等核心 `Trait` 全部位于 `core` 中；
2. **`alloc`（接入堆分配器即可使用）**：在无操作系统但提供堆分配器的硬件上，引入 `alloc` 即可获得 `Vec<T>`、`String`、`ToOwned` 以及 `Box<T>`、`Rc<T>`、`Arc<T>`；
3. **`std`（依赖操作系统服务）**：桌面与服务端默认启用，封装文件（`std::fs`）、网络（`std::net`）、线程（`std::thread`）等系统调用（这套极小内核取舍的横向对比可参阅附录「[Rust 的三条设计取舍](/appendix/comparisons/design-philosophy/)」）。

开发操作系统内核、单片机固件或精简 WebAssembly 模块时，只需在入口写一行 `#![no_std]` 卸下 `std`，所有权检查、模式匹配、泛型单态化与 `core` 中的全部契约依然原样工作。
