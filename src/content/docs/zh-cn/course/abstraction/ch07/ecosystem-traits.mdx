前两节分别打通了必定成功的消费转换（`From` / `Into`）与零堆分配的只读视图提取（`AsRef` / `Borrow`）。沿着所有权流向与数据合法性继续核对，接口边界上还有三块拼图需要补齐：如何从动态大小切片 `&str` 反向升级为堆所有者 `String`？按值转换可能失败时如何避免 `panic!`？无隐式零值的 Rust 又靠什么提供安全的默认初值？这三项职责分别对应 **`ToOwned`、`TryFrom` 与 `Default`**。

## 切片升级：`ToOwned` 为何独立于 `Clone`

对于编译期大小已知的具体类型，`Clone` 的签名为 `pub trait Clone: Sized { fn clone(&self) -> Self; }`——父契约 `: Sized` 与返回类型 `-> Self` 要求被借用目标与复制出的新值必须是**同一个固定大小的类型**。

而字符串切片 `&str` 指向的 `str` 是编译期大小未知的动态大小类型，函数在物理上无法按值返回裸 `str`，它对应的堆所有者是另一个结构体 **`String`**（同理 `[T]` 对应 **`Vec<T>`**）。为此，标准库在 `alloc::borrow` 中结合上一节的 `Borrow` 定义了 **`ToOwned`**：

```rust
pub trait ToOwned {
    type Owned: Borrow<Self>;
    fn to_owned(&self) -> Self::Owned;
}
```

关联类型约束 `type Owned: Borrow<Self>` 锁定了双向对称关系：升级出的堆所有者 `Owned` 必须能反过来通过 `Borrow` 借出当前切片 `Self`。`str` 指定 `type Owned = String`（调用 `"localhost".to_owned()` 分配堆内存返回 `String`），`[T]` 指定 `type Owned = Vec<T>`，所有已实现 `Clone` 的定长类型 `T` 则通过一揽子实现自动满足 `ToOwned<Owned = T>`（后续[写时复制智能指针 `Cow<'a, B>`](/architecture/cow-clone-on-write/)即建立在这对桥接契约之上）。

## 受检转换：`TryFrom<T>` 与 `TryInto<U>`

编写转换实现或审查代码时有一条硬性边界：**禁止在 `From::from` 内部因外部输入越界或格式错误而调用 `panic!` 或 `.unwrap()`**。`From<T>` 只用于无损且必定成功的转换（如从合法 `Port` 提取底层 `u16`）。

一旦源类型的取值范围大于目标类型的合法域（例如把 `u32` 缩窄为限定在 `1..=65535` 内的非零端口 `Port`），必须改用受检转换契约 **`core::convert::TryFrom<T>`**：

```rust
pub trait TryFrom<T>: Sized {
    type Error;
    fn try_from(value: T) -> Result<Self, Self::Error>;
}
```

给定源类型 `T` 与目标类型 `Self`，失败的错误类型唯一确定，因此用关联类型 `type Error;` 锁定。标准库同样内置了一揽子实现，只需手写 `TryFrom`，调用方即自动获得返回 `Result` 的 `.try_into()` 方法并可直接配合 `?` 传播错误。

## 默认初值：`Default` 与不变量保护

Rust 要求实例化结构体时显式初始化每个字段，由 **`core::default::Default`**（`fn default() -> Self;`）统一提供无参初始值。实现 `Default` 后，除了支持 `Config { timeout: 30, ..Default::default() }` 更新语法外，还解锁两项实用工具：

1. **`Option<T>::unwrap_or_default()`**：为 `None` 时自动调用 `T::default()` 回退；
2. **`std::mem::take(&mut target)`**：面对可变借用 `&mut String` 或 `&mut Vec<T>`，无需外包 `Option`（对比[工程裁决：驾驭 `Option` / `Result`](/types/error-handling/)中的 `Option::take`），直接向原槽位填入 `Default::default()` 空壳并抽走原堆缓冲区所有权——空 `String::new()` 与 `Vec::new()` 容量为 `0`、不申请堆内存，整步置换零堆分配。

<Aside type="caution" title="防止 #[derive(Default)] 绕过受检边界">
`u16` 的默认值是 `0`。若对规定合法域为 `1..=65535` 的 `struct Port(u16)` 直接标注 `#[derive(Default)]`，编译器会生成返回 **`Port(0)`** 的实现，使外部调用 `Port::default()` 即可绕过 `TryFrom` 造出非法实例。带有合法域不变量的类型，应手写 `impl Default` 返回合法初值（如 `Port(8080)`），或直接不实现 `Default`。
</Aside>

## 成本命名法则：`as_`、`to_` 与 `into_`

汇总前三节的全部转换契约，标准库 [API 命名指南](https://rust-lang.github.io/api-guidelines/naming.html)（详查附录「[Rust 命名约定与工程惯例速查](/appendix/basics/conventions/)」）将所有权流向与堆分配成本直接编码进了方法名前缀：

| 转换方向 | 代表 `Trait` | 方法前缀 | 接收者 | 分配成本与原变量状态 | 标准库示例 |
| --- | --- | --- | --- | --- | --- |
| **借用取视图** | `AsRef` / `Borrow` | **`as_...`** | `&self` | **零堆分配**；构造引用或胖指针，原变量继续有效 | `s.as_str()`、`s.as_bytes()`、`v.as_slice()` |
| **借用造新值** | `ToOwned` / `Clone` | **`to_...`** | `&self` | **有分配成本**；申请新堆块并复制字节，原变量继续有效 | `s.to_owned()`、`s.to_lowercase()`、`slice.to_vec()` |
| **消费交所有权** | `From` / `Into` | **`into_...`** | `self` | **原变量移动失效**；原地转交底层堆缓冲区，零字节复制 | `s.into_bytes()`（24B 控制头直接转交 `Vec<u8>`） |
| **受检转换** | `TryFrom` / `TryInto` | **`try_...`** | `self` 或源值 | 校验输入合法性并返回 `Result` | `Port::try_from(n)` |

<span class="rr-keypoint">审查循环热路径代码时，重点核查密集的 `.to_vec()`、`.to_owned()` 与 `.clone()`：下游仅只读时换用 `as_bytes()`，原值不再使用时换用 `into_bytes()`（或 `mem::take`）复用已有堆内存。</span>
