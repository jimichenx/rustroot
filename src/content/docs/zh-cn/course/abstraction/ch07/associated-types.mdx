上一节的 `Summary` 契约中，方法返回类型固定为 `String`。但在真实接口中，契约常常需要引入另一个待定类型——例如「从某种源类型转换而来」或「每次调用产出某种元素」。

向 `Trait` 引入待定类型有两种语法形式：**尖括号泛型参数 `trait MyFrom<T>`** 与**花括号内的关联类型 `type Item;`**。两者的分工取决于同一个目标类型是否允许实现多次该契约。

## 一对多实现：泛型 `Trait<T>`

先看数据包 `Packet { len: usize }` 的构造需求：业务既希望从长度数字 `usize` 构造 `Packet`，也希望从字符串切片 `&str` 构造 `Packet`。将源类型 `<T>` 作为泛型参数放在契约名后，填入不同参数即生成互不冲突的契约（`MyFrom<usize>` 与 `MyFrom<&str>`），同一个 `Packet` 可以分别实现两次：

调用 `Packet::my_from(64usize)` 与 `Packet::my_from("hello")` 时，编译器按实参类型自动匹配对应实现。当同一个目标类型需要针对多种不同外部类型分别实现同一契约（**一对多关系**）时，使用泛型 `Trait<T>`。

## 全写成泛型 `<T>` 会有什么问题

如果把递增计数器 `Counter { current: u32 }` 的迭代契约也照搬写成泛型 `trait BadIterator<Item> { fn next_item(&mut self) -> Option<Item>; }`，会立刻暴露两处问题：

1. **语义失控**：任何人都能给同一个 `Counter` 同时实现 `BadIterator<u32>` 与 `BadIterator<String>`，违背了一个具体计数器产出元素类型唯一确定的事实；
2. **类型标注泛滥**：由于编译器必须假设 `Counter` 可能实现任意多个 `BadIterator<T>`，调用 `c.next_item()` 时常被迫手写目标类型标注，且接收该迭代器的泛型函数必须同时拖带 `<C, Item>` 两个类型参数（`where C: BadIterator<Item>`）。

## 一对一锁定：关联类型 `type Item;`

要表达「每个具体类型最多只能实现一次该契约，一旦实现者 `Self` 确定，产出的元素类型即唯一确定」，需将占位符从尖括号移入花括号内部，声明为**关联类型（Associated Type）**：

改用 `type Item;` 后，两处问题同时消除：

1. **编译期强制一对一（`E0119`）**：`MyIterator` 名后不带泛型参数，对 `Counter` 而言只有唯一一份 `MyIterator`；取消源码中第二个 `impl MyIterator for Counter` 的注释会立即触发 `error[E0119]: conflicting implementations of trait MyIterator for type Counter`；
2. **调用与泛型签名免除多余参数**：`Counter` 的 `Item` 已唯一锁定为 `u32`，调用点无需附加类型标注，泛型函数也只需声明单一参数 `<C: MyIterator>` 并通过 `C::Item` 引用产出类型。

## 选型判据：输入用 `<T>`，输出用关联类型

设计自定义 `Trait` 或阅读标准库签名时，按输入与输出角色即可区分两者：

| 维度 | 泛型 Trait：`trait Trait<T>` | 关联类型：`trait Trait { type Item; }` |
| --- | --- | --- |
| **实现基数** | **一对多**：同一类型可针对不同 `T` 实现多次 | **一对一**：同一类型只能实现一次（重复实现报 `E0119`） |
| **工程角色** | 契约的**输入参数**（由调用方决定传入哪种 `T`） | 契约锁定的**唯一输出类型**（由实现者 `Self` 唯一决定） |
| **标准库代表** | `From<T>` / `Into<T>`、`AsRef<T>` | `Iterator::Item`、`Future::Output`、`TryFrom::Error` |

<Aside type="note" title="同时包含两者的标准库案例：Add">
[泛型与单态化](/abstraction/generics-and-monomorphization/)报错提示中的加法契约定义为 `pub trait Add<Rhs = Self> { type Output; fn add(self, rhs: Rhs) -> Self::Output; }`：右操作数 `Rhs` 是**泛型参数**（默认等于 `Self`），允许坐标点 `Point` 既支持加向量 `Vector` 又支持加标量偏移 `i32`（一对多输入）；而相加结果 `Output` 是**关联类型**，一旦左右操作数类型确定，结果类型即唯一锁定（一对一输出）。
</Aside>
