前序章节已经使用过 `Vec<T>`、`Option<T>`、`Result<T, E>` 等标准库泛型构造器。本章切换到定义者视角，先解决一个底层执行问题：在[类型的两面](/types/representation-and-constraints/)与[结构体（`struct`）](/types/structs/)中确认过，Rust 的值在运行时内存里只是紧挨平铺的裸字节——`u8` 占 1 字节，`String` 占 24 字节，没有任何运行时对象头记录类型或大小。既然传入函数的只是裸字节，一段写成 `fn swap_tuple<T>(a: T, b: T) -> (T, T)` 的泛型代码，在运行时如何知道该搬运几个字节、又该如何释放内存？

## 泛型参数 `<T>` 的四个位置

**泛型（Generics）**是在定义数据结构或函数时，用 `<T>`（多个参数以逗号分隔，如 `<T, E>`）留出等待填入具体类型的编译期参数槽。它可出现在四个位置：

```rust
struct Pair<T> {
    first: T,
    second: T,
}

enum Maybe<T> {
    Nothing,
    Just(T),
}

fn first_item<T>(pair: Pair<T>) -> T {
    pair.first
}

impl<T> Pair<T> {
    fn into_swapped(self) -> Pair<T> {
        Pair { first: self.second, second: self.first }
    }
}
```

注意第 4 处的 `impl<T> Pair<T>`：第一个 `<T>` 向编译器声明该实现块引入泛型参数 `T`，第二个 `Pair<T>` 则是将参数填入构造器，为任意 `T` 生成的 `Pair<T>` 批量挂载方法。正如[类型构造器](/types/type-constructors/)所确立的规则，未填参的裸 `Pair` 不是具体类型（直接写 `let p: Pair = ...` 报 `E0107`）；填入不同参数后，编译器分别合成出 `Pair<u8>`（2 字节）、`Pair<u64>`（16 字节）或 `Pair<String>`（48 字节）等独立的具体类型。

## 裸数据与编译期单态化

来看 `fn swap_tuple<T>(a: T, b: T) -> (T, T)` 的执行条件。要让 CPU 正确运行这段函数，必须明确三项类型元信息：参数 `a` 和 `b` 在栈帧上各占多少字节、参数 `b` 位于栈帧的哪个偏移处、函数返回前是否需要对丢弃的值执行堆内存释放（`drop`）。

在带运行时虚拟机的面向对象语言中，每个堆对象自带对象信息头，或栈上统一存放 8 字节引用指针，CPU 可以用同一份通用指令搬运指针。而在 Rust 中，栈上的参数是尺寸各异、不含对象头的裸字节。既然运行时数据本身不携带类型元信息，编译器就只剩两条路安放这些信息：

1. **编译期单态化（把类型信息固化进多份独立机器码）**：保持栈上按值传递裸字节；编译器扫描全程序调用点，发现 `swap_tuple` 被传入了 `u8`、`u64` 和 `String`，就在编译期将它拆成三份独立的机器码函数——分别专职搬运 1 字节、8 字节以及带释放逻辑的 24 字节控制头；
2. **运行时动态分发（把类型信息补进胖指针）**：若要求二进制中只保留单份通用函数，就无法按值接收未知大小的裸 `T`，必须改由指针间接传参，并将大小、释放函数与方法地址打包成只读虚表（`vtable`），组成 **16 字节胖指针**传入——这条路径将在[`dyn Trait` 与 `vtable`](/abstraction/dyn-trait-and-vtable/)展开。

编写泛型 `<T>` 时，Rust 走的是第一条路径。这个在编译期按实际填入的具体类型参数，将一份泛型模板展开为多份专用机器码的过程，称为**单态化（Monomorphization）**。

<Aside type="note" title="用困难三角看单态化的取舍">
单态化在运行时实现了零成本抽象：调用 `swap_tuple(1u8, 2u8)` 与手写专用函数 `swap_u8(a: u8, b: u8)` 的机器指令完全一致，无装箱、无虚表跳转。相应的代价转移到了**编译耗时与二进制体积**上：对十几种具体类型调用同一个大型泛型函数，就会重复编译并生成十几份机器码。
</Aside>

与代入具体类型后才报错的宏替换式模板不同，<span class="rr-keypoint">Rust 在单态化展开之前，直接对照泛型函数签名对函数体做一次性类型与借用检查。</span>写下无约束的 `<T>` 等于声明该函数必须对**任意具体类型**成立；面对未知的 `T`，所有类型共有的合法操作只有**移动、借用（`&T` / `&mut T`）与离开作用域释放**——加法 `+`、相等比较 `==`、格式化打印与字段访问均被拒绝。

要让泛型函数调用特定方法或运算符，必须在签名上显式声明准入条件（如上面编译器提示的 `trait Add`）。下一节进入跨类型的能力契约——**Trait 与泛型约束**。
