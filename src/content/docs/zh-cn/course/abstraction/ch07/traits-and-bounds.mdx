上一节末尾遇到了裸 `<T>` 的能力边界：编译器在单态化之前就会静态审查函数体，未知的 `T` 除了移动、借用与释放外不具备任何额外方法。要让不同的具体类型进入同一个泛型函数并调用共同方法，需要引入跨类型的能力契约——**`Trait`**。

## 定义与实现 `Trait`

在[方法接收者三件套与自动解引用](/types/methods/)中，`impl Article { ... }` 只为单个结构体挂载固有方法。当多个独立类型（如文章 `Article` 与监控指标 `Metric`）需要对外提供同一项能力时，分两步编写 `trait` 定义与 `impl Trait for Type` 实现：

`trait Summary` 花括号内只列出方法签名并以分号 `;` 结尾；随后通过 `impl Summary for Article` 为具体类型补齐实现。只要 `Summary` 在当前作用域内，即可直接在实例上用点号调用 `post.summarize()`。

## 为什么不能直接写 `item: Summary`

契约就绪后，编写接收任意可摘要数据的通用函数 `notify`。有 Java 或 Go 背景的开发者常会尝试把 `Summary` 直接写在参数类型位置：

<Code code={traitNotType} lang="rust" anchor="notify_bound" />

取消第 28 行 `// fn bad_notify(item: Summary) {}` 的注释后，编译器直接报出 `error[E0782]`：

<small class="code-source">编译器输出摘要（取消 trait-not-type.rs 第 28 行注释后）</small>
```text
error[E0782]: expected a type, found a trait
  --> types/traits/src/bin/trait-not-type.rs:28:21
   |
28 | fn bad_notify(item: Summary) {}
   |                     ^^^^^^^
   |
help: use a new generic type parameter, constrained by `Summary`
```

回到[类型的两面](/types/representation-and-constraints/)：Java 的 `Summary item` 变量在栈上存放的是固定字长的堆对象引用；而 Rust 变量默认按值内联在栈上，`Summary` 只规定了行为签名，没有规定栈尺寸（`Article` 占 48 字节，`Metric` 占 24 字节）。<span class="rr-keypoint">`Trait` 本身不是具体值类型，而是筛选类型的编译期契约。</span>

静态多态下的标准写法是用它约束泛型参数，写成 **`fn notify<T: Summary>(item: &T)`**：真正充当参数类型的是泛型引用 `&T`（单态化阶段分别展开为 `&Article` 与 `&Metric`），`: Summary` 则是挂在 `T` 上的准入契约。

<small class="code-source">源文件：<code>examples/types/traits/src/bin/trait-not-type.rs</code></small>

## 泛型约束的双向检查

`<T: Summary>` 称为**泛型约束（Trait Bound）**。同时要求多项契约时用 `+` 叠加（如 `<T: Summary + std::fmt::Debug>`），约束较长时可用 `where` 子句移至签名末尾（`where T: Summary + std::fmt::Debug`）。

在编译期，`<T: Summary>` 同时向内、向外执行双向静态检查：

<small class="code-source">源文件：<code>examples/types/traits/src/bin/two-way-contract.rs</code>（节选）</small>
<Code code={twoWayContract} lang="rust" anchor="two_way" />

1. **对函数体内部的权限限制（`E0609`）**：函数体内获准调用 `item.summarize()`，但也**只能访问 `Summary` 契约声明过的方法**。即便稍后只传入带 `.value` 字段的 `Metric`，取消 `item.value` 的注释仍会当场触发 `error[E0609]: no field value on type &T`；
2. **对调用点的准入核对（`E0277`）**：取消 `notify(&raw)` 的注释，传入未实现 `Summary` 的 `Unregistered` 时，编译器立即以 `error[E0277]: the trait bound Unregistered: Summary is not satisfied` 拒绝编译。

<Aside type="tip" title="函数签名即能力边界">
双向检查使泛型签名成为严格的审查边界：看到 `fn process<T: Summary>(item: &T)` 时，无需翻阅函数体实现，编译期即保证该函数（无论由人还是 AI 编写）除调用 `Summary` 方法外无法触碰 `T` 的任何私有字段或状态。
</Aside>

### 默认方法与父契约约束

定义 `Trait` 时还支持两项复用语法：

- **默认方法（Default Methods）**：在 `trait` 内直接写出方法体（如 `fn headline(&self) -> String { format!("[Breaking] {}", self.summarize()) }`），具体类型只需实现 `summarize` 即可自动获得 `.headline()`；
- **前置父契约（Supertraits，如 `trait Printable: Summary`）**：要求实现 `Printable` 的类型必须先实现 `Summary`，使 `Printable` 的默认方法可直接调用 `self.summarize()`。这不是类继承，而是对 `Self` 施加的前置约束。
