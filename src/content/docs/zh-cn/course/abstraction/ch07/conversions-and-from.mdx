上一节用 `MyFrom<T>` 演示了一对多的泛型 `Trait`。在标准库中，承担无损值转换的正式契约正是 **`From<T>`**（从 `T` 转换而来）与 **`Into<U>`**（转换为 `U`）。本节依次拆解围绕它们的三个高频问题：为什么只写 `From` 就自动拥有 `.into()`？没有同名函数重载时如何接纳多种构造参数？`?` 运算符又如何自动归并不同的错误类型？

## 一揽子实现：实现 `From` 自动获得 `Into`

标准库 `core::convert` 中两份契约的定义如下：

```rust
pub trait From<T> {
    fn from(value: T) -> Self;
}

pub trait Into<U> {
    fn into(self) -> U;
}
```

当我们为网络端点 `Endpoint` 实现 `From<&str>` 后，除了调用 `Endpoint::from("example.com")`，还能直接在字面量上写 `let ep: Endpoint = "example.com".into();`。未手写 `Into` 却自动获得 `.into()`，源于标准库内置的一段通用实现：

```rust
impl<T, U> Into<U> for T
where
    U: From<T>,
{
    fn into(self) -> U {
        U::from(self)
    }
}
```

与为单个结构体实现契约的 `impl Summary for Article` 相比，这里 `for` 后面的目标直接写成了带约束的泛型参数 `T`。<span class="rr-keypoint">这种「对满足特定约束的所有类型 `T` 批量挂载某个 `Trait`」的写法称为一揽子实现（Blanket Implementation）。</span>

- 一旦写下 `impl From<&str> for Endpoint`，约束 `Endpoint: From<&str>` 即成立，一揽子实现随即自动为 `&str` 挂上 `Into<Endpoint>`；
- 同时标准库还内置了自反一揽子实现 **`impl<T> From<T> for T`**（任意类型可无损转为自身），使 `Endpoint` 自身也天然满足 `Into<Endpoint>`。

<Aside type="tip" title="只手写 From，不手写 Into">
由于标准库已通过一揽子实现桥接了 `From` 与 `Into`，为自定义类型编写必定成功的转换逻辑时**只实现 `From`**，调用方便可同时使用 `Target::from(src)` 与 `src.into()`。
</Aside>

## 用 `<T: Into<Target>>` 兼容多种构造参数

在 C++ 或 Java 中，若希望 `connect` 函数同时接纳域名字符串 `"example.com"`、带端口元组 `("127.0.0.1", 8080)` 与现成的 `Endpoint` 实例，通常要编写三个同名重载函数。

## `?` 运算符的跨错误类型归并

掌握 `From<T>` 后，即可补齐[错误即数据：`Result<T, E>` 与 `?` 短路传播](/types/result-and-try/)留下的跨模块错误转换环节。

当顶层函数 `parse_positive_double(raw: &str) -> Result<u32, AppError>` 内部调用返回 `ParseIntError` 的 `raw.parse::<u32>()?` 时，`?` 在 `Err(e)` 分支展开的代码实际调用了 `From::from`：

```rust
let n = match raw.parse::<u32>() {
    Ok(v) => v,
    Err(e) => return Err(<AppError as From<ParseIntError>>::from(e)),
};
```

其中 `<AppError as From<ParseIntError>>::from(e)` 是**完全限定语法（Fully Qualified Syntax）**，用于明确指定调用 `AppError` 身上哪一份 `Trait` 实现（遇到多份 `Trait` 方法重名时同样靠该语法消歧）。因此，只需为顶层错误 `AppError` 实现 `From<ParseIntError>`，即可打通 `?` 的自动错误归并：
