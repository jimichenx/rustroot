---
title: 泛型、Trait 与函数式组合
description: 从编译期单态化与 Trait 契约出发，理解 Rust 如何为不同类型表达共同行为，并将所有权三件套合流到动态分发、迭代器与闭包中。
---

前两篇拆解了单个具体类型的内存表示与安全约束：用结构体（`struct`）表达「且关系」的积类型，用枚举（`enum`）表达「或关系」的和类型，并在编译期拦截悬垂引用与空指针。

进入稍具规模的项目后，下一个问题随即浮现：**当十几种不同的具体类型需要走同一套处理流程、或对外提供同一组行为契约时，在没有类继承（`class extends`）的 Rust 里，代码如何组织？**

本篇从「类型元信息存放在哪里」出发，分三章推进：

- **[泛型与 Trait 契约](/abstraction/generics-and-traits/)**：将泛型参数 `<T>` 还原为编译期按需生成机器码的单态化机制，用 `Trait` 挂载跨类型契约、转换视图与孤儿规则，看清极小内核如何与标准库分工；
- **[静态分发、动态分发与多态选型](/abstraction/dispatch-and-architecture/)**：定位静态单态化的运行时边界，拆解 16 字节虚表胖指针 `dyn Trait` 与 `dyn` 兼容性，确立闭合 `enum` 与开放 `Trait` 的架构选型判据；
- **[迭代器与闭包](/abstraction/iterators-and-closures/)**：剥开 `for` 循环与 `|x| ...` 闭包的语法糖外壳，看所有权接收者三件套、关联类型与单态化如何合流为零成本的函数式流水线。

智能指针的内部清理机制与跨函数生命周期参数留待下一篇展开；本篇专注把跨类型的抽象契约与多态成本算清。
