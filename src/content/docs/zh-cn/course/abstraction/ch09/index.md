在其他语言中，`for` 循环通常是开篇即讲的基础语法，闭包（Lambda 表达式）也常被当作黑盒语法糖使用。本指南将它们放在本篇收官章拆解，是因为一旦动手编写 Rust 的循环与闭包，就会遇到靠死记口诀无法解释的现象：为什么 `for x in v` 会移走整个集合，而 `for x in &v` 会让左边的 `x` 自动变成引用 `&T`？为什么一个匿名闭包会分化出 `FnOnce`、`FnMut`、`Fn` 三种不同的契约？

剥开外壳后可以看到，语言内核为 `for` 循环与闭包做的事情极少；真正支撑它们的，正是前序章节建立的**独立类型身份、接收者三件套（`self` / `&self` / `&mut self`）、`Option<T>`、关联类型、一揽子实现与编译期单态化**的合流。

本章分三步推进：

- **`for` 循环与遍历三件套**：认识标准库 `IntoIterator` 与 `Iterator` 契约，看清内核如何仅靠 4 行机械展开，配合 `Vec<T>`、`&Vec<T>`、`&mut Vec<T>` 三个独立类型打通三种遍历模式，并在编译期拦截遍历中扩容修改（`E0502`）。
- **闭包、匿名 `struct` 与 `Fn` 家族**：将每个闭包表达式还原为编译器自动合成的匿名结构体，由接收者三件套直接推出 `Fn`、`FnMut`、`FnOnce` 的包含层级，厘清捕获方式（`move`）与调用能力两轴正交的选型规则。
- **迭代器适配器链、组合子与零成本抽象**：将游标与闭包串联为惰性栈上结构体流水线，核对「泛型单态化 + 优化器内联」如何将其编译为与手写循环一致的机器码，掌握 `Option` / `Result` 组合子及代码审查中的冗余分配拦截。

读完本章，你应当能独立回答以下问题：

1. `IntoIterator::into_iter(self)` 的接收者写死了按值接收 `self`，为什么写 `for x in &v` 时既没有移走 `v`，又让循环变量 `x` 自动变成了 `&T`？
2. 为什么要拆出 `IntoIterator`（生成游标）与 `Iterator`（推进游标）两个 `Trait`，直接让 `Vec<T>` 实现 `Iterator` 会遇到什么障碍？
3. 写下闭包 `|x| x + base` 时，编译器在底层生成了什么结构？为什么带 `move` 按值捕获 `String` 的闭包仍可能实现可多次只读调用的 `Fn`？
4. 为什么 `.iter().filter(...).map(...).sum()` 在运行时既不分配每一步的中间数组，也没有虚表或函数指针跳转开销？
