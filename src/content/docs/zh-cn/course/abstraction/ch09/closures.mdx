## 捕获变量存放在哪里：匿名 `struct` 合成

普通 `fn` 函数必须显式标注类型且不能直接读取外部局部变量；**闭包**则是参数写在两条竖线 `|...|` 之间的匿名可调用表达式（无参写作 `|| expr`，参数与返回类型通常由上下文自动推断），并且可以直接**捕获（Capture）**定义处作用域内的外部变量：

```rust
let base = 10;
let add_base = |x: i32| x + base;
println!("{}", add_base(5));
```

顺着栈与堆模型追问：普通不捕获环境的函数指针 `fn(i32) -> i32` 只是 8 字节机器码地址；而在没有垃圾回收器暗中分配堆环境对象的 Rust 里，被 `add_base` 捕获的 `base` 存放在哪里？

答案直接复用[结构体（`struct`）](/types/structs/)与[方法接收者三件套与自动解引用](/types/methods/)：**每写下一个闭包表达式，编译器就在编译期当场合成一个独一无二的匿名 `struct` 类型，把捕获的外部变量存为结构体字段，再将闭包体生成为该结构体上的调用方法：**

```rust
struct __Closure_1<'a> {
    base: &'a i32,
}

impl<'a> __Closure_1<'a> {
    fn call(&self, x: i32) -> i32 {
        x + *(self.base)
    }
}

let add_base = __Closure_1 { base: &base };
```

看清「闭包实例就是携带捕获字段的普通栈上匿名结构体」后，两项基本特征立即可核对：

1. **栈大小等于捕获字段大小之和（无额外对象头）**：未捕获外部变量的空闭包 `|x: i32| x + 1` 等同于单元结构体，占 **0 字节**；借用两个 `i32` 占 **16 字节**（两个 `&i32`）；按值持有一个 `String` 则占 **24 字节**；
2. **每个闭包拥有独立的匿名类型**：如同手写两个同字段结构体互不兼容一样，每处闭包表达式都会生成独立的类型（报错中记作 `{closure@src/main.rs:12:14}`）。由于源码中写不出该内部名字，函数接收或返回闭包时均通过下方的 **`Fn` 家族 `Trait`** 声明约束。

## 接收者三件套投射：`Fn`、`FnMut` 与 `FnOnce`

既然调用闭包 `f(args)` 就是调用匿名结构体上的方法，方法接收者便只有[方法接收者三件套与自动解引用](/types/methods/)确立的三种形态——`&self`、`&mut self` 与 `self`。标准库的三个闭包 `Trait` 正是这三种接收者的 1:1 映射（经 `#[lang]` 钩子与调用语法 `f(...)` 绑定）：

```rust
pub trait FnOnce<Args> {
    type Output;
    fn call_once(self, args: Args) -> Self::Output;
}

pub trait FnMut<Args>: FnOnce<Args> {
    fn call_mut(&mut self, args: Args) -> Self::Output;
}

pub trait Fn<Args>: FnMut<Args> {
    fn call(&self, args: Args) -> Self::Output;
}
```

不写 `move` 时，编译器按闭包体内部对外部变量的实际操作，依最小权限原则自动决定字段类型与实现的最高契约：

| 闭包体对捕获变量的动作 | 默认合成字段 | 方法接收者 | 实现的最高契约 | 调用限制 |
| --- | --- | --- | --- | --- |
| **只读访问**（`|| text.len()`） | `&T` | **`&self`** | **`Fn`**（兼满足 `FnMut`、`FnOnce`） | 可任意多次共享调用 |
| **修改内容**（`|| count += 1`） | `&mut T` | **`&mut self`** | **`FnMut`**（兼满足 `FnOnce`） | 可多次顺序调用（闭包绑定须声明 `let mut`） |
| **移出所有权**（`|| text`） | `T` | **`self`** | 仅 **`FnOnce`** | **仅能调用一次**（调完后闭包实例失效，再调报 `E0382`） |

留意前置父契约声明 `Fn: FnMut` 与 `FnMut: FnOnce`：三者构成 **`Fn` ⊆ `FnMut` ⊆ `FnOnce`** 的单向包含关系——只要求按值调用一次（`FnOnce`）的接口，传入支持只读多次调用的 `Fn` 或可变调用的 `FnMut` 均能胜任；反之向要求 `Fn` 的接口传入消耗型 `FnOnce` 则报 `E0525`。

## 两轴正交：`move` 捕获与 `Fn` 调用互不决定

若想在函数内构造闭包并将其作为返回值传出（或交给后台线程），默认捕获引用 `&prefix` 会在原函数栈帧销毁时变成悬垂引用（报 `error[E0373]`）。此时需在参数列表前加上 **`move`** 关键字，强制编译器在创建闭包时将捕获变量**按值移入**匿名结构体字段：

观察上面的输出：`make_greeter` 返回的 `move` 闭包在栈上占 `24B`（按值内联持有了 `prefix: String`），但依然满足 `F: Fn(&str) -> String` 并被连续调用了两次。<span class="rr-keypoint">`move` 只决定创建闭包时变量如何进入匿名结构体字段；而闭包实现 `Fn`、`FnMut` 还是仅实现 `FnOnce`，只取决于调用时闭包体内部代码如何使用这些字段。</span>`make_greeter` 内的闭包体只读取 `self.prefix`（只需 `&self`），因此即使带了 `move`，它依然是支持多次调用的 `Fn`。

## 高阶函数与回调签名选型

设计接收闭包的接口或审查代码时，按以下两项准则裁决：

| 函数内部如何调用参数闭包 `f` | 参数约束选型（就宽不就窄） | 标准库签名印证 |
| --- | --- | --- |
| **最多只调用一次**（初始化、错误回退、单次任务） | **`F: FnOnce(...)`**（最宽，接纳全部三种闭包） | `Option::unwrap_or_else<F: FnOnce() -> T>` |
| **循环顺序调用多次**（允许调用方顺带更新局部计数） | **`F: FnMut(...)`**（兼容 `FnMut` 与 `Fn`） | `Iterator::map<B, F: FnMut(Self::Item) -> B>` |
| **经 `&F` 并发共享调用或重入调用** | **`F: Fn(...)`**（最严，仅在确需共享只读时使用） | 多线程并发只读处理器 |

此外注意区分 `Fn` 契约与小写的原生**函数指针类型 `fn(i32) -> i32`**（占 8 字节代码地址，仅普通函数及 0 字节无捕获闭包可转入）：常规传参优先用静态泛型 `<F: FnMut(...)>` 以保留内联优化；仅当需在 `Vec` 中混装多个不同闭包或运行期动态替换回调时，才使用 16 字节胖指针 `Box<dyn Fn(...)>`（审查单次回调参数时若见到 `Box<dyn Fn(...)>`，应改为泛型 `F: FnOnce(...)` 消除堆分配）。
