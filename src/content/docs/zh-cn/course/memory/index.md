---
title: 内存与所有权
description: 从栈与堆的自动释放问题出发推导所有权与借用模型，再用变量声明、赋值和遮蔽的 Rust 代码核对释放责任。
---

你可能已经会写另一门语言，也可能刚写了一阵 Rust。所有权、移动、引用、生命周期这些词，单独看都懂，放在一起却像一套要背的禁令：为什么给 `String` 赋值会让旧变量失效，为什么把值传给函数之后调用方就不能再用，为什么引用不能活过它的所有者。

这一篇不急着给你背条文。Rust 想在不引入垃圾回收（GC）、也不靠人手写 `free` 的前提下保证内存安全，这些看似严苛的规则，都是被这一个目标从物理内存里逼出来的。我们会先把这层物理底图补回来：一次函数调用在栈上留下什么，堆上动态申请的数据在返回后去了哪，栈帧、堆块与地址之间是什么关系。

如果你从 Java、Python 或 Go 来，这层意识往往是空的——并不是底层的栈与堆不存在，而是运行时用 GC 替你兜住了释放细节，平时不用去想它；到了 Rust，释放责任不再交给后台运行时，而是要求你自己看懂。

这一篇不展开类型系统，也不碰可变引用、并发和 `unsafe`。类型怎么接住这些规则、读写权限怎么分工、多个所有者怎么共享，都留到后续篇章。

这一篇分两章。[从自动释放到所有权](/memory/ownership/)不引入语法负担，从栈与堆推演出自动释放模型；[变量与赋值](/memory/variables/)再把模型落进真实的 Rust 代码里，逐一核对声明、重新赋值与同名遮蔽下的释放责任。

读完这一篇，面对一段普通单线程代码里的赋值、传参或借用报错，你应该不再只能靠试错应付编译器，而是能从内存与释放责任上看出它为什么成立。
