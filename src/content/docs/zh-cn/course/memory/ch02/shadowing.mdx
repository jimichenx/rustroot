## 重新赋值与同名遮蔽

原因在于底层动作不同：**每写一次 `let`，都是在栈帧上创建一个全新的变量。**

逐行拆解 `shadow.rs`，注意 `let` 语句**先计算等号右侧、再建立左侧新绑定**的求值顺序：

1. `let n = 7;`：在栈上创建**第一个变量**（类型 `i32`，值为 `7`），将名字 `n` 绑定到该变量；
2. `let n = n + 1;`：先计算等号右侧的 `n + 1`——此时新绑定尚未生效，右侧的 `n` 读取的仍是第一个变量里的 `7`，算出 `8`；随后左侧的 `let` 在栈上创建**第二个变量**（放入 `8`），并将名字 `n` 改绑到第二个变量；
3. `let n = String::from("eight");`：左侧的 `let` 在栈上创建**第三个变量**，其类型独立确定为 `String`，并非前一个 4 字节整数槽位在运行时改变了类型。

在 Rust 中，用新的 `let` 创建同名新变量、使后续同名访问使用新绑定的机制，称为**遮蔽（Shadowing）**。回看[声明与绑定](/memory/bindings/)中提到的关键字选择，用 `let` 而不是 `var` 或 `val`，在这里也显得更为顺畅：`var`（变量）与 `val`（值）作为名词，在同一作用域里连续写两次 `var n` 或 `val n`，字面上像是在重复定义同一个东西，很难讲通；而 `let` 读作「令此后出现的 `n` 绑定到这个新值」，连续写多次在语感上自然成立。

将重新赋值与同名遮蔽放在一起对照：

| 对比维度 | 重新赋值（`n = n + 1;`） | 同名遮蔽（`let n = n + 1;`） |
| --- | --- | --- |
| **操作的变量** | 同一个已有变量 | **创建全新变量**，将后续同名访问改绑到新变量 |
| **原变量是否需要 `mut`** | **需要**（否则报 `E0384`） | **不需要**（未修改原变量） |
| **类型能否改变** | **不能**，新值须匹配原变量类型 | **能**，新变量的类型独立确定 |

<Aside type="note" title="遮蔽在工程中的两类常见用途">
在日常 Rust 代码中，同名遮蔽常用于两类场景：

1. **类型转换时免去拼凑过渡变量名**：例如从配置读入字符串后再解析为整数端口，连续写两次 `let port = ...;` 即可沿用贴切的名字，同时防止后续代码误读未解析的原始字符串。
2. **初始化加工后收回可变权限**：若变量仅在构建阶段需要修改（`let mut s`），加工完毕后写一行 `let s = s;`，即可在不复制堆数据的前提下将后续访问锁定为不可变绑定。
</Aside>

## 被遮蔽的旧值何时释放

上一节看到，重新赋值 `target = source;` 会在 `=` 这一行当场释放旧值。如果在同一层作用域里先写 `let s = String::from("hello");`，紧接着写 `let s = 7;` 遮蔽它——后续代码已无法再通过名字 `s` 访问旧字符串，那块 `"hello"` 堆缓冲区会在 `let s = 7;` 当行释放吗？

可以用引用实验直接验证：在第一个 `s` 被遮蔽前，先用 `let r = &s;` 借用它的地址；等 `let s = 7;` 遮蔽发生后，再顺着 `r` 读取。若旧 `String` 在遮蔽行就已经释放，`r` 必然成为悬垂引用并被借用检查器拦截：

<small class="code-source">源文件：<code>examples/memory/variables/src/bin/shadow-reference.rs</code></small>
<Code code={reference} lang="rust" />

程序顺利通过编译，输出 `hello 7`。

<ShadowCoexist />

这一结果验证了遮蔽在栈与堆上的真实行为：

1. **遮蔽不会使旧变量失效，也不会立即释放旧值。**
2. 执行 `let s = 7;` 后，当前栈帧上**并存着两个独立的变量**：旧变量（`String`）仍在栈槽位中持有 `"hello"` 的三格控制头，新变量（`i32`）占用另一处 4 字节栈槽位。
3. `let s = 7;` 只把源码后续出现的名字 `s` 改绑到新变量上。此前建立的引用 `r` 仍指向旧变量的栈地址，其有效区间（持续到 `println!` 那一行）完全落在旧变量的存活区间之内（对照[悬垂引用](/memory/lifetimes/)的区间比对规则）；旧变量管理的 `"hello"` 堆缓冲区一直保留到 `main` 结尾的 `}` 闭合时才自动释放。

在 `let s = s;` 这一行中，遮蔽与移动同时发生：等号右侧先读取旧变量 `s`，由于 `String` 未实现 `Copy`，控制头与释放责任**移动**给左侧新创建的变量 `s`。此时旧变量确实在编译期状态表中变为已失效，但令它失效的原因是右侧发生了移动，而非左侧的同名 `let`；到 `main` 结尾的 `}` 处，仅由接手责任的新变量释放一次 `"hello"`。

## 本章总结与综合验收

汇总本章三节，分析任意一行 `let` 与 `=` 时只需核对三项动作与状态：

| 语法形式 | 底层动作 | 对旧变量与堆内存的影响 |
| --- | --- | --- |
| **首次绑定**（`let b = a;`） | 创建新变量并接手初值 | 实现 `Copy` 则按位复制；未实现 `Copy` 则**移动**（原变量失效，责任转移）；加 `&` 则为**借用**（不转移责任） |
| **重新赋值**（`x = new_val;`） | 更新同一个已有变量（需 `let mut`，不可换类型） | 若 `x` 当前持有有效移动值，**在 `=` 当行先释放旧值**再接手新值；若值已移出或尚未初始化，直接写入新值 |
| **同名遮蔽**（再次 `let x = ...;`） | 创建同名新变量，改绑后续名字指向（无需 `mut`，可换类型） | **旧变量不立即释放**，与新变量在栈帧上并存，仍等到所属作用域的 `}` 闭合时释放（除非右侧将旧值移走） |

3. 到 `main` 结尾的 `}` 闭合时，由哪一个变量负责释放 `"first"`？

<details>
<summary>点击核对逐行推演</summary>

1. **三次打印输出**：依次为 `second`、`7 first`、`first`。
2. **外层前四句（移动与空置重填）**：
   - `let mut s = String::from("first");`：外层 `s` 持有 `"first"`；
   - `let t = s;`：将 `"first"` **移动**给 `t`，`t` 接手释放责任，外层 `s` 记为值已移出；
   - `s = String::from("second");`：向已移出的外层 `s` 写入新值（不触发释放），外层 `s` 恢复有效并持有 `"second"`，第一次打印输出 `second`。
3. **内层 `{}` 块（借用与块内遮蔽）**：
   - `let r = &t;`：借用 `t`（指向 `"first"`）；
   - `let s = 7;`：在内层块创建新整数变量 `s`，暂时遮蔽外层字符串变量 `s`，第二次打印输出 `7 first`；
   - 内层 `}` 闭合：退场的只有内层整数 `s` 与引用 `r`，外层 `s` 仍在作用域内，**`"second"` 不会在内层 `}` 处释放**。
4. **外层最后三句（覆盖释放与同名移动）**：
   - `s = t;`：外层 `s` 此时持有有效的 `"second"`，重新赋值时 **`"second"` 在这一行当场释放**；同时 `t` 持有的 `"first"` 移入外层 `s`（`t` 失效）；
   - `let s = s;`：创建同名新变量 `s`，将外层旧 `s` 持有的 `"first"` **移动**给新变量 `s`。最终在 `main` 结尾的 `}` 处，由这最后一个新变量 `s` 释放 `"first"`。

</details>

随后在 `review.rs` 中做一处改写验证：将内层块里的 `let s = 7;` 改为不带 `let` 的 `s = String::from("third");`。去掉 `let` 后，内层语句不再创建新变量，而是直接对外层可变变量 `s` 执行重新赋值——外层 `s` 原先持有的 `"second"` 提前在内层赋值行当场释放，改持 `"third"`（第二次打印变为 `third first`）；后续执行外层 `s = t;` 时，当场被替换释放的就变成了 `"third"`。

### 动手编写：可变加工后锁定只读

最后在任意示例的 Playground（或本地 `src/main.rs`）中，从零写出几行 `fn main()` 代码完成以下三步：

1. 创建持有堆上文本 `"draft"` 的字符串变量 `doc`，并调用 `.push_str(" v1")` 向末尾追加版本号；
2. 加工完成后，在不额外申请堆内存（不调用 `.clone()`）的前提下，继续沿用变量名 `doc` 并将它收紧为不可变绑定（若后续误写 `doc.push_str(" v2")` 会被编译器以 `E0596` 拦截）；
3. 用只读借用 `preview` 指向锁定后的 `doc`，同时打印 `doc` 与 `preview`。

<details>
<summary>点击核对参考实现</summary>

```rust
fn main() {
    let mut doc = String::from("draft");
    doc.push_str(" v1");

    let doc = doc;
    // doc.push_str(" v2"); // 若取消注释，因新变量未声明 mut 而报 E0596
    let preview = &doc;
    println!("{doc} | {preview}");
}
```

`let doc = doc;` 在编译期创建不可变的同名新变量，并将旧 `doc` 的三格控制头连同释放责任移动给新变量，全程只有最初那一块堆缓冲区；随后 `preview` 只借用新 `doc` 的栈地址，两处都能正常打印，最终在 `}` 处由新 `doc` 释放堆内存。

</details>
