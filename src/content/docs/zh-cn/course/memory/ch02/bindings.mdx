### 变量声明、初始化与为什么叫「绑定」

在其他主流语言中，看到 `let n = 7;`，我们通常直接称之为**定义变量**。拆开看，这一行语句（以分号 `;` 结束）在底层完成了两步动作：

1. **变量声明（Declaration）**：向编译器引入局部变量名 `n`，编译器据此在当前栈帧中留出对应大小的栈槽位；
2. **初始化（Initialization）**：计算 `=` 右侧的 `7`，将初始值写入该栈槽位。

既然就是定义变量，为什么 Rust 官方文档与编译器报错里常把 `let` 称为建立**变量绑定（Binding）**，而且关键字选了 `let`（类似数学推导中的「令 `n = 7`」）而不是常见的 `var`？这里有两层直接原因：

- **默认不可变**：`var`（variable）在字面上暗示「值会随时变化」，而 Rust 用 `let` 建立的关系默认不可修改，需要修改时须显式写成 `let mut`。
- **区分「名字」与「背后的变量槽位和值」**：在许多语言里，一个局部变量名在当前作用域内始终对应同一块数据；而在 Rust 中，随着所有权流转，变量手里的资源可能被**移动**给别的变量（原变量随即失效），同一个名字也允许通过再写一次 `let` 改绑到栈上新开的另一个变量槽位上（见[遮蔽与作用域](/memory/shadowing/)）。把 `let n = 7;` 准确理解为「声明变量，并将名字 `n` 与栈上的值建立**绑定**」，后续分析移动与遮蔽时就不会把「名字」和「值」混为一谈。

### 类型标注、类型推断与终端打印

再看 `binding.rs` 里的另外三处基础语法：

- **类型标注（Type Annotation）与基础类型命名**：`let count: i32 = 7;` 在变量名后用 `: i32` 显式指明类型。Rust 的整数按「`i` 有符号 / `u` 无符号 + 比特位宽」命名（如 `i32` 占 4 字节、`u64` 占 8 字节，随平台字长变化的索引类型为 `usize`；浮点数为 `f32` / `f64`，布尔值为 `bool`）。
- **类型推断（Type Inference）**：`let n = 7;` 省略了 `: i32`，编译器会根据右侧字面量自动推算出类型（未标注的整数字面量默认推断为 `i32`，浮点字面量默认推断为 `f64`）。
- **终端打印 `println!`**：双引号内是格式字符串，`"{n} {count}"` 直接在花括号内读取同名变量，等价于位置占位符写法 `println!("{} {}", n, count);`。末尾的 `!` 表示宏调用；现阶段只需记住一条关键规则：**`println!` 内部只借用变量读取内容，不会接手所有权或把变量移走**（更多格式写法可查附录「[怎么打印变量？](/appendix/basics/printing/)」）。

这里还要明确一个编译期事实：**省略类型标注不等于没有类型，也不等于动态类型。** 编译器生成机器指令前，必须确定每个局部变量在栈帧中占多少字节、离开作用域时是否需要释放堆内存。即便省略 `: i32`，`n` 的类型在编译期也已经固定为 `i32`（更多内置基础类型见附录「[标量、元组与单元类型](/appendix/basics/scalars-and-tuples/)」）。

### 2. 字符串初始化：移动与读懂第一条编译报错

保持代码结构不变，将整数换成持有堆缓冲区的 `String`：

<Code code={move} lang="rust" />

先看第 3 行的写法：`String::from("hello")` 通过 `::` 调用 `String` 类型上的关联函数（类似其他语言的静态工厂方法），在堆上分配一块存放 `"hello"` 的字符缓冲区，并将三格控制头（堆指针 `ptr`、长度 `len`、容量 `cap`，64 位平台共 24 字节）放入栈变量 `s`。注意这里没有直接写 `let s = "hello";`——裸双引号字面量 `"hello"` 存放在可执行文件的只读数据段中，不涉及堆内存分配与释放（详见后续[字符串](/types/strings/)）；要观察堆资源的释放责任交接，需要使用 `String` 类型。

取消源码中 `// println!("{s}");` 的注释再运行，编译器会拒绝编译，并输出完整的诊断报告：

<small class="code-source">编译器输出（取消 init-move.rs 中注释行后）</small>
```text
error[E0382]: borrow of moved value: `s`
 --> src/bin/init-move.rs:5:16
  |
3 |     let s = String::from("hello");
  |         - move occurs because `s` has type `String`, which does not implement the `Copy` trait
4 |     let t = s;
  |             - value moved here
5 |     println!("{s}");
  |                ^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
4 |     let t = s.clone();
  |              ++++++++
```

这是我们在本指南中遇到的第一条 `rustc` 报错。阅读 Rust 编译错误时，重点不是背诵错误码 `E0382`，而是顺着源码下方的横线（`-`）与箭头（`^`）标注看清前因后果——这三处标注正好完整回放了[复制与移动](/memory/minimal-model/)建立的**编译期状态表**：

1. **判定依据（第 3 行标注）**：`s` 的类型是 `String`，未实现 `Copy` Trait（Trait 是编译期行为契约）。在真实的 Rust 编译器中，静态检查区分复制与移动的唯一判据就是**类型是否实现 `Copy`**：`i32`、`bool` 等标量实现了 `Copy` 走复制语义，`String` 未实现 `Copy` 一律走移动语义。
2. **责任转移（第 4 行 `value moved here`）**：执行 `let t = s;` 时，运行时只将 `s` 的 24 字节控制头按位复制给 `t`（`s` 的栈槽位仍留在当前栈帧中，生成最终机器码时编译器还可优化掉这次栈复制）；编译期状态表将堆缓冲区的释放责任转归 `t`，并把 `s` 记为**已失效**。
3. **违规拦截（第 5 行 `value borrowed here after move`）**：`println!` 内部只借用变量读取内容（因此第 6 行打印 `t` 不会把 `t` 移走），但此时状态表里 `s` 已经失效，借用检查器当场拦截对 `s` 的借用。

<StringMove />

同时留意诊断末尾的 `help` 提示：编译器指出若能接受性能开销，可以改写为 `let t = s.clone();`——`.clone()` 会在堆上重新申请一块内存并把 `"hello"` 的字节完整复制一份，让 `s` 和 `t` 各管各的堆缓冲区。但如果新变量只是为了读取数据，盲目按提示加 `.clone()` 就会付出多余的堆分配成本；此时应当使用不复制堆数据的借用。

### 3. 只使用数据而不转移责任：借用

<small class="code-source">源文件：<code>examples/memory/variables/src/bin/init-reference.rs</code></small>
<Code code={reference} lang="rust" />

程序顺利编译，输出 `hello hello`。

观察第 3 行 `let r: &String = &s;`，符号 `&` 在等号两侧出现两次，承担不同的语法职责：

- **等号右侧的 `&s`（借用运算符，不可省略）**：执行**借用（Borrowing）**动作——不移走 `s` 的控制头，而是取出 `s` 的栈地址，构造一个占 8 字节、剥离了释放责任的只读引用赋给 `r`。若漏写右侧的 `&` 写成 `let r: &String = s;`，编译器会因类型不匹配而报错。
- **冒号后的 `: &String`（引用类型标注，可省略）**：标明 `r` 的类型是「指向 `String` 的只读引用」；日常代码中通常直接简写为 `let r = &s;`，由编译器自动推断出 `&String`。

因为释放责任留在原变量 `s` 上，`s` 保持有效，堆上的字符缓冲区仍由 `s` 在离开 `main` 的 `}` 时释放（且只读引用 `&String` 自身实现了 `Copy`，可按位复制给多处读取）。

## 三种初始化对照与核对

将本节三种首次绑定语句放在一起对照：

| 初始化语句 | 等号执行的动作 | 原变量是否仍有效 | 堆缓冲区的释放责任 |
| --- | --- | --- | --- |
| `let b = a;`（`a: i32`） | **复制**：按位复制栈上 4 字节（`i32` 实现 `Copy`） | 有效 | 无堆缓冲区 |
| `let t = s;`（`s: String`） | **移动**：复制控制头，转移释放责任（`String` 未实现 `Copy`） | **已失效（读取报 `E0382`）** | 转移给新变量 `t` |
| `let r: &String = &s;` | **借用**：取 `s` 的栈地址，不承担释放责任 | 有效 | 留在原变量 `s` |

### 动手核对

在 `init-move.rs` 的 Playground 中，将 `let t = s;` 改为 `let t = &s;`，并取消 `println!("{s}");` 的注释。运行前先对照上表确认两点：

1. 加上 `&` 后，编译器为 `t` 推断出的类型变成了什么？
2. 为什么 `s` 不再触发 `error[E0382]`，堆上的 `"hello"` 最终由谁释放？

核对结果：右侧改为 `&s` 后执行的是借用，`t` 的类型推断为 `&String`。借用不转移释放责任，`s` 在编译期状态表中保持有效，两行打印均输出 `hello`，堆缓冲区仍由 `s` 在离开 `}` 时释放。

本节所有的 `=` 左侧都带有 `let`，属于在创建新变量的同时放入初始值。如果变量已经创建完毕，后续不写 `let`、直接用 `s = ...` 给已有变量换入新值，它原先持有的堆内存会如何处理？下一节继续拆解可变绑定与重新赋值。
