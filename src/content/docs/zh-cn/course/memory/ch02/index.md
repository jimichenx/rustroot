在其他主流语言里，变量声明和赋值几乎不需要专门讨论：声明一个变量，用 `=` 放入值，后续随时读取或替换。但在 Rust 里，写下前几行 `let` 和 `=` 时，就会遇到「移动后变量失效」「`Copy` 与移动」「不加 `mut` 无法调用修改方法」等编译检查。

原因在[从自动释放到所有权](/memory/ownership/)中已经推演清楚：在带垃圾回收（GC）的语言里，`=` 只复制值或对象引用，内存何时回收由运行时兜底；而在 Rust 里，每一行 `let` 和 `=` 都在编译期交接或触发**释放责任**。

本章直接打开编译器，围绕 `let` 与 `=` 分三步推进：

- **首次绑定（`let x = ...`）**：声明新变量并接手初值。从第一个可运行程序出发，核对同一个 `=` 在整数、`String` 与引用上为什么分出复制、移动与借用三条路径。
- **重新赋值（`x = ...`）**：更新同一个已有变量。拆解 `let mut` 开放的两项权限，并顺着编译期状态表回答：当新值换入时，变量原本持有的旧值去了哪里。
- **同名遮蔽（再次 `let x = ...`）**：声明同名新变量并改绑名字。对照重新赋值与遮蔽的边界，通过引用实验验证被遮蔽的旧值何时释放。

读完这一章，面对一段真实 Rust 代码，不需要死记编译器错误码，你应该能逐行回答三个问题：

1. **这是哪个动作**：这一行是在创建新变量（首次 `let`）、更新已有变量（重新赋值），还是用同名新变量遮蔽旧变量？
2. **右侧怎样交接**：等号右侧的值发生了复制、移动，还是只借用了地址？
3. **旧值何时释放**：当前哪些变量仍然有效？每一块堆内存由哪个变量负责，是在赋值那一行当场释放，还是等到作用域结束（`}`）时释放？
