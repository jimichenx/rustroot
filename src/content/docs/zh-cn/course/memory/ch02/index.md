在其他主流语言里，变量定义和赋值几乎不需要专门讨论：定义一个变量，用 `=` 放入值，后续随时读取或替换。但在初学 Rust 时，刚写下前几行代码就会遇到一连串编译拦截：为什么赋值之后原变量会突然失效，为什么声明的变量默认连内容都不允许修改。

原因在[从自动释放到所有权](/memory/ownership/)中已经推演清楚：在带垃圾回收（GC）的语言里，`=` 只复制值或对象引用，内存何时回收由运行时兜底；而在 Rust 里，每一行 `let` 和 `=` 都在编译期交接或触发**释放责任**。

本章打开编译器，从你的第一个可运行 Rust 程序开始，按日常代码里最常见的三种写法依次推进：先看用 `let x = ...` 定义新变量时的复制、移动与借用，再看用 `x = ...` 给已有变量重新赋值时的可变权限与旧值去向，最后对比再写一次 `let x = ...` 声明同名新变量时的作用域与释放时机。

读完这一章，面对一段真实 Rust 代码，不需要死记编译器错误码，你应该能逐行回答三个问题：

1. **这是哪个动作**：这一行是在定义新变量（首次 `let`）、更新同一个已有变量（不带 `let` 的重新赋值），还是声明了另一个同名新变量（再次 `let`）？
2. **右侧怎样交接**：等号右侧的值发生了复制、移动，还是只借用了地址？
3. **旧值何时释放**：当前哪些变量仍然有效？每一块堆内存由哪个变量负责，是在赋值那一行当场释放，还是等到作用域结束（`}`）时释放？
