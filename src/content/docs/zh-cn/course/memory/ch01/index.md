description: 不引入语法负担，从栈与堆的物理事实一步步推导出一套不靠 GC、也不靠人手写 free 函数的自动内存回收模型。

---

这一章要解决一个看似矛盾的问题：**如果不靠人手写每一次 `free` 函数，也不靠垃圾回收（Garbage Collection，GC）在运行时扫描或计数，程序怎样既自动回收内存，又保证内存安全？**

为了不受语法细节干扰，本章六节是一场连续的第一性原理推演——前五节不写实际的 Rust 语法，也不预先搬出「所有权」「借用」「生命周期」这些术语，而是站在模型设计者的视角，顺着每次遇到的安全缺口一步步把规则逼出来；最后一节再将这套机制与 Rust 的标准概念逐一对位。

六节分三段推进：

- **第一段：摆出问题与内存底图。** 先从困难三角确立「自动回收、但非 GC」的切入方向，再建立栈与堆的物理底图：栈帧随函数返回自动收回，只有堆上动态申请的资源需要单独释放，而持有堆地址的栈变量恰恰有确定的作用域终点（`}`）。
- **第二段：从旧变量失效到移动语义。** 先立下「栈变量离开作用域就释放堆」的最简规则，随即用一行赋值 `t = s` 测出双重释放冲突；为守住模型正确性先打上「旧变量失效」的补丁，再将它重塑为符合人类直觉的移动语义，并掀开硬件只做栈字节复制、状态交接全在编译期完成的物理真相。
- **第三段：从受限指针到自动插入 `free` 函数。** 为解决按值传参把实参移走的困境，顺着传递 8 字节内存地址（指针）的思路，剥离 C 语言裸指针的越权能力，设计出受限指针——引用；再针对原变量先退场留下的悬垂引用，把防线前移到编译期比对有效区间；最后对位所有权与借用，看清整套规则的共同目标：让编译器在正确的位置自动插入 `free` 函数。

读完这一章，不需要背诵任何语法条文，你应该能自己推清楚三件事：

1. 为什么栈上的局部变量随函数返回自动收回，而堆资源必须有人负责归还？
2. 为什么同样是一行赋值 `=`，整数走复制语义，管理堆资源的动态字符串却必须从「旧变量失效」重塑为移动语义，而硬件底层并没有真的搬走数据？
3. 为什么物理上同样是 8 字节地址的引用可以自由复制共享，却必须由编译器在编译期限制它的有效区间？
