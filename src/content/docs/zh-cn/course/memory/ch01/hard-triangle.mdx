学一门新语言之前，先问一个起点问题：世界上已经有 C、C++，也有 Java、Python、Go，为什么还要设计 Rust？

答案落在它的首要设计目标上：**同时拿到贴近硬件的运行性能与内存安全。**在此之前，这两件事长期处于二选一的拉扯中。你在 Python、Java、JavaScript 里写下一行对象赋值 `b = a`，两个变量就同时指向了内存里的同一个对象，不需要写释放代码，程序也能安全跑下去——语言把内存管理成本转交给了运行时；而在 C、C++ 里，代码直接贴着硬件运行，却要由程序员自行安排释放、防范内存错误。

要看懂 Rust 的设计目标，以及它为此付出了什么代价，需要先回到编程语言设计的底层取舍，从三个相互制约的指标看起：

- **性能（Performance）**：代码以多低的开销在硬件上运行；
- **安全（Safety）**：程序能否避免访问已失效的内存、读写越界等内存错误；
- **表达力（Expressiveness）**：既指高层抽象能力，也指写代码时受多少限制、有多大自由度。

这三者之间的取舍，我们称为编程语言的**困难三角**。它不是非此即彼的开关，而是程度问题——侧重其中两项，第三项就要多付代价。

本节先聚焦 Rust 最先要攻克的**安全与性能**这一条边：内存由谁释放、在何时释放。

## 安全与性能：内存由谁在何时释放

这条边的分歧在于：内存在什么时刻释放，这个时刻由谁决定。现成的做法分两类：

- **交给写代码的人（C / C++ 手动管理）**：`free` 或 `delete` 写在哪一行，内存就在哪一行释放，运行时不需要扫描或计数。代价落在安全上——释放后继续访问，或者对同一块内存释放两次，都会造成内存错误。C++ 的 RAII 和智能指针也能按作用域自动释放，但编译器通常不检查代码是否继续访问已经释放的数据。
- **交给运行时（Java / JavaScript / Python / Go）**：由运行时的回收机制找出不再使用的内存并释放。Java、JavaScript、Go 采用追踪式垃圾回收（Tracing GC），在后台扫描对象可达性，释放时刻通常不确定，高并发下可能带来停顿或延迟抖动；CPython（常用的 Python 实现）以引用计数为主，多数对象在计数归零时即时释放，循环引用仍交给分代 GC 处理。

把两类做法放在一起对照：

| 维度 | 运行时回收（Java / JavaScript / Python / Go） | 手写释放（C / C++ 手动管理） |
| --- | --- | --- |
| **释放时刻** | 追踪式垃圾回收通常不确定；CPython 的引用计数多数即时 | 写下 `free` / `delete` 的那一行 |
| **侧重** | 安全与共享自由度：多处共享对象时不必手动协调释放 | 运行时性能与确定性 |
| **代价** | 扫描或计数的 CPU 与内存开销、停顿、延迟抖动 | 需要人保证不在释放后继续访问、不释放两次、不遗漏释放 |
| **生产环境典型隐患** | 吞吐量下降、尾延迟毛刺、内存占用偏高 | 进程崩溃、数据损坏，或因遗漏释放导致内存持续增长 |

## 另外两条边：抽象开销与底层权限

困难三角的另外两条边同样贯穿语言设计：

- **性能与表达力**：高层抽象是否增加运行时步骤。Python 里的 `a + b` 需要在运行时根据对象类型分派加法逻辑；C 里两个 `int` 相加可以直接编译为机器加法指令。高层抽象不一定带来运行时开销，取决于多少检查与展开能在编译期完成。
- **安全与表达力**：给写代码的人开放多大的底层权限。能直接操纵的内存地址越自由，编译器在运行前能证明的安全性质就越少。C 允许把任意整数转成指针直接写入，编译器无从判断目标地址是否有效；Java 不开放指针运算，并在运行时检查数组下标越界。

这两条边留待后续篇章展开，本章只攻克「内存何时释放」这一条边。

## Rust 的切入点：自动回收，但非 GC

前面的两类主流做法都在做二选一：要安全，就接受 GC 的运行时成本；要性能，就由人手写释放并承担出错风险。

如果把「由谁决定释放」和「是否依赖运行时回收器」交叉成四个象限，只有左下角这一格同时满足**自动回收（非手动）**与**无运行时回收器（非 GC）**——Rust 选择的正是这一格。

<ReleaseGrid />

顺着这一格往下想，立刻会遇到一个表面上的矛盾：写代码的人不写 `free`，程序跑起来又没有回收器在后台扫描或计数，程序怎么知道一块内存什么时候不再使用、该在哪一行释放？

正因为这两件事在直觉上难以兼顾，主流语言往往把「自动回收」直接等同于「引入 GC」。Rust 选择走通左下这一格，而困难三角的制约并未消失：当安全与性能都不让步时，代价就会转移到第三项——**编译期对代码写法的约束**。

在不靠人手写、也不靠运行时盯梢的前提下，怎样算出一块内存的释放时机？下一节我们先看程序运行时的内存分成哪两块，弄清释放难题究竟出在哪一块上。
