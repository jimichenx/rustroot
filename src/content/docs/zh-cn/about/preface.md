## 为什么从原理出发

学习 Rust 时，你可能已经记住了所有权和借用的规则，却仍然不清楚编译器为什么拒绝一段代码，也不知道该修改借用方式还是调整数据的组织方式。

Rust Root 是一份开源 Rust 指南。我们从具体问题和基本约束出发，结合代码实验，解释 Rust 的规则与设计取舍，帮助你建立分析代码和解决问题的思路。

本指南希望帮助你理解一条规则解决什么问题、在哪些条件下适用；遇到编译错误时，能找到相关的约束；设计接口或审查代码时，能比较所有权、运行时成本和错误处理方式。

## 我们怎样解释 Rust

本指南借鉴第一性原理的思路：先看程序要解决的问题和需要遵守的约束，再考察一种方案会遇到什么问题，以及 Rust 如何处理。代码实验和编译器反馈帮助我们核对这些判断。

这不意味着 Rust 的所有设计都能从基本事实中推导为唯一答案。语言设计也包含不同方案之间的取舍、历史选择和约定。我们会区分 Rust 的语言保证、为了讲解而简化的模型，以及需要结合场景判断的工程建议。

例如，编译器可以通过类型检查和借用检查排除一部分错误，但编译通过不等于业务逻辑正确，也不保证代码符合性能要求。无论代码由人编写还是由 AI 生成，都需要结合需求、测试和实际成本进行判断。

## 怎样阅读

主线从所有权、类型和抽象等问题出发，交替使用解释与代码实验。建议从第一篇开始，后续内容会复用前面建立的判断。

[附录](/appendix/)提供基础语法、机制详解、跨语言对照和工程排障速查，遇到需要核对的内容时可以按需查阅。本指南不以列举全部 API 为目标，具体接口的完整说明仍需参考 Rust 文档。

建议先掌握一门编程语言，不要求有 Rust 基础。你也可以在已经写过一些 Rust、希望理解编译错误或接口设计时，从相关章节开始阅读。
