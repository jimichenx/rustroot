按最简模型推演：传参就是一次赋值，形参接手释放责任；函数返回，形参离开作用域，堆被释放；回到调用处，原来的变量已经失效。取消 `main` 里最后一行的注释，编译，报 `error[E0382]`。

和上一课 `t = s` 之后用 `s` 是同一个错误码。不是巧合：在模型里，传参就是一次移动。一个只想读一眼的函数，把调用方的值弄没了。

## 诊断：模型里只有一种交法

问题不在函数贪心，在模型只给了一种交法。

函数想要的是「用一下」。模型交数据的唯一方式，是把释放责任一起交出去——一个值只有一种身份：被一个变量拥有。没有「只拿地址用一下」这个位置，「用」和「拥有」被绑死在同一个动作上。

要修，就得给「用」另立一个位置。

## 修：只传地址，责任留下

能想到的修法有两个。

**连堆一起复制。** 给函数一份完整的副本，调用方保住自己的。代价上一课算过：一次读操作，背着整块堆的复制。性能这笔账不允许，这里同样不允许。

**只把地址传过去。** 堆不动，所有权留在原来的变量上。函数拿着地址用，用完就走，不碰释放责任。

第一条路是最简模型已经否掉的深拷贝：性能。选第二条。

传过去的地址不能是裸的。C 的指针就是一个地址，编译器不检查它指向的东西还在不在，也不管谁负责释放。我们要的地址，带两条限制：

1. 它指向的数据必须仍然有效；
2. 它不承担释放责任。

满足这两条的这个值，叫**引用（Reference）**。`&s` 就是在造一个引用：把数据的地址交出去用一段时间，所有权和释放责任都留在原来的变量上。

引用记的就是这件事：地址给你用，责任还在我。

## 引用指向哪里

写代码之前，先把一件事说清楚：`&s` 里的地址，到底是什么地址？

前面看过的 `String` 布局：栈上三个机器字——指针、长度、容量；字符数据在堆上。`&s` 取的是**栈上那个 `String` 结构体**的起始地址，不是堆上字符缓冲区的地址。

<ReferencePoints />

顺着 `&s` 读数据要两跳：先到栈上的 `String` 结构体，再顺着 `ptr` 字段到堆上的字符。

`let r = &s;` 之后，`r` 是一个普通的变量，类型是 `&String`，在栈上占一个机器字，装着这个地址。引用本身是值：有类型，有大小，能赋给变量，能传来传去——这一点后面马上要用到。

为什么拿着地址，却不负责释放？释放需要的恰恰只是地址——C 的 `free` 拿到一个地址就能归还堆，「保存的只是地址」根本挡不住释放。挡住的是责任：责任只有一份，跟着所有权走，不跟着地址走。地址可以抄给任意多个引用，责任抄不动。持有地址，不等于持有责任。

这和 C、Java 的直觉不同。C 的 `char*` 直接指向字符数据；Java 的引用直接指向堆上的对象。Rust 的 `&String` 指向的是栈上的管理结构。第二篇讲 `&str` 和 `&String` 的区别时，这个两跳结构会重新出现。

## 只读是默认

从引用的两条限制往下推。

引用不负责释放，数据的生死仍归所有者管。引用能做的事，是顺着地址读。读不改数据：一个引用在场，不妨碍别的引用读同一块数据。多个引用可以同时指向一块数据，共享不需要任何额外机制。

假如引用能改呢？读的人刚看过数据的样子，写的人转身把它改了，接下来读到的和刚看的对不上；更糟的是，容器放不下时会换一块新的堆，别的引用还指着旧地址。共享和可写，不能同时成立。

两个都要，就都得不到。默认给用得多的那个：读。所以引用默认只读，写成 `&T`——共享、只读、不负责释放。

## 要改，就独占：`&mut T`

函数确实要改数据时，还是传引用，但共享必须让位：同一块数据上，要么多个只读引用同时在场，要么一个可变引用独占在场，不能重叠。

这套分工，读写锁（Read-Write Lock）也是这么分的：读共享，写独占。落回这三种身份：

| | 能读 | 能改 | 负责释放 | 同一块数据上同时有几份 |
| :--- | :--- | :--- | :--- | :--- |
| 所有者（`String`） | ✓ | ✓ | ✓ | 一个 |
| 只读引用（`&String`） | ✓ | ❌ | ❌ | 多个 |
| 可变引用（`&mut String`） | ✓ | ✓ | ❌ | 一个，期间别的引用都不在 |

三行排下来是一座权限阶梯：`T` 拿全部三权——读、写、释放；`&mut T` 拿两权——读、写，不负责释放，代价是排他；`&T` 只拿一权——读，换来的是共享。

「一个」有两种含义。所有者的一个：一个值只有一个所有者。可变引用的一个更严：它活着的期间，这块数据上不能再有任何引用，只读的也不行。

想造出可变引用，变量声明时要写 `mut`：`let mut s`。`mut` 的完整账目第二篇再算，这一课记住一件事：想取 `&mut`，先声明 `mut`。

## 三个类型

回看那张表的行名：`String`、`&String`、`&mut String`——三个不同的类型。

`&` 和 `&mut` 出现在类型的位置：参数写 `&Vec<i32>`；`let r = &s;` 之后，`r` 的类型是 `&String`，在栈上占一个机器字。`&String` 不是 `String` 加了一个标记：大小不同，一个机器字对三个；身份不同，一个负责释放，一个只读。`&String` 和 `&mut String` 也不是同一个类型加标记：一个能改，一个不能。

`&` 加在一个类型前面，得到的是另一个类型。这件事的分量，第二篇讲类型系统时展开；这里先把事实摆下：类型里的 `&`，造的是类型。

<Aside type="tip" title="如果你来自 C++">
C++ 的引用是变量的别名，用起来像原变量本身。Rust 的 `&` 造出的是一个独立的值：独立的类型，独立的大小；取地址写 `&s`，读指向的内容写 `*`。两者都不负责释放，差别在下一课——Rust 编译器检查引用指向的数据是否还在。
</Aside>

<Aside type="tip" title="如果你来自 Java 或 Python">
这些语言里「用」和「拥有」不区分：对象在堆上，引用就是共享的入口，释放交给 GC。这一课拆开的两件事，在那些语言里是同一件事。
</Aside>

## 成了什么，缺了什么

到这里：无 GC、无手写 `free`，释放时刻唯一确定；函数能用数据而不夺走所有权；多个读者共享，一个写者独占。

但定义的第一条——「指向的数据必须仍然有效」——目前还只是愿望，模型里没有任何规则保证它。所有者先离开作用域，堆被释放，引用还握在手里：会发生什么？
