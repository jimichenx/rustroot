## 我们要解决的问题

找一组整数里最大的，找一组小数里最大的，找一组字符里最大的。三个函数的函数体一模一样，只有类型不同。

能不能只写一份？只写一份，运行时要不要为此付出代价？

## 类型也是参数

你已经见过这种写法：`Vec<T>`、`Option<T>`、`Result<T, E>`。尖括号里的 `T` 是类型参数（Type Parameter），用的时候换成具体类型。写在类型上、也可以写在函数上的类型参数，叫泛型（Generics）。

`fn largest<T>(items: &[T]) -> T`：一份源代码，`T` 可以是任何类型。源代码只写一份没有问题。问题在编译出来的机器码。

## 第一版：只编译一份机器码

Java 的泛型就是这样：`List<Integer>` 和 `List<String>` 在运行时是同一份代码。能做到，是因为 Java 里每个对象都在堆上，`T` 在机器码里永远是一个引用，一个机器字。

我们的语言不是这样。`u8` 是 1 个字节，`i32` 是 4 个，`String` 是 24 个，都可以直接放在栈上。`largest` 的函数体里有一句 `let mut max = items[0]`：要在栈帧里给 `max` 留多大的位置？遍历 `items` 时，下一个元素离当前元素多远？一份机器码回答不了，因为答案随 `T` 变。

1.2 和 5.1 都撞过同一堵墙：栈帧里每个位置的大小，编译期就要定下。

## 第二版：全部放上堆

那就学 Java，把每个值都放到堆上，`T` 在机器码里统一成一个地址。一份机器码又行了。

代价是第一篇省下来的那些：每个整数都要一次堆分配，每次读都要隔着一个地址，每块堆都要有人释放。为了少写几个函数，让所有值都付这笔账，不划算。

## 第三版：每个类型一份

编译期已经知道每一次调用用的是什么类型。那就为每个用到的具体类型，各生成一份机器码，在每一份里把 `T` 换成那个类型。这叫单态化（Monomorphization）。

<Code code={oneCopyPerType} lang="rust" />

`size_of_one` 的函数体只有一行，三次调用打印 1、4、24。每一份生成的代码都知道自己的 `T` 是什么，栈上该留多大，编译期就定了。

单态化之后，调用哪个方法、比较用哪条指令，也都在编译期定下，运行时不查任何东西。上一课说「`a.area()` 调用哪一个，编译期就定了」，就是这样做到的。

## 函数体能对 `T` 做什么

一份源代码对应好几份机器码。编译器什么时候检查函数体？

**每生成一份，检查一份。** C++ 的模板这样做。函数体里用了 `>`，传进来的类型不支持 `>`，错误出现在生成那一份的时候，报在函数体深处。作者改了函数体，某个调用方的代码突然编译不过，调用方看不出为什么。

**按签名检查一次。** 签名写明 `T` 能做什么，函数体只能用这些；调用方只能传满足这些的类型。这就是上一课说的：签名是契约。

`T: PartialOrd + Copy` 用上一课的 Trait 约束说清两件事：`T` 能比较大小，`T` 能复制。有了这两条，函数体能编译，调用方也只能传满足这两条的类型。

## 零成本的两层意思

单态化常被叫作零成本抽象（Zero-cost Abstraction）。这句话有两层。

**不用就不付。** 没被调用过的泛型函数，生成的程序里没有它的代码。

**用了，通常接近手写。** 每一份生成的代码，都和你为那个类型手写的差不多，编译器还能进一步内联、优化。代价挪到了别处：用到的类型越多，生成的代码越多，程序体积和编译时间都会上去。这一层是通常能达到的效率，不是没有代价。

## 泛型参数那里没有桥

5.3 说，方法调用点有一座桥：编译器替你补引用、做转换。到了泛型参数那里：

<Code code={noBridge} lang="rust" />

`Summary` 只为 `String` 实现。`r` 是 `&String`，`r.summary()` 能调用：方法解析沿着桥，从 `&String` 找到了 `String` 的实现。

取消注释 `show(r)`，报 `error[E0277]`：`&String` 没有实现 `Summary`。

`show<T: Summary>` 的 `T` 是由你传进去的东西定的。你传的是 `&String`，`T` 就是 `&String`。编译器若在这里替你解引用，`T` 该是 `String` 还是 `&String`？单态化要为一个确定的类型生成代码，它不猜。你给什么，`T` 就是什么，然后查它有没有实现 `Summary`。

改法有两种：签名里把引用写出来，`show_ref<T: Summary>(x: &T)`，这时 `T` 是 `String`；或者把拥有的值交进去，`show(s)`。

<Aside type="note" title="补充基础">
  参数写成 `&impl Summary`，和写成 `<T: Summary>(x: &T)` 是同一件事的两种写法。上一课用的是前一种。
</Aside>

## 顿悟时刻

值的大小各不相同，一份机器码服务不了所有类型；都放上堆又要付第一篇省下的账。所以编译器为每个用到的类型各生成一份：单态化。

函数体按签名里的约束检查一次，不按将来传进来的类型猜。泛型参数按你给的类型精确匹配，没有方法调用点的那座桥。
