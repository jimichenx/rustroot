## 静态的答案已经写完

先看一段最朴素的连续数据：五个 `i32`。Rust 的数组把它写成 `[i32; 5]`——类型里写明了「五个」，五个格子紧挨着躺在栈上。

2.1 练的辨认在这里用得上：`let b = a` 是复制还是移动，判定标准是 1.3 立下的那条线——复制出去的字节里，是否包含一块需要承担释放责任的堆内存。`[i32; 5]` 的 20 个字节全在栈上，没有堆，没有释放责任。赋值是整段抄过去，两个名字都有效：复制（Copy）。

同样五个整数，换成 `Vec<i32>`：数据在堆上，栈上的名字握着三个机器字——地址、长度、容量。赋值抄的是这三个字，释放责任跟着走，原来的名字失效：移动（Move）。

同一组数据，切割线的两侧。差别只有一个：`[i32; 5]` 的长度编译期就知道，`Vec<i32>` 的长度要到运行时才定下来。

## 改一个条件：长度运行时才知道

现在把条件改一个字：长度要到运行时才知道。用户的输入、文件的内容、网络包——现实数据大多这样。静态答案作废，三个问题重新回答。

数据放哪。栈上的值要在栈帧里占位置，位置多大，编译期就得定下来；长度运行时才知道的值，栈上放不下，只能去堆。

长度放哪。类型里写不进一个运行时的数字。堆也帮不上忙：1.2 里堆是向操作系统借来的资源，借到手的是一块地址，块上不带任何元数据。长度只能跟着指向它的句柄走。

账怎么走。堆上的数据要有唯一的所有者负责释放（1.3）。这个所有者你已经认识：`Vec<T>`——地址、长度、容量，三个机器字的拥有型句柄，长度就装在句柄里。2.1 里它走 Move，账就是从这三笔来的。

到这里，动态长度数据的拥有形态齐了。但第一章的分工是两条：拥有者负责释放，借用者只是看（1.4）。想看数据中间的一段，借用的形态长什么样？

## 中间一段，只能借

「其中一段」有个绕不开的物理障碍：堆内存按块分配、按块归还，所有权的责任挂在整块上（1.3 的「一块堆」）。你可以拥有一个 `Vec` 的全部，没法只拥有它堆块里的第 3 到第 8 个元素——除非复制一块新的出来，付 2.1 的账单。

所以指向中间的句柄，身份只能是借用：不拥有、不复制、登记在账本上。这个句柄要能用，得回答两个问题——从哪里开始，到哪里为止。一个起点地址，一个长度。

长度哪里查？哪里都查不到。1.3 对照过 Java 的立场：对象全在堆上，栈上的名字放引用，GC 兜底。那个立场给了每个堆对象一个头，长度就存在头里，引用保持一个字。Rust 的堆没有扫描器伺候，块上无头——长度只能句柄自己带。

先看前半段的赋值：`a` 给了 `b` 之后两个名字都能用——视图是 `Copy` 的，抄的是起点和长度这两个字，数据一个字节没动。2.1 的切割线再次落下：复制出去的字节里没有堆责任。

后半段的 `size_of` 是标准库里问「这个类型占几个字节」的函数，三个数字各对一件事：`&[i32; 5]` 是 8——长度在类型里，引用保持一个字；`&[i32]` 是 16——类型里没有长度，起点和长度都装在值里；`Vec<i32>` 的 24 是拥有侧的同类——地址、长度、容量，外加释放责任。

这个自带长度的借用类型，就是本课的主角。**切片（Slice）**：不拥有数据、指向所有者数据里一段的借用。表示比普通引用多一个长度，胖指针（Fat Pointer）这个名字来自这里；因为它只看不改，也说它是这段数据的**视图（View）**。

`&s[0..5]` 的类型是 `&str`，不是 `&String`。范围正好对应视图的表示：从字节 0 开始，长度是 5。省略起点写成 `&s[..5]`，省略终点写成 `&s[6..]`，两端都省略，`&s[..]` 是整个字符串的视图。

字面量 `"hello world"` 的类型本来就是 `&str`。它指向编译进程序的一段字符，不在栈上，也不在堆上；没有 `String` 拥有它，没有堆要释放，它和整个程序活得一样久。

<Aside type="note" title="按字节，不按字符">
范围里的数字是字节。本课的例子全是 ASCII，一个字符正好占一个字节。范围切在多字节字符的中间——比如一个汉字——程序在运行时 panic；拦下它的是运行时的边界检查，不是编译期的借用检查。按字符处理字符串用 `chars`，见官方 Book 第 8 章。
</Aside>

<Aside type="tip" title="如果你来自 C++">
`std::string_view` 和 `std::span` 是同类视图：一个地址加一个长度，不拥有数据。C++ 编译器不核对视图和数据谁先失效；Rust 把视图记成借用，数据被修改或提前释放时，编译期就报 `error[E0502]`、`error[E0597]`。
</Aside>

参数写成 `&String` 会怎样？函数照样能写、能编译，只是字面量被关在门外：`"hello"` 指向静态区的字符，没有 `String` 结构可指，类型对不上，`error[E0308]`。要让它编译，调用方得先 `String::from` 分配一次——函数只想读 3 个字节，调用方却要先当上拥有者。

参数类型是向调用方开出的条件。`&String` 开的条件是「你必须是个 `String`」，`&str` 开的条件是「给我一段字符」。函数要什么，就让参数收什么。

## 返回值：函数交回一段

函数要把数据里的一段交回给调用方，交什么？三个答案挨个看。

## 同一个视图，两对类型

序列是同一个推导再走一遍。`Vec<T>` 拥有一段元素，`&[T]` 是其中一段的视图：

<Code code={vecSlice} lang="rust" />

`sum` 只认 `&[i32]`：对数组取 `&a[..]`，是整个序列的视图；对 `Vec` 取 `&v[1..]`，是从第 1 个元素到结尾的视图。同一个函数服务两种所有者，没有复制，也没有脱离账本的数字。

| 拥有数据的类型 | 借用其中一段的类型 |
| --- | --- |
| `String` | `&str` |
| `Vec<T>` | `&[T]` |
| `[T; N]` | `&[T]` |

前两行的左列持有堆上的释放责任，右列只有两个机器字；`[T; N]` 的数据在栈上，没有这份责任。写函数参数用右列，`String`、`Vec`、字面量就都进得来——本课的 `contains`、`first_word` 和 `sum` 都是这么写的。

本课的切片都带着 `&`。裸的 `str` 和 `[T]` 表示长度不定的数据，不能直接绑定到变量上；为什么，附录里讲数组、切片与 `Vec<T>` 内存布局的文章再拆。

## 这次复现留下什么

读一个连续数据的类型，先问一个问题：长度在哪？

- 在类型里——`[T; N]`，静态答案，值本身躺在栈上，Copy；
- 在拥有句柄里——`String`、`Vec<T>`，堆上一块，释放责任跟着句柄走；
- 在借用句柄里——`&str`、`&[T]`，两个机器字，指向所有者的数据，可以指到中间。

第三个位置就是切片。看到 `&s[..5]`，读成一次借用的发生：1.5 管它活多久，1.6 管它和 `&mut` 的冲突。索引没有这层身份，它只是一段不在账本里的数字，出错要到运行时才现形。

写函数参数时，用视图类型把条件收窄到「给我一段数据」；返回数据的一段时，先问要快照还是要视图——要快照，`clone` 的账单记在明处；要视图，交还的是两个机器字的借用。
