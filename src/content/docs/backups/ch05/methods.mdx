## 我们要解决的问题

一个计数器要有几个操作：读出当前的数，加一，最后把总数交出去。每个操作都是一个作用在计数器上的函数。

计数器怎么交给这些函数？调用的时候，又要写多少东西？

## 交法只有三种

第一篇已经把「把值交给函数」这件事想完了，一共三种交法：

- **移交**：值交给函数，以后由函数负责，调用方的名字失效。1.3 的移动。
- **只读借**：函数看一眼，值还是调用方的。1.4 的 `&`。
- **可变借**：函数改一下，值还是调用方的，改的期间别人不能碰。1.4 的 `&mut`。

作用在计数器上的函数，第一个参数就是计数器本身，它也只能是这三种之一。Rust 把这个参数叫 `self`，写在 `impl` 块里，这种函数叫方法（Method），第一个参数叫接收者（Receiver）：

<Code code={receivers} lang="rust" />

| 接收者 | 交法 | 对回 | 调用之后 |
| :--- | :--- | :--- | :--- |
| `&self` | 只读借 | 1.4 | 计数器照常能用 |
| `&mut self` | 可变借 | 1.4 | 计数器照常能用 |
| `self` | 移交 | 1.3 | 计数器失效 |

`get` 只读，写 `&self`。`bump` 要改，写 `&mut self`。`finish` 把总数交出去，之后这个计数器没有用了，写 `self`。调用 `c.finish()` 之后 `c` 失效，取消最后一行的注释，报 `error[E0382]`。

写方法时先问：这个方法要对值做什么？只看，要改，还是用完交出去。签名跟着答案定。

交法不只是三种做法，是三个类型：`self` 的类型是 `Counter`，`&self` 是 `&Counter`，`&mut self` 是 `&mut Counter`。4.2 结尾那组人——`T`、`&T`、`&mut T`——从这里走进签名；调用方和编译器核对的，是写在签名上的那个类型。

## 没有接收者的：构造函数

`Counter::new` 没有接收者。它不作用在已有的计数器上，而是造一个新的。这种函数叫关联函数（Associated Function），用 `类型::函数` 调用。

## 调用时要写多少

`push` 的接收者是 `&mut self`。按签名，调用时要把 `&mut v` 交进去：

<Code code={autoRef} lang="rust" />

第一行把函数写全：`Vec::push(&mut v, 4)`。第二行 `(&mut v).push(5)`，引用手写。每次调用都这样写，代码里到处是 `&` 和 `&mut`。

**让编译器在调用点补上。** 第三行 `v.push(6)` 什么都没写。编译器看 `push` 要的是 `&mut Vec<i32>`，替你取了 `&mut v`。

补法叫方法解析：先在接收者的类型上找这个方法；找不到，试它的 `&T` 和 `&mut T`；还找不到，沿着类型之间的转换往下找，取第一个匹配的。`s.contains("wor")` 的 `contains` 定义在 `str` 上，不在 `String` 上，编译器从 `String` 转到 `str` 才找到它。5.1 里 `&s` 能传给 `&str` 参数，也是这次转换。它靠 `Deref`，8.1 讲怎么实现。

可以把这层补全看成编译器在调用点修的一座桥。桥修好之后，`v.push(6)` 看起来像是「通过 `v` 直接调用里面的函数」。熟悉 Java 的你会把它读成：引用和对象是一回事，拿着引用就能调用对象的一切方法。在撞墙之前，这个读法一直是对的。

## 桥会不会越权

编译器替你补的东西，会不会让你做到自己写不出来的事？

它不能。桥上的每一步，都必须是你自己手写得出来、并且能通过检查的那一步。拿三个例子核对。

**补 `&mut v`，要 `v` 是 `mut` 绑定。**

**补 `&mut v`，要此刻没有别的借用活着。**

取消注释，报 `error[E0502]`：`first` 这份只读借用还活着。这是 1.4 的读写排他。

**补不出所有权。**

<Code code={consumeThroughRef} lang="rust" />

`r` 是 `&String`。`r.len()` 要 `&self`，可以。`r.into_bytes()` 要 `self`，要把 `String` 本身交出去。取消注释，报 `error[E0507]`：不能从共享引用后面把值搬出来。`r` 只是借着，没有所有权可以交。所有者 `s` 自己调用就可以。

三堵墙说的是同一件事：权限只降不升。`&mut` 可以当 `&` 用，`&` 升不回 `&mut`，引用也变不成所有者。路径上任何一环是共享引用，从那里往后只能读。

所以「引用和对象是一回事」这个读法，撞到这里就不成立了。`&String` 和 `String` 是两个类型，规矩不同。桥让你少写字，规矩一条没少。

## 凑齐四块

回头看 `v.push(4)` 能编译，要同时有四件事：

1. `push` 的签名要 `&mut self`；
2. `v` 是 `mut` 绑定，能借出 `&mut`，这是 4.2 的绑定上的 `mut`；
3. 编译器在调用点把 `v` 取成 `&mut v`；
4. 此刻没有别的借用活着。

「变量是 `mut` 的，所以能调用会修改它的方法」，这句话里压着这四块。缺第二块是 `error[E0596]`，缺第四块是 `error[E0502]`。

桥只修在方法调用点。换一个地方，比如把 `&String` 交给一个要求某种类型的泛型参数，编译器就不补了。那堵墙在 7.2。

## 顿悟时刻

方法的接收者只有三种，因为把值交给函数只有三种交法：`&self` 只看，`&mut self` 要改，`self` 用完交出去。

调用时编译器替你补引用，但补的每一步都要过检查。它补不出你没有的权限：少了 `mut` 绑定、借用重叠、要从共享引用里拿走值，都会被拒绝。
