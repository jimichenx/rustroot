## 我们要解决的问题

上一课末尾说：数据的大小和寿命全在编译期定死，作用域就够了，不需要所有权。

五个整数就是这样。长度编译期知道，写进类型：`[i32; 5]`。20 个字节紧挨着放在栈上，没有堆，赋值整段抄过去，两个名字都能用。

现在改一个条件：长度要到运行时才知道。用户的输入、文件的内容、网络包，现实里的数据多半这样。三个问题要重新回答：数据放哪？长度放哪？谁负责释放？

## 数据放哪

1.2 说过，栈帧里每个名字占多大，编译期就要定下，函数一进来就按这个大小划出栈帧。长度运行时才知道的数据，栈帧里留不出位置。

数据只能去堆。

## 长度放哪：三个候选

去了堆，还要有地方记着它有多长。候选有三个。

**候选一：写进类型。** `[i32; 5]` 就是这样做的。可运行时才知道的数字写不进类型：编译完了，类型就定了，程序运行时读到的「37 个」进不去。

**候选二：写在堆块的头上。** 在数据前面多放一个格子记长度，名字只抄一个地址。Java 的数组就是这样：`int[]` 的长度在对象头里，引用只有一个机器字。

**候选三：写在句柄里。** 名字除了地址，自己再带一个长度。

候选一出局。候选二和候选三，对「拥有一整块」来说都说得过去。先不急着选，下面「借一段」会替我们选。

## 谁负责释放

堆上的数据要有唯一的所有者，这是 1.3。所有者是栈上的那个句柄：它记着地址，离开作用域时把堆还回去。

Rust 的这个所有者叫 `Vec<T>`。它在栈上是三个机器字：地址、长度、容量。容量是堆块实际留出的空间，比长度多出来的部分用来增长。

<Code code={arrayVec} lang="rust" />

`[i32; 5]` 的赋值是复制。`Vec<i32>` 的赋值抄走栈上三格，释放责任跟着走，原来的名字失效：移动。同样五个整数，只差长度何时知道这一个条件，落在了切割线的两侧。

## 借一段

新的需求：一个函数只想读 `Vec` 中间的一段，比如第 1 到第 3 个元素。

先问能不能拥有这一段。堆按块分配、按块释放，所有权挂在整块上，1.3 的「一块堆，一个所有者」。你能拥有一个 `Vec` 的全部，没法只拥有它堆块里的第 1 到第 3 个。要拥有，只能另分配一块、复制过去，付一次 4.1 的克隆。

不复制，指向中间一段的东西就只能是借用：不拥有，不负责释放。

借出去的东西要说清两件事：从哪开始，有多长。起点是一个地址。长度放哪？三个候选再过一遍，这次加一个检验：从同一块数据里，同时借出整段、第 1 到第 3 个、第 2 个往后。

**候选一：写进类型。** 切出来的长度是运行时算出来的，写不进类型。出局。

**候选二：写在堆头上。** 数据只有一个头，头里只有一个长度。三段借用长度各不相同，头里记谁的？只能每借一段，就在堆上另造一个头记它的长度。每切一次分配一次堆，而且这个新头要有人释放。借用不负责释放，于是又要一个新的所有者，或者请回 GC。1.3 被连根拔起。出局。

**候选三：写在句柄里。** 句柄是借用自己的，每段借用各带各的长度，互不干扰。

候选三还有两种做法。一种是把长度放在另一个名字里，和地址分开：C 的函数常写成 `f(int *p, size_t len)`。可这两个名字是一对，编译器不知道；传参时漏了一个、传错了长度，没人检查。另一种是把地址和长度绑成一个值：复制它就是复制两个字，再切一段就是算两个数，都不碰堆。

只有最后这种过得了关。

## 长度属于视图

检验里还藏着一个事实：同一块数据可以同时有好几段借用，每段长度不同，数据只有一份。长度不是数据的属性，是每一段借用自己的属性。它就该待在借用自己身上。

回头看拥有的一侧，候选二也没有理由留下：借用已经自带长度，所有者 `Vec` 也把长度放在自己的句柄里。Rust 不在堆块上记长度。

地址加长度绑成的这个借用，叫**切片（Slice）**：不拥有数据、指向所有者数据中一段的借用。它比普通引用多一个长度，所以也叫胖指针（Fat Pointer）。借出一段数据给别人看，也说它是这段数据的视图。

<Code code={fatPointer} lang="rust" />

`a` 赋给 `b` 之后两个都能用：抄走的是起点和长度，没有释放责任，是复制。`size_of` 查一个类型占几个字节。在 64 位机器上：

- `&[i32; 5]` 是 8。长度写在类型里，指针不用带。
- `&[i32]` 是 16。类型里没有长度，指针带着地址和长度。
- `Vec<i32>` 是 24。拥有一侧的同类：地址、长度、容量，再加上释放责任。

<Aside type="tip" title="如果你来自 Java">
  Java 的数组引用只有一个字，因为长度在堆上的对象头里。要借数组中的一段，Java 的 `ByteBuffer` 用 position 和 limit 另造一个堆对象，旧版 `String` 的 `substring` 用 offset 和 count。它们都是在堆上重新造了一个胖指针，也都要 GC 来回收这个新对象。
</Aside>

## 指针的胖瘦由指向的东西决定

`&[i32; 5]` 和 `&[i32]` 都是指向五个整数的引用，一个 8 字节，一个 16 字节。差别不在 `&` 上，在它指向的类型上。

`[i32; 5]` 的大小写在类型里，是 20 字节。`[i32]` 只说「一串 `i32`」，没说几个，大小不定。大小不定的类型不能直接当一个名字的类型，因为栈帧里给它留不出位置。它只能待在指针后面，指向它的指针自动带上长度。

这条规则不只管 `&`。凡是指向 `[T]` 的指针都带着长度：拥有它的指针也一样，是两个机器字。`str` 是同一回事，它是一串 UTF-8 字节，大小不定，`&str` 也是两个字。

`&s[0..5]` 的类型是 `&str`，不是 `&String`。范围正好对上切片的两个字：从字节 0 开始，长度 5。省略起点写 `&s[..5]`，省略终点写 `&s[6..]`，两端都省略，`&s[..]` 是整段。

字面量 `"hello world"` 的类型本来就是 `&str`。它指向编译进程序的一段字符，不在栈上，也不在堆上，没有 `String` 拥有它，它和程序活得一样久。

<Aside type="note" title="按字节，不按字符">
  范围里的数字是字节。本课的例子都是 ASCII，一个字符一个字节。范围若切在多字节字符的中间，比如一个汉字的中间，程序在运行时 panic。拦下它的是运行时的边界检查，不是借用检查。按字符处理字符串用 `chars`，见官方 Book 第 8 章。
</Aside>

参数写 `&str`，三种调用方都进得来：`String` 的引用 `&s`、字面量、别处借出的一段 `&s[6..]`。`&s` 从 `&String` 变成 `&str`，是调用点上的一次自动转换，5.3 拆开。

参数写成 `&String` 会怎样？字面量进不来：`"hello"` 没有一个 `String` 可以指，报 `error[E0308]`。调用方得先分配一个 `String`，才能把 5 个字节交给一个只读的函数。

参数类型是向调用方开出的条件。`&String` 要求「你得是一个 `String`」，`&str` 只要求「给我一段字符」。

序列走的是同一条推导：

`sum` 只收 `&[i32]`：对 `Vec` 取 `&v[1..]`，对数组取 `&a[..]`，一个函数服务两种所有者。

把这一课的类型按两个问题排开，长度何时知道、拥有还是借用：

| | 长度编译期知道 | 长度运行时才知道 |
| :--- | :--- | :--- |
| 借用 | `&[T; N]` | `&[T]`、`&str` |
| 拥有 | `[T; N]` | `Vec<T>`、`String` |

`Vec<T>` 能增长，容量就是为增长留的。拥有、长度运行时才定、之后不再增长，这一格也有，叫 `Box<[T]>`，句柄是两个机器字，对应 Java 的 `new int[n]`。它要等 8.1 讲 `Box` 时才补上。

## 顿悟时刻

长度要到运行时才知道，数据去堆，长度跟着句柄走。拥有的句柄是 `Vec<T>` 和 `String`，借一段的句柄是 `&[T]` 和 `&str`。

长度属于借出去的那一段，所以切片把地址和长度绑成一个值，两个机器字。指针的胖瘦由它指向的东西决定：指向大小不定的 `[T]`，就带上长度。

读一段连续数据的类型，先问：长度在哪？
