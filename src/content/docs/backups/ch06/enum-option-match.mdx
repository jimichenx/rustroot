## 我们要解决的问题

一个函数按名字查年龄，可能查不到。它的返回值要能表示「没有」。

4.1 定下，一个绑定要么有值，要么编译器知道它没有；这说的是编译期。现在「有没有」要到运行时才知道，得写进值里。这门语言怎么表示「没有」？

## 第一版：空地址

Java 和 C 的做法：引用可以是 `null`，一个不指向任何东西的地址。查不到，就返回 `null`。

1.4 设计引用时，给它定的第一条限制是：它指向仍然有效的数据，通过它可以读到内容。`null` 不指向任何数据。允许引用是 `null`，这条限制就没了：每一个引用在用之前，都可能是空的。

要么每次使用都在运行时检查一遍，要么在运行时出事。Java 的 `NullPointerException` 就是后一种。我们的语言里，引用不能是空的。

## 第二版：留一个特殊值

年龄是整数，不是引用。拿一个不可能的值表示没有，比如 `0`。

可 `0` 岁是合法的年龄。换成 `u32::MAX`，是另一个约定：写在注释里，调用方记得就检查，忘了就把它当成一个年龄加一。5.2 里「请只放偶数」守不住，这里一样。

## 第三版：标志加字段

用 5.2 的结构体，一个字段说有没有，一个字段放年龄：

`present` 是 `false`，`age` 却是 30。这个值到底有没有年龄？编译器接受了它。最后一行不看标志就读 `age`，编译器也接受了。

问题出在结构体的含义上：字段同时存在。「没有年龄」的时候，`age` 字段照样在，照样能读。标志和字段各写各的，哪些组合合法，只在写代码的人脑子里。

## 第四版：一次只有一种情况

要的不是「这个且那个」，而是「这个或那个，一次只有一种」。每种情况带着它自己的数据，没有的情况就没有那份数据。

这是一种新的类型，叫枚举（Enum）：

<Code code={variantData} lang="rust" />

`Payment` 要么是 `Cash`，要么是 `Card`，每一种情况叫一个变体（Variant）。`Card` 带一个卡号，`Cash` 什么都不带。一个 `Payment` 值同一时刻只是其中一个变体，不会出现「付现金，却有卡号」。

可能的取值数，是各变体可能的取值数相加，所以枚举也叫和类型（Sum Type）。结构体说「这个且那个」，枚举说「这个或那个」。

## `Option<T>`

「可能没有」是枚举的一个实例，标准库写好了：

```rust
enum Option<T> {
    None,
    Some(T),
}
```

这段是标准库定义的简化写法，不是实验源码。`Option<u32>` 读作「一个 `u32`，或者没有」。尖括号里的 `T` 是类型参数，7.2 讲，现在把 `Option<u32>` 当成一个整体的类型名。

<Code code={option} lang="rust" />

`find_age` 找到了返回 `Some(7)`，找不到返回 `None`。拿到的 `age` 是 `Option<u32>`，不是 `u32`。取消注释那一行，报 `error[E0369]`：`Option<u32>` 不能加一个整数。年龄装在 `Some` 里面，不先看是哪个变体，就拿不到它。

## 必须每种都看

看是哪个变体，用 `match`：每个变体写一条分支，叫一条臂（arm）。`Some(a)` 这条臂把年龄取出来绑到 `a` 上，`None` 这条臂处理没有的情况。

如果允许只写 `Some` 那条臂，漏掉 `None`，会怎样？查不到的时候，程序走进一条没人写的路。这就是第一版空地址的事故，换了个样子回来。

所以 `match` 必须把每个变体都写到：

<Code code={exhaustive} lang="rust" />

把 `Light::Green` 那条臂注释掉，报 `error[E0004]`：模式不完整，`Light::Green` 没有被覆盖。这叫穷尽检查。以后给 `Light` 加一个变体，每个没写到它的 `match` 都会编译失败，编译器替你找出所有要改的地方。

`Option` 比空地址多出来的，就是这一条：「没有」成了一个变体，而每个变体都必须有人接。

## 编译器证明了什么

穷尽检查证明的是结构：每一种情况都有一条臂接着。它不证明臂里写得对。红灯写成 30 秒还是 3 秒，编译器不管；付款的金额算没算对，也不管。这些要靠测试和对业务的理解。

<Aside type="tip" title="如果你来自 Java">
  Java 的任何引用类型都可能是 `null`，类型不告诉你。Rust 的 `String` 一定有值；可能没有，类型写成 `Option<String>`，不先 `match` 就拿不到里面的 `String`。空值从运行时的 `NullPointerException`，变成了编译期必须处理的一个变体。
</Aside>

## 顿悟时刻

「没有」不能是一个空地址，那会打破引用的定义；也不能是约定，约定守不住。它是一种情况，和「有」并列。几种情况一次只有一种，用枚举。

`Option<T>` 把缺失写进类型，`match` 必须穷尽。穷尽检查证明结构没有遗漏，业务对不对另由测试回答。

这一课 `match` 的对象都是拥有的值，臂里取出的数据直接归了新名字。隔着一个引用去 `match`，取出来的归谁？下一课。
